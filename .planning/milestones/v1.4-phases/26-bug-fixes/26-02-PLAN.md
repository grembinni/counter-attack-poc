<objective>
Fix two server-side rule-validation defects in `gameEngine.ts`:

- BUG-28: when the attacker wins a header duel, the target-hex must be validated against
  the winning contestant's actual position so a valid goal-side hex is always accepted and
  no invalid/unreachable hex is used.
- BUG-29: standard shot range validation must use the correct (cube-consistent) distance
  calculation so shots are accepted/rejected at the right range.

Both are investigation-first fixes: confirm the root cause against the current code, apply
the minimal correction, and lock the behaviour with a regression suite.

Purpose: Header targeting and shot range must be rule-correct and consistent between the
winning-contestant position and the client's range preview (BUG-28, BUG-29).
Output: Corrected `applyResolveHeaderTarget` reference position + verified `applyDeclareShot`
range gate, both covered by a new regression suite.
</objective>
