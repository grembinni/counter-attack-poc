<objective>
Build the pack-generation half of the draft engine (DRAFT-05): extend `draftEngine.ts` with a batch generator that produces the full set of `PACKS_PER_MATCH` packs a match needs from the selected pool(s), each composed per `PACK_COMPOSITION`, with pool-shortage backfill (D-12) and no cross-pack duplication (D-09). Randomness is fully injected — the shared engine never calls `crypto` or `Math.random` (28-04 supplies the server-side `crypto.randomInt`).

Purpose: This is the authoritative pack set Phase 29's draft UI/session will consume. It must be deterministic given an RNG (so tests are reproducible and the server can be audited) and must guarantee correct per-tier composition even when a small pool (e.g. original-only) cannot fill 8 packs on its own.
Output: `generateDraftPacks`, the `DraftPack` and `RandomIntFn` types, and an internal Fisher-Yates `shuffle`, all added to `draftEngine.ts`; plus pack/backfill/determinism tests in `draftEngine.test.ts`.
</objective>

    Add `export type RandomIntFn = (minInclusive: number, maxExclusive: number) => number;` with JSDoc noting it mirrors Node `crypto.randomInt(min, max)` and that the server injects the crypto-backed implementation (28-04); the engine itself never sources randomness (mirrors `scoreUtils.ts` "dice values passed in — no RNG here").

    Add `export interface DraftPack { packNumber: number; cards: TieredPoolPlayer[]; }` (packNumber is 1-based). JSDoc cites DRAFT-05, D-09.

    Add an internal (non-exported) `function shuffle<T>(items: readonly T[], rng: RandomIntFn): T[]`: copy the input, run Fisher-Yates from the end using `rng(0, i + 1)` as the swap index, return the new array. Never mutate the input.

    Add `export function generateDraftPacks(selectedPools: DraftPoolId[], rng: RandomIntFn): { pool: TieredPoolPlayer[]; packs: DraftPack[] }` (D-09..D-12). Implement in these stages:

    (1) SELECTED SET: `selected = resolvePoolPlayers(selectedPools)`.

    (2) FALLBACK ORDER: define the constant backfill order `['original', 'mls', 'international']` (Original → MLS → International per D-12); the active fallback list is that order minus any pool already in `selectedPools`.

    (3) NEED COUNTS: `keeperNeed = PACKS_PER_MATCH * PACK_COMPOSITION.keeper`; and for each outfield tier `t` in `['chase','rare','uncommon','common']`, `need[t] = PACKS_PER_MATCH * PACK_COMPOSITION[t]`.

    (4) BACKFILL (D-12 — uniform for keeper and outfield): maintain a working `union: PoolPlayer[]` seeded from `selected` and a `Set` of included ids. Loop: classify the current `union` via `assignTiers`; count keepers (tier `'keeper'`) and each outfield tier. If keeper count `< keeperNeed` OR any outfield-tier count `< need[t]`, draw ONE not-yet-included eligible player from the fallback pools and add it, then repeat. Draw rule: walk the fallback list in order; for the first fallback pool that still has un-included members of the needed KIND (a GK if only the keeper bucket is short, otherwise an outfield player — when both are short, prefer whichever the current fallback pool can supply, GK first), pick one at random using `shuffle(candidates, rng)[0]` (or `rng`-indexed selection) and add it. When a fallback pool is exhausted of the needed kind, move to the next fallback pool. Terminate when every need is met OR the fallback list is exhausted for the still-short kinds. Re-running `assignTiers` each iteration satisfies D-05 ("recompute percentiles on the union of selected pools PLUS backfill players"). NOTE for the executor: because the percentile bands (10/10/20/60) are narrower than the pack composition ratios, the true backfill target is per-tier (chase/rare are the binding tiers), so an original-only selection pulls MORE than the illustrative "48 outfield" figure in CONTEXT D-12 — this is correct and is what guarantees D-09's no-duplication property. Only if a needed kind cannot be filled from ANY pool does dealing fall back to reuse (stage 6).

    (5) FINAL CLASSIFY: `pool = assignTiers(union)` — the authoritative tiered pool returned to the caller.

    (6) DEAL: partition `pool` by tier into five arrays, and `shuffle` each with `rng`. For each pack index `0..PACKS_PER_MATCH-1`, take `PACK_COMPOSITION[tier]` cards from each tier's shuffled array by advancing a per-tier cursor (no reuse). If a tier's cursor would exceed its array length (only possible when backfill could not reach `need[t]` because all pools were exhausted), WRAP the cursor modulo the array length — this is the D-09 duplication exception, a dormant last resort that never triggers for the default constants with all three pools available (16 keepers ≥ 8; ≥130 outfield ≥ every tier need). Assemble each `DraftPack` with `packNumber = index + 1` and its 7 `cards`. Card order within a pack is Claude's discretion (e.g. chase, rare, uncommon, common×3, keeper) — keep it stable/deterministic.

    (7) RETURN `{ pool, packs }`.
