<objective>
Bind the shared draft engine to a cryptographically-secure randomness source on the server (the threat-model mitigation for pack fairness): a small `packages/server/src/draftPacks.ts` module that injects Node's `crypto.randomInt` into `generateDraftPacks` and exposes `generateMatchPacks(selectedPools)` as the single authoritative entry point Phase 29's `ROOM_SETTINGS_CONFIRM` handler will call. Includes an integration test proving the end-to-end pipeline (pool derivation → tier classification → backfill → composed packs) holds its structural invariants under real crypto RNG.

Purpose: The shared engine (28-02/28-03) is deliberately RNG-agnostic so it stays client-safe. Someone must supply the CSPRNG server-side; per the project convention (`diceUtils.ts`, `gameEngine.ts`) and the phase threat model, that source is `crypto.randomInt` — never `Math.random`, never client-supplied. This plan is where that binding and its end-to-end proof live.
Output: `generateMatchPacks` server module + `draftPacks.test.ts` integration invariants.
</objective>

| server pack generation → both clients | Fairness/authority boundary: packs decide draftable players, so generation must run only on the server with a source of randomness neither client can predict or influence. Clients receive the resulting packs (Phase 29); they never generate them. |

| Threat ID     | Category                           | Component                            | Disposition | Mitigation Plan                                                                                                                                                                                                                                                                                                         |

| T-28-04-FAIR  | Tampering / Information disclosure | generateMatchPacks randomness source | mitigate    | Injects `crypto.randomInt` (CSPRNG) — the shared engine is RNG-agnostic and `Math.random`-free, so no predictable/seedable RNG can reach pack generation; `grep` gate asserts zero `Math.random` in `draftPacks.ts`; generation is server-only, so a client cannot pre-compute or bias which players it will be offered |

| T-28-04-SC    | Tampering                          | package installs                     | accept      | No npm/pip/cargo packages installed (only existing `vitest`/`tsc` + Node built-in `crypto`); no supply-chain surface — no legitimacy checkpoint required                                                                                                                                                                |
