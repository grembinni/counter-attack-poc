<objective>
Fix the two server-side draft→game lifecycle bugs found in the 29-06 human verification, both isolated to `packages/server/src/roomHandlers.ts`:

1. **Post-draft rearrangement is dead** — the `DRAFT_REARRANGE` handler rejects every request once `room.draftSession.draftComplete` is true, so the player can never freely arrange lineup/bench after the draft ends and before Confirm (violates D-08/D-15 and blocks DRAFT-09/DRAFT-10).
2. **Drafted roster never reaches game start** — draft rooms seed `room.homeAssignment`/`room.awayAssignment` as `Array(11).fill(null)` and never update them; the drafted players live in `room.draftSession.homeLineupSlots`/`awayLineupSlots`. `LINEUP_CONFIRM` resolves the null assignment shell, so `buildInitialGameState` receives undefined players and on-pitch pieces have no stats/positions (the most severe gap, breaks the playable match).

Purpose: Restore the post-draft arrangement capability and make a completed draft produce a real, fully-statted 22-piece match — the whole point of the draft flow.
Output: Corrected `DRAFT_REARRANGE` guard and `LINEUP_CONFIRM` draft-mode roster resolution, plus server integration tests proving both truths.
</objective>
