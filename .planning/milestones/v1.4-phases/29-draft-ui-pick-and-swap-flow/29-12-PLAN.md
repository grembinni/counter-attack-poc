<objective>
Close the single remaining CRITICAL, in-scope gap on Phase 29 (29-VERIFICATION.md, verified 2026-07-21T23:10:00Z, status `gaps_found`): the bench carousel's horizontal scroll position snaps back to the leftmost card mid-drag, defeating the D-21 bench-carousel navigation this phase built (29-08).

Root cause (independently confirmed by the verifier via direct code read, not accepted on 29-REVIEW.md's word):

- `LineupAssignmentScreen.tsx` recomputes `benchCards` inline via `draftView.benchIds.map(resolveTieredCard).filter(...)` on every render (old lines 528-530), producing a fresh array reference every render regardless of whether the underlying bench data changed.
- `BenchCarousel.tsx`'s scroll-reset effect `useEffect(() => { el.scrollLeft = 0; updateScrollState(); }, [cards])` (lines 63-68) depends on that array's identity, so it fires on every unrelated parent re-render.
- `handleDraftSlotDragOver` (line 429-431) calls `setDraftDropTargetIndex(idx)` unconditionally on every native `dragover` tick (many times per second) while a user drags ANY card over ANY lineup slot. Each tick re-renders the parent → new `benchCards` reference → `BenchCarousel`'s effect re-runs → `scrollLeft = 0`. The rejection-message timeout (`setRejectionMessage(null)`, line 416) triggers the same reset.

Fix (belt-and-suspenders — both halves of the verification's suggested fix, because they address complementary layers):

- **Part A (source of the churn):** memoize `benchCards` in `LineupAssignmentScreen.tsx` on `[draftView?.benchIds, cardCache]` so its reference is stable unless the benched-id list or the tier-color cache legitimately changes.
- **Part B (intrinsic robustness of the child):** re-key `BenchCarousel`'s scroll-reset effect on a content-derived `benchKey` (joined card ids) instead of the `cards` array identity, so the carousel is resilient to reference churn from ANY future caller — and so the regression test can pin the contract at the component boundary.

Purpose: satisfy the derived truth behind DRAFT-09 / ROADMAP Phase 29 Success Criteria #4 — "overflow drafted players appear on a dynamically-sized bench carousel … and remain usable/stable while the user is interacting with the draft screen." Phase 29 is the last phase in the v1.4 roadmap.

Output: two minimal client-side edits (parent memoization + child effect re-key) plus a regression test that asserts the scroll-reset effect does NOT fire on an unrelated re-render but DOES fire on a genuine bench-content change.

**Why one plan, two tasks:** the two edits are one concern (bench carousel scroll stability) and compose into a single fix. Task 1 is the fix across both files (they are one atomic change — Part B is what makes Part A verifiable and vice versa). Task 2 is the regression test the verification report explicitly requires. Both share Wave 1; there are no other new gap plans to depend on.
