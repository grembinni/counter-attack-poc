## v1.1 Requirements — Final Status

### Visual Token Design

- [x] **VIS-01**: Home team tokens display a single vertical black stripe; away team tokens display two horizontal dark stripes — both teams are visually distinguishable on the pitch without requiring labels
  - **Outcome:** ✅ Validated — Phase 12 Plan 01 (PieceOverlay SVG stripe defs)
- [x] **VIS-02**: Token stripe design is consistent in all contexts: on-pitch overlays, player stats panel, and replay
  - **Outcome:** ✅ Validated — Phase 12 Plan 03 (MiniTokenBadge in PlayerStatsPanel)

### Hex Highlights & Indicators

- [x] **UX-05**: Piece selection state uses distinct outlines: selectable pieces show a bright blue outline; the currently active (selected) piece shows a green outline; pieces already activated this turn show an orange outline
  - **Outcome:** ✅ Validated — Phase 12 Plans 01/04 (SelectionState enum + HexGrid derivation)
- [x] **UX-06**: Game-state hex tints use a unified color system — risk hexes transparent orange; goal hexes transparent red; safe move hexes transparent yellow; kick off setup hexes transparent blue; shot-path hexes transparent white
  - **Outcome:** ✅ Validated — Phase 12 Plans 02/04 (HexHighlightType + priority ternary in HexGrid)

### Screen Layout

- [x] **LAYOUT-01**: A persistent scoreboard is displayed at the top of the screen in all game phases; it contains home team score, match time + half indicator + connection status, and away team score
  - **Outcome:** ✅ Validated — Phase 13 Plan 02 (80px CSS-Grid top band)
- [x] **LAYOUT-02**: An action/log panel is displayed at the top of the screen alongside or below the scoreboard; it contains available action buttons, current phase status text, and the recent event log; the hex grid occupies the main screen area beneath both top components; layout is responsive-aware
  - **Outcome:** ✅ Validated — Phase 13 Plan 02 (phase-aware action section + collapsible log)

### Match Clock

- [x] **CLOCK-01**: Match time displays in MM:SS format; first half runs from 0:00 forward; second half starts at 45:00 and runs forward through added time to full time
  - **Outcome:** ✅ Validated with override — Implemented as MM:00 (event-driven, not real-time); CLOCK-01 spec says MM:SS but CONTEXT.md D-08 overrides to MM:00. Accepted.
- [x] **CLOCK-02**: The clock is visible in all game phases including kick off setup, GK restart, GK diving, half time screen, full time screen, and post-game replay
  - **Outcome:** ✅ Validated — Phase 13 Plans 02/03 (D-11 unconditional render; D-12 HALF_TIME/FULL_TIME as overlays)

### Kick Off Rules

- [ ] **MATCH-06**: Default kick off setup places midfielders and backs within hex columns 6–20 (server-set default placement at match start and at half-time reset)
  - **Outcome:** ⚠️ Spec conflict — Implemented as symmetric mirror formation (Home DEF q=6, Away DEF q=30 which mirrors q=6 on 37-col board; Home MID q=10, Away MID q=26). Requirement text q∈[6,20] was written from Home perspective only. Design intent is correct; requirement text needs updating.
- [ ] **MATCH-07**: Only a Standard Pass can be played as the opening action from the kick off hex; any other action type attempted from the centre hex during kick off is rejected by the server
  - **Outcome:** ✅ Wired (admin gap — checkbox not ticked) — Server guard KICKOFF_STANDARD_PASS_ONLY + client isKickOff guard implemented. Phase 14 Plan 01.

### Replay Improvements

- [ ] **REPLAY-04**: Post-game replay plays at double the v1.0 speed (approximately 0.5 seconds per action frame instead of 1 second)
  - **Outcome:** ✅ Wired (admin gap — checkbox not ticked) — 500ms cadence implemented and integration tested. Phase 14 Plan 03.
- [ ] **REPLAY-05**: During a Movement Phase replay frame, all pieces moved in that phase animate/update simultaneously rather than one at a time
  - **Outcome:** ✅ Wired (admin gap — checkbox not ticked) — K simultaneous step-frames implemented and integration tested. Phase 14 Plan 03.
- [ ] **REPLAY-06**: Ball position updates correctly on every replay frame; the ball marker always reflects the ball's final position for each replayed action
  - **Outcome:** ❌ Partially implemented — ballAfter field universal on 13 ActionEvent members; unit test passes. UAT Test 6 confirmed live-session ball tracking bugs; deferred as minor to v1.2.

### Rule Correctness & Bug Fixes

- [x] **RULE-01**: On a High Pass, the header contestant selection phase is triggered only after the accuracy check roll resolves — not before the roll
  - **Outcome:** ✅ Validated — Phase 11 Plans 01/03 (headerAccuracyRollPending gate)
- [x] **RULE-02**: On a High Pass with header contestants, the target hex selection step is triggered only after the header contestant duel resolves — correct sequence is: accuracy check → contestant duel → target selection
  - **Outcome:** ✅ Validated — Phase 11 Plans 01/04 (computeHeaderDuelWinner + winner-guarded applyResolveHeaderTarget)
- [x] **RULE-03**: After a snapshot resolves, all shot-path highlight hexes are cleared from the board before entering the next phase; no stale highlights persist into the Movement Phase or subsequent actions
  - **Outcome:** ✅ Validated — Phase 11 Plan 02 (lastShotPath: null on 3 LOOSE_BALL branches)
- [x] **RULE-04**: During SNAP_DEFLECT phase, hex highlights for a deflecting piece's valid moves are suppressed once that piece has used its maximum deflection pace allowance (2 hexes)
  - **Outcome:** ✅ Validated — Phase 11 Plan 03 (canSelectSnapDeflect pace guard in HexGrid)
- [x] **RULE-05**: After a shot is deflected into Loose Ball, both teams enter a normal Movement Phase; both teams' pieces are selectable and can be activated in the correct 4-5-2 sequence
  - **Outcome:** ✅ Validated — Phase 11 Plan 03 (root cause: stale paceUsedByPieceId; fixed in applyStartMovement reset)
