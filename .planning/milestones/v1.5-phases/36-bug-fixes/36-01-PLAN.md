<objective>
Restore a Back control on the Game Settings screen (BUG-33 / D-01..D-05) that returns the host
to the Landing screen AND tears the already-created room down server-side immediately via a new
dedicated `LEAVE_ROOM` socket event.

Purpose: today `GameSettingsScreen` renders immediately after Create Room (the room already
exists server-side — `App.tsx`'s `onRoomJoined` routes slot 1 straight to `GAME_SETTINGS`), and
there is no way out. The host is stuck. Per D-03 the fix must NOT lean on the existing
disconnect/grace-timer path, which leaves the room code alive and joinable for up to ~90s.

Output: `LEAVE_ROOM` event + server handler, a Back button on `GameSettingsScreen` only (D-04),
client state reset back to `LANDING`, and regression coverage in both packages.
</objective>

Task 1's second integration test asserts a room-less socket cannot delete an unrelated room.                                                              |

No mutex or rate limit needed for a terminal, idempotent handler.                                                                                                                                                                  |
