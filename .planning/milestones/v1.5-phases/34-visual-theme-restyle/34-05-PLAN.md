<objective>
Close the two Phase 34 UAT gaps (tests 3 and 8), which share one root cause: the Confirm
buttons on the Uniform Selection screen (the screen users experience as "Team Select") and
the Lineup Assignment screen ("Roster") use bespoke color tokens instead of the shared CTA
color pattern used everywhere else in the app.

Per the user's verbatim UAT report, the not-ready Confirm must "follow the white
outline/text w/grey background pattern for other buttons" and the ready Confirm must "match
the other green ready button patterns." Translating to the canonical family in
ActionPanel.module.css (`.ctaButton` / `.ctaButtonReady`):

- Not-ready = neutral-grey base: `background: var(--color-bg-surface-alt)` (#262626),
  `color: var(--color-text-inverse)` (white), `border: 1px solid var(--color-border-muted)`
  (already present). Today it wrongly uses `--color-confirm-pending-bg` (#eab308 bright
  yellow/gold) with dark text.
- Ready = canonical green: `background: var(--color-cta-ready-bg)` (#27ae60) with
  `--color-cta-ready-bg-hover`. Today it wrongly uses `--color-success` (#22c55e) /
  `--color-success-hover`.

Additionally, the Roster screen has no true not-ready visual state in code (the Confirm is
either hidden or always rendered green); this plan adds a disabled grey not-ready Confirm
button to the draft-incomplete branch so the user sees the not-ready → ready transition.

This addresses THEME-01 (consistent charcoal/CTA palette app-wide) and closes UAT tests 3
and 8. Both gaps are cosmetic.

Purpose: One consistent Confirm-button color language across the setup screens.
Output: Migrated confirm-button color tokens + renamed self-documenting classes + a genuine
not-ready state on the Roster screen, with the affected component tests updated.
</objective>
