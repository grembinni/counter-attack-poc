<planner_decisions>
Decisions made during planning that extend (never replace) the locked CONTEXT.md decisions. Downstream plans cite these as PD-NN.

- **PD-01 — "shot hex" means the SHOOTER's hex, not the target hex.** D-01 defines `X` as "the shot hex's distance from the near goal line... 0 = standing on the goal line, growing as the shooter moves away". "Standing" and "as the shooter moves away" both refer to the shooter's own position. `45-PATTERNS.md`'s inline sketch passes `shotTarget` — that sketch is superseded by this decision. Use the shooter piece's `position` at the moment of the shot. For a penalty kick, the kicker piece's position (which sits at `PENALTY_SPOT` after `PENALTY_KICK_SETUP`) is the shot hex.
- **PD-02 — goal orientation.** `pitch.ts` places `homeGoal` at `q = 0` and `awayGoal` at `q = 36`. A team defends its own goal, so `attackingTeam === 'home'` attacks `q = 36` and its defender-count regions are `awaySixYardBox` / `awayPenaltyArea`; `attackingTeam === 'away'` attacks `q = 0` with `homeSixYardBox` / `homePenaltyArea`. `X = Math.abs(shotHex.q - goalQ)`.
- **PD-03 — per-factor clamping (extends D-01, does not alter its weights).** D-01's four factors are each `1 - (something non-negative)` and are therefore each `<= 1`, but they can go negative for extreme inputs (8 defenders in the six-yard box makes factor 1 negative; a 20-hex-deep shot makes factor 4 negative). Two negative factors would multiply back to a nonsensical positive xG. Each of the four factors is clamped with `Math.max(0, factor)` BEFORE multiplication. The weights, thresholds, and structure of the formula are untouched. Result is therefore always in `[0, 1]`.
- **PD-04 — raw float storage.** `matchStats.xg` holds an unrounded running float. All rounding/formatting is display-only, client-side.
- **PD-05 — no new `ActionEvent` type and no new `ActionEvent` field.** xG and shot counts are written directly into `GameState.matchStats` at each resolution site. STATE.md flags "new dice-roll event types are invisible to Undo/Replay unless registered in every relevant list" as a bug class that has already shipped twice (BUG-30/31, BUG-37). Keeping the `ActionEvent` union untouched removes that entire checklist (isBoundary, REPLAY_ELIGIBLE_TYPES, ELIGIBLE_NEXT_ACTIONS, ActionLog exhaustiveness) from this phase's risk surface. This supersedes `45-RESEARCH.md`'s "stash `xg` on the resolving event" suggestion and `45-PATTERNS.md`'s `xg?: number` ActionEvent field.
- **PD-06 — `wasManualOverride` lives inside `RefereeCard`, not as a sibling `GameState` field.** `buildReplayFrames` already carries `refereeCard: finalState.refereeCard` verbatim into every replay frame, so nesting the flag there makes it survive replay for free. `45-RESEARCH.md` Pitfall 3 offered both placements; this is the cheaper one.
</planner_decisions>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server engine → GameState → Socket.io broadcast → both clients | The new `matchStats` values cross from authoritative server computation into two untrusted browser contexts. This plan defines the shape only; no boundary is crossed by this plan's own code. |
| shared package → server AND client | `packages/shared` is imported by both tiers. A function placed here is callable client-side, so any function that must remain authoritative needs its authority enforced by where it is CALLED, not by where it lives. |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01 | Tampering | `computeShotXg` in `packages/shared` is importable by the client, so a modified client could compute its own xG | mitigate | The value is never accepted from the client: `GameState.matchStats` is written only by server code (plans 45-02/45-03) and only ever read by the client. There is no client→server event in this phase that carries a stat value. The client renders `state.matchStats` verbatim and computes only pure display ratios (percentages) from server-provided raw counts, per 45-RESEARCH.md Security Domain and STATE.md's server-authoritative decision. Enforced by plan 45-04's acceptance criteria, which forbid importing `computeShotXg` into any client component. |
| T-45-02 | Information disclosure | `matchStats` broadcast symmetrically to both players | accept | Match statistics are not secret and are shown identically to both managers by design (STATS-01/STATS-02). ASVS V4 applies only narrowly here: no per-team filtering is required, unlike `DraftClientView`'s privacy split. The existing full-snapshot `GAME_STATE` broadcast already delivers identical bytes to both sockets. |
| T-45-03 | Denial of service | Unbounded/NaN xG value poisoning a running total | mitigate | PD-03's per-factor clamp bounds every single-shot contribution to `[0, 1]`, so the running total cannot diverge, go negative, or sign-flip. | T-45-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this phase installs zero external packages (45-RESEARCH.md Package Legitimacy Audit: `packages/shared` has no dependencies at all; no new dependency declarations in any package).
