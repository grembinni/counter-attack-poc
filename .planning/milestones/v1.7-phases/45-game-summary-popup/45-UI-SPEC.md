## Spacing Scale

Declared values (must be multiples of 4) — reusing the project's established subset, confirmed by explicit precedent comment in `GameSettingsScreen.module.css` ("Spacing: new elements use only 4/8/16/24/32"):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between stat value and its pill/badge; gap inside `(i)` icon row |
| sm | 8px | Gap between settings-recap parenthetical items; row-internal gaps |
| md | 16px | Gap between stat rows; modal card internal gap |
| lg | 24px | Modal card padding (matches `.overlayCard`/`.card` precedent) |
| xl | 32px | Not used this phase |
| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

Exceptions:
- Diverging-bar height: `6px` and the center seam gap: `2px` — graphic/stroke dimensions, not layout spacing. Consistent with existing non-4px exceptions already in the codebase (1px borders, 2px `--color-divider-subtle` hairlines).
- `(i)` info-icon circle diameter: `16px` — reuses the existing `.statBubble` circle-diameter convention verbatim (`GameBoard.module.css`), not a new exception.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 13px | 400 | 1.5 |
| Label | 13px | 700 | 1.2 |
| Heading | 18px | 700 | 1.2 |
| Display | 20px | 700 | 1.2 |

Usage mapping (so the 4 generic roles read unambiguously against this phase's actual elements):
- **Body (13/400):** settings/toggle recap text, xG explainer note, "Waiting for..." style helper copy.
- **Label (13/700, uppercase, `letter-spacing: 0.05em`):** centered stat-row labels ("TOTAL SHOTS", "POSSESSION") — reuses `.phaseLabel`/`.sectionLabel` treatment verbatim, no new CSS pattern.
- **Heading (18/700):** stat VALUE numerals (home/away figures either side of each bar) and the possession percentage inside its pill. New size (18px) is deliberately close to the existing 18px non-text UI scale already used immediately adjacent in this same top-band region (`NationFlag`/`CardInjuryBadge` at `size={18}`) — chosen for visual parity, not invented arbitrarily.
- **Display (20/700):** modal title "MATCH SUMMARY" — reuses `GameSettingsScreen.module.css`'s `.heading` size verbatim.

Only 3 distinct sizes (13 / 18 / 20) and 2 weights (400 / 700) — within the 3–4 size / 2 weight ceiling.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `var(--color-bg-page)` (#121212) | Modal backdrop's page-level context (pitch behind it), overlay backdrop itself uses the existing `--color-overlay-backdrop` scrim |
| Secondary (30%) | `var(--color-bg-surface)` / `var(--color-bg-surface-alt)` | Modal card background, bar TRACK background (unfilled portion), divider background context |
| Accent (10%) | `var(--home-accent)` / `var(--away-accent)` (runtime per-team CSS custom properties, already injected at the `GameBoard` root) | Reserved for: (1) home/away VALUE numerals in every stat row except Yellow/Red Cards, (2) the two diverging-bar fill segments, (3) the two possession pills. **Not** `--color-accent-gold` — gold stays exclusively reserved for the clock/brand per the existing project rule (confirmed via codebase grep: gold never used for stat/data emphasis anywhere today); this phase does not introduce a new gold usage. |
| Destructive | `var(--color-danger)` (#ef4444) for Red Cards; `var(--color-card-yellow)` (#eab308) for Yellow Cards | Documented exception below |

Accent reserved for: home/away stat-row value numerals, diverging-bar fill segments, possession pills — nowhere else in this popup. The `(i)` info icons are intentionally NEUTRAL (`--color-text-secondary` glyph on `--color-bg-surface-alt` circle, `--color-border-muted` border) so they don't compete with the team-accent comparison language of the bars, and don't compete with the gold clock they sit directly above (D-08 placement).

**Documented exception — Yellow Cards / Red Cards row:** the two VALUE numerals in these two rows render in their fixed semantic card color (`--color-card-yellow` / `--color-card-red`) instead of `--home-accent`/`--away-accent`, because card color is already a fixed, non-team-tinted semantic everywhere else in the app (`CardInjuryBadge`, pitch overlay, roster, bench — cards are always yellow/red regardless of which team). The diverging BAR beneath those two rows still splits using `--home-accent`/`--away-accent` (the bar's job is proportional comparison, not card-color semantics) — only the two numerals change convention.

## Layout & Component Contract (Phase-Specific)

This section captures the visual direction locked in from the 3 user-provided reference images (Sofascore-style "Match overview", a red/white "Top stats" sheet, and a crest-branded tabbed "Stats" page). **Common thread used as the actual design decision:** horizontal diverging bar-per-stat, not a two-column table.

### `MatchSummaryContent` — shared block (D-11)

One component, two consumers: (a) body of the standalone on-demand modal, (b) appended inside the existing HALF_TIME/FULL_TIME `.overlayCard`, below its current header, above its existing proceed/confirm controls (D-10). Do not fork the rendering logic between call sites.

Content order, top to bottom:

1. **Settings recap section** — "SETTINGS" label + the inline parenthetical recap row (Copywriting Contract above). Plain text, no bars — these are toggle states, not comparable numeric values.
2. **Divider** — `1px solid var(--color-border)` full-width rule (reuses the exact token/weight already used for `.topBand`'s border-bottom and `.tabs`' border-bottom — not `--color-divider-subtle`, which is reserved for the scoreboard's own internal cell dividers). Mirrors reference image 2's section-divider pattern.
3. **Stat-bars section** — 8 rows, generous vertical spacing (`16px` gap between rows), no per-row dividing lines — spacing alone separates rows (matches reference image 1's "no visible dividing lines" note). Row order: Possession → Passes Completed → Tackles & Steals → Shots → Expected Goals (xG) → Fouls → Yellow Cards → Red Cards.

### Stat row anatomy — standard (diverging) rows

Applies to: Passes Completed, Tackles & Steals, Shots, Expected Goals (xG), Fouls, Yellow Cards, Red Cards (7 of the 8 rows).

- **Text row:** 3-part flex row — home value (far-left, Heading style 18/700, colored per the Color contract above) — stat label (centered, Label style 13/700 uppercase) — away value (far-right, Heading style 18/700, colored per the Color contract above).
- **Bar row (below text row):** thin (`6px` tall, `border-radius: 3px`) two-segment bar with a `2px` gap at the horizontal center (the "diverging bar chart" look from reference images 1 and 3 — NOT a continuous single fill).
  - `home_share = home / (home + away)`.
  - Left segment (grows outward from the center-left toward the left edge): width = `home_share × half-track-width`, fill = `--home-accent`.
  - Right segment (grows outward from the center-right toward the right edge): width = `(1 - home_share) × half-track-width`, fill = `--away-accent`.
  - **Divide-by-zero guard (documented default):** if `home + away === 0` (e.g. no shots taken yet), render the bar as a flat, unfilled track (`--color-bg-surface-alt`, no colored segments) rather than fabricating a 50/50 split — an even split would visually imply real comparative data where none exists yet. This is this spec's explicit choice per the open "your call" in the design brief.
- **Tackles & Steals value format:** `{count} ({percent}%)` per side, e.g. `12 (67%)` — the raw `{count}` (successful tackles + steals) drives the diverging-bar calculation above; the `({percent}%)` success-rate figure is secondary text appended inline in the same Heading-styled value, not a separate row or separate bar (percentages aren't independently summable the way counts are).

### Stat row anatomy — Possession (special case, per reference image 1)

- **Pills (above the bar):** two rounded pill badges, home value pill flush-left (solid `--home-accent` background, white text, e.g. "58%"), away value pill flush-right (solid `--away-accent` background, white text, e.g. "42%"). Pill text uses Heading style (18/700).
- **Bar (below the pills):** a single, edge-to-edge, continuous (no center gap) bar, `6px` tall. Left segment width = home%, fill `--home-accent`; immediately followed by right segment width = away%, fill `--away-accent`; NOT a diverging/center-split bar like the other 7 rows — this is the one row that is already a direct 0–100 percentage, so it fills directly (matches reference image 1's possession treatment exactly).
- **Remainder guard:** possession is tracked as "percentage of elapsed match minutes," and dead-ball/stoppage time may not be attributed to either team, so `home% + away%` can be `< 100%`. Render any remainder (`100 - home% - away%`) as a neutral, unfilled track segment (`--color-bg-surface-alt`) at the right end of the continuous bar, after the away segment — this keeps the bar's total width meaningful (always 100%) without fabricating possession data for dead time.

### `(i)` info icons — two distinct instances, do not conflate

1. **Scoreboard (i) icon (STATS-01, D-08/D-09):** hosted in `GameBoard.tsx`'s `.scoreboardCentreCell`, as a new row directly above `.clockRow`. 16px neutral circle (`--color-bg-surface-alt` fill, `--color-border-muted` border, `i` glyph in `--color-text-secondary`, 10px/700). Always clickable in every phase (D-09) — opens the standalone `MatchSummaryContent` modal. Hover shows the native `title="View match summary"` tooltip; click/tap opens the modal (click is authoritative — must work identically on mouse and touch, since this is a real-time 2-player game where either input device is in play).
2. **xG-row (i) icon (new this phase, per reference image 1's precedent):** hosted inline immediately after the "Expected Goals (xG)" label text inside that stat row, same 16px neutral circle treatment as #1 above (same visual token, different placement/purpose — do not visually distinguish them from each other). **Interaction (this spec's judgment call, since the design brief left it open):** click/tap toggles an inline expandable text note directly beneath the xG row (accordion-style reveal, not a floating tooltip/portal) showing the static explainer copy from the Copywriting Contract above. Chosen over a hover-only tooltip because hover has no reliable touch equivalent and the codebase has no existing tooltip/portal library to build a proper floating tooltip with (no Popper/Floating UI dependency) — an inline expand/collapse reuses the same "plain conditional render" pattern already used throughout this app (e.g. `ActionLog`'s expand/collapse chevron), works identically on mouse and touch, and needs no new dependency.

### Modal chrome — standalone on-demand popup

New CSS, modeled directly on existing precedent rather than invented:

- **Backdrop:** `.matchSummaryOverlay` — `position: fixed; inset: 0;` + `var(--color-overlay-backdrop)`, `z-index: 30` (higher than the existing substitution overlay's `z-index: 20`, so it can always open on top per D-09's "always clickable including mid-duel/prompt interrupts" — this popup must never be blocked by or hidden under another overlay).
- **Card:** `.matchSummaryCard` — modeled on `.overlayCard` verbatim (`max-width: 760px`, `background: var(--color-bg-surface)`, `border: 1px solid var(--color-border)`, `border-radius: 4px`, `padding: 24px`, `display: flex; flex-direction: column; gap: 16px`), plus `max-height: 85vh` so the card never exceeds the viewport.
- **Header row:** modal title ("MATCH SUMMARY", Display style) left-aligned or centered (centered, matching all 3 reference images' centered-title convention) with a small `×` icon-button top-right for quick dismiss (`aria-label="Close match summary"`) — pinned outside the scroll region.
- **Scrollable body:** `MatchSummaryContent` itself gets `max-height: 50vh; overflow-y: auto;` inside the card, so the title and the bottom Close button remain visible/pinned even if the stat list needs to scroll.
- **Footer:** "Close" button, reusing `.overlayCtaButton`'s exact visual treatment verbatim — pinned outside the scroll region, below `MatchSummaryContent`.

### Modal chrome — HALF_TIME/FULL_TIME embedded instance

No new overlay/backdrop (reuses the existing `.overlay`/`.overlayCard` already rendered for these two phases, per D-10). Insertion order inside the existing `.overlayCard`:

1. Existing score-row header (`.halfTimeScoreRow` etc.) — untouched.
2. **NEW:** divider (`1px solid var(--color-border)`).
3. **NEW:** `MatchSummaryContent`, with `max-height: 40vh; overflow-y: auto;` (slightly tighter than the standalone modal's 50vh, since the score-row header above it is already tall).
4. Existing proceed/confirm controls (`myConfirmed`/"Start 2nd Half" button at half-time; result display at full-time) — untouched, but now positioned below the appended stats block per D-10, not immediately after the header as they are today.

### Explicitly out of scope this phase

- Tabbed stat-category navigation (reference image 3's "General / Passing / Attacking / Defending" tabs) — this phase's stat list is small and flat (8 rows); no category grouping was requested by CONTEXT.md or REQUIREMENTS.md. Do not build a tab system.
- Per-value "leading stat" badge/pill highlighting (reference image 2's inconsistent solid-vs-outline circle treatment on standout values) — flagged as optional future polish, not required for this phase. Do not block delivery on it; the plain colored-numeral treatment specified above is the shipped baseline.
- Live-update visual transitions (flash/highlight on a changed number) — confirmed by the user: plain re-render only, no animation/highlight treatment when a stat updates while the modal is open.
