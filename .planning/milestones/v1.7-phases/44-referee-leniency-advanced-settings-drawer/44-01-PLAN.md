<objective>
Give `buildInitialGameState` the ability to accept a host-supplied Referee Leniency override and bake it into `GameState.refereeCard.leniency` instead of the random roll, without touching any wire contract, room state, or UI.

This is the deepest hop of the six-hop plumbing chain and is deliberately isolated: it adds two **defaulted trailing parameters**, so every existing positional caller (production `roomHandlers.ts` LINEUP_CONFIRM plus ~40 test call sites) keeps compiling untouched and the repository stays fully green at this plan's boundary.

Purpose: REFEREE-02 needs the selected 2–5 value to actually reach the engine. REFEREE-04 requires that the override drive **both** the booking threshold and the added-time calculation — this plan proves the coupling holds automatically because both consumers already read `state.refereeCard.leniency` and neither needs an override branch. REFEREE-03 was already shipped by quick task `260823-akw` (commit `390bd271`); this plan does **not** re-implement it, it pins it with a regression test so the new conditional cannot silently break the random fallback.

Output: two new engine parameters, one conditional expression, and a dedicated engine test file.
</objective>
