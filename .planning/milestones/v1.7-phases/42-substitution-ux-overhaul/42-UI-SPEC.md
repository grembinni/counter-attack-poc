## Spacing Scale

Declared values (must be multiples of 4) — matches the scale already in use across `LineupAssignmentScreen.module.css`/`GameBoard.module.css`:

| Token | Value | Usage                                                                   |
| ----- | ----- | ----------------------------------------------------------------------- |
| xs    | 4px   | Icon-to-label gaps, badge padding (`.outBadge`/`.redCardBadge` pattern) |
| sm    | 8px   | Card internal gap, column gap, chip gap                                 |
| md    | 16px  | Section gap (`.benchSection`/`.formationColumns` gap), screen padding   |
| lg    | 24px  | Screen-level padding (`.screen`), Resume CTA button horizontal padding  |
| xl    | 32px  | Reserved — not needed by any new element this phase                     |
| 2xl   | 48px  | Reserved — not needed by any new element this phase                     |

Exceptions:

- Confirm-popup card padding is `16px` with a `12px` internal gap (`.confirmCard`, `ActionPanel.module.css`) — reused verbatim, not redeclared.
- The 3-way mode toggle's own new elements (substitution-mode action button, red-card slot placeholder) must stay on this scale; no new off-scale value is introduced by this phase.

## Typography

Only the sizes/weights needed by this phase's NEW elements are declared below. Every value is a value already in use elsewhere in the codebase — no new size or weight is introduced.

**Weight budget for this phase: 2 weights — 400 and 700.** Both are new-to-this-phase declarations, used exactly as the 2-weight rule intends: 400 for body/helper copy, 700 for labels/small buttons.

| Role                                                           | Size | Weight | Line Height |
| -------------------------------------------------------------- | ---- | ------ | ----------- |
| Body / helper text                                             | 13px | 400    | 1.5         |
| Label / meta (badges, chip text, slot caption)                 | 12px | 700    | 1.2         |
| Small button (mode-toggle action button, matches `.ctaButton`) | 11px | 700    | 1.2         |

**Accepted deviation — CTA row (not counted against the 2-weight budget above):**

| Role                                               | Size | Weight | Line Height |
| -------------------------------------------------- | ---- | ------ | ----------- |
| CTA (Resume button, matches `.confirmButtonReady`) | 20px | 800    | 1.2         |

This phase adds zero new elements that originate a new font weight of their own — the Resume button is a straight visual-weight match to the app's single, pre-existing "primary CTA" convention (`.confirmButtonReady`, `.confirmButton`), which has already been weight-800 everywhere it appears since before Phase 42 (see `ActionPanel.module.css`, referenced directly by D-04 in `42-CONTEXT.md`: the Resume button must match "the visual weight of other CTA buttons in the app (e.g. the ActionPanel's Confirm button)"). Declaring it at 700 instead would fabricate a _new_, phase-local visual treatment that contradicts D-04's explicit instruction to reuse the existing CTA convention as-is — a worse outcome than reusing a pre-existing, zero-new-weight exception. Per the dimension-4 rule, this is requested as an accepted deviation: the phase's own weight budget is 2 (400, 700); 800 is not a third phase-introduced weight, it is the unmodified reuse of an app-wide convention that predates this phase and appears in zero other new elements here.

## Interaction States (new elements only)

Positioning-mode on-field card:

- Default: `.statCard` (existing) — `cursor: grab`
- Dragging: `.statCardDragging` (existing, 0.45 opacity)
- Valid drop target (another on-field card, position swap): `.statCardDropTarget` (existing gold ring) — applies instantly on drop, **no confirm popup** (D-02)
- Disabled (any other action selected/pending, SUB-09): card is non-draggable; no new visual treatment needed beyond `draggable={false}` — reuse `.statCard` base with `cursor: default` via the existing `isDraggable` boolean already threaded through `LineupStatCard`

Red-carded on-field slot (D-05/D-06):

- Renders the "SENT OFF" placeholder in place of a player card (never renders the red-carded piece itself on the pitch side)
- Remains a valid drop target for another on-field player being repositioned into it (not permanently locked)
- Uses the same card footprint (`.statCardBase` dimensions: `min-width: 260px`, `padding: 6px 8px`, `border: 1px solid var(--color-border)`, `border-radius: 4px`) so the formation column layout does not reflow when a red card is issued mid-column

Substitution-mode entry/cancel button:

- Default ("Substitute"): small button matching `.ctaButton` (11px/700, `--color-bg-surface-alt` background, hover to `--team-accent`)
- Disabled (3/3 subs used): `opacity: 0.5`, `cursor: default` (matches existing `.ctaButton:disabled`)
- Active ("Cancel"): same button treatment, label swap only — no color change needed since Cancel is not destructive

Bench card in substitution mode (unchanged from Phase 40 — reused as-is):

- Draggable when `status === 'available'` and not `readOnly`
- Non-draggable + `.cardUnavailable` (0.7 opacity) when `subbedOut` or `redCarded`
- Badge: reuses Phase 41's `CardInjuryBadge` exactly (D-07) — no new bench-side component

Resume button:

- Default: full-width, bottom of panel, `--color-cta-ready-bg` background, `--color-text-inverse` text, 20px/800
- Hover: `--color-cta-ready-bg-hover`

`.subButtonStrip` editable state (SUB-17):

- Inactive/not-editable: existing default (`--color-bg-surface` background, `--color-text-secondary` label)
- Editable (stoppage + this team's turn to act): full container background becomes `--color-speed-standard-bg`, label color `--color-success` — extends the existing `.subButtonActive` treatment (currently only on the inner 28px button) to the whole `.subButtonStrip` container, per D-03
