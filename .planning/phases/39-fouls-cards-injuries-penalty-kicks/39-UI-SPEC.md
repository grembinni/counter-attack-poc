## Typography

| Role    | Size | Weight | Line Height |
| ------- | ---- | ------ | ----------- |
| Body    | 13px | 400    | 1.5         |
| Label   | 11px | 400    | 1.5         |
| Heading | 12px | 700    | 1.2         |
| Display | 20px | 700    | 1.2         |

Only two weights exist app-wide: 400 (regular) and 700 (bold/emphasis) — no intermediate weights. Do not introduce one for this phase.

Role mapping for this phase's new components:

- **Heading (12px/700)** — `FoulChoicePanel`/`GkDiveAtFeetPromptPanel`/box-entry-prompt/`PenaltyKickSetupPanel` panel titles (`"Foul!"`, `"Dive at Feet?"`, `"Goalkeeper Reposition?"`, `"Penalty Kick"` — see Copywriting Contract).
- **Label (11px/400/1.5)** — `.helperLine2`-style detail text under each prompt heading, constraint/status rows, `.errorText`, CTA/choice button text, the roster-panel card/injury chip text, the booking banner's "DOGSO" label text.
- **Body (13px/400/1.5)** — `ActionLog` entries for every new roll type (foul detection, injury check, booking check, GK-dive-at-feet duel, box-entry response, penalty-kick duel) — matches every existing `ActionLog` entry's `.entry`/`.content` sizing exactly, per D-02's "logs always" requirement. Also the extended `LOOSE_BALL_LAND` entry text (D-15).
- **Display (20px/700/1.2)** — the transient `EventBanner` message text (`.banner` at `font-size: 28px` is the one existing exception to the 20px Display role — reuse the banner's own established 28px size, do not shrink it to 20px for this phase's new foul/injury/booking banner variants; this preserves visual parity with the existing goal/interception/tackle banners already at 28px).

## Color

| Role            | Value                                                                                                                                 | Usage                                                         |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| Dominant (60%)  | `#121212` (`--color-bg-page`)                                                                                                         | Page background behind the board                              |
| Secondary (30%) | `#1c1c1c` (`--color-bg-surface`) / `#262626` (`--color-bg-surface-alt`)                                                               | New panels' container backgrounds                             |
| Accent (10%)    | `#27ae60` / `#f39c12` (`--color-cta-ready-bg` / `--color-cta-pending-bg`), `--team-accent` (`#b08b08` fallback, runtime team-derived) | See "Accent reserved for" below                               |
| Destructive     | `#ef4444` (`--color-danger`)                                                                                                          | Inline validation/error text; red-card badge fill (see below) |

Accent reserved for:

- `--color-cta-ready-bg` (green) / `--color-cta-pending-bg` (orange) — `PenaltyKickSetupPanel`'s Confirm button, state-derived exactly like every prior restart panel. The `FoulChoicePanel`/`GkDiveAtFeetPromptPanel`/box-entry-prompt's two choice buttons are **not** color-coded (co-equal `.ctaButton` default styling — neither "Continue Play" vs. "Take the Free Kick" nor "Dive" vs. "Decline" is visually promoted).
- `--team-accent` — CTA hover state only, consistent with every existing sidebar panel.
- The existing hex-tint/ring highlight system (`docs/HIGHLIGHT-REFERENCE.md`) governs all in-pitch highlighting (see Design System's highlight-mapping table above) — out of scope for this 60/30/10 chrome split.

**New semantic tokens required this phase** (card/injury badges are a genuinely new UI concept — not a reuse of an existing chrome color under its original meaning; per the project's established "reuse the same swatch value under a new dedicated semantic name" convention — see `tokens.css`'s own precedent for `--color-border` reusing `--color-bg-surface-alt`'s value and `--color-speed-standard` reusing `--color-success`'s value):

| New token             | Value     | Reuses swatch of             | Usage                                                                                           |
| --------------------- | --------- | ---------------------------- | ----------------------------------------------------------------------------------------------- |
| `--color-card-yellow` | `#eab308` | `--color-confirm-pending-bg` | Yellow-card badge fill (on-board `PieceOverlay` badge, roster-panel chip, booking banner badge) |
| `--color-card-red`    | `#ef4444` | `--color-danger`             | Red-card badge fill (on-board `PieceOverlay` badge, roster-panel chip, booking banner badge)    |

**Card/injury badge geometry (D-05):** same radius as the existing ball-possession dot (`PIECE_RADIUS * 0.59`, `PieceOverlay.tsx`), positioned at the **negated** dot offset (`-dotOffsetX, -dotOffsetY` — i.e. the corner of the piece opposite wherever the ball dot renders: top-left for home pieces, top-right for away pieces). Card badge = a small rounded-rect (not a circle, to read distinctly from the circular ball dot) filled `--color-card-yellow`/`--color-card-red` with a `rgba(0,0,0,0.5)` 1px stroke (matching the ball dot's own stroke treatment). Injury badge = a white (`--color-text-inverse`) plus-sign glyph (two crossed rounded bars, no background fill of its own) with a thin `rgba(0,0,0,0.5)` outline for legibility against any jersey color — rendered in JSX/DOM order **after** the card badge so it visually layers on top per D-05, distinguishable from the card badge by shape (cross vs. rectangle), not color, since both may render in the same corner simultaneously.

**Booking banner card badge (D-03):** a small `--color-card-yellow`/`--color-card-red` rectangle (roughly icon-sized, ~18×24px, matching a miniature card silhouette — taller than wide) rendered inline beside the banner text, inside `.banner`'s existing centered box. When the booking resulted from a Professional (Last Man) Foul (FOUL-04/CARD-03), an additional `"DOGSO"` text label (Label role, 11px/700, `--color-text-inverse`, letter-spaced like `.helperLine1`) renders directly beside the card badge — no other visual difference from a normal booking banner.
