  <action>
Add four phase branches, each modelled on the existing goal-kick reposition branch rather than invented from scratch.

`PENALTY_KICK_SETUP_ATTACKING` / `PENALTY_KICK_SETUP_DEFENDING` (PEN-02, D-08):

- A piece is selectable when `myTeam === gameState.activeTeam`, its id is in `penaltyKickEligibleIds.attacking` (attacking window) or `.defending` (defending window), and it is not already in `movedPieceIds`.
- Valid destination hexes are the selected piece's `hexNeighbors` filtered to `isPitchHex` and unoccupied — single-step adjacency per click, exactly like the goal-kick window.
- There is NO per-piece hex budget: PEN-02 is unbudgeted free repositioning (UI-SPEC: "no hex-distance cap qualifier"). Do not port the goal-kick branch's `usedPace >= 6` cutoff. `penaltyKickUsedPace` is still read to detect an in-progress activation (a piece with a non-zero entry that is not yet in `movedPieceIds`), which is what keeps the currently-walking piece selected across broadcasts.
- Additionally exclude any destination inside the defending team's penalty area unless the selected piece is the defending goalkeeper or the already-chosen `penaltyKickTakerId`. Derive the region key from `penaltyKickTeam`: the kicking team attacks the OTHER team's area, so the restricted region is `penaltyKickTeam === 'home' ? 'awayPenaltyArea' : 'homePenaltyArea'`. This is a client-side convenience highlight only — the server rejects the same placement independently (RESEARCH.md's standing rule that the client filter is never the defence).
- Repositioning emits the existing `emitMove` (`GAME_MOVE`), not a new event, matching the goal-kick and corner-kick precedent.

`PENALTY_KICK_TAKER_SELECT` (PEN-02): clicking an own-team, non-goalkeeper, on-pitch piece calls `emitPenaltyKickTaker(piece.id)` directly and selects nothing — mirroring how `THROW_IN_SETUP` routes a piece click to `emitThrowInPlace`. No destination hex is chosen client-side; the server places the taker on `penaltyKickSpot`.

`GK_BOX_ENTRY_MOVE` (D-10): only the piece whose id equals the responding team's goalkeeper is selectable, and only when `myTeam === gkBoxEntryTeam`. Valid hexes are that goalkeeper's `hexNeighbors` filtered to `isPitchHex` and unoccupied — at most six, exactly one step, no budget. Clicking a valid hex calls `emitGkBoxEntryMove(hex)`.

In `setGameState`'s sticky-selection block, add `PENALTY_KICK_SETUP_ATTACKING`, `PENALTY_KICK_SETUP_DEFENDING` and `GK_BOX_ENTRY_MOVE` to the list of phases that keep a locked piece selected across same-window broadcasts, and clear `selectedPieceId` plus any derived pace state whenever the phase changes between two different members of the new set (the `PENALTY_KICK_SETUP_ATTACKING` → `PENALTY_KICK_SETUP_DEFENDING` handoff must start the defending manager with nothing selected, exactly as `GOAL_KICK_SETUP_GK` → `GOAL_KICK_SETUP_OPPONENT` does today).

`FOUL_CHOICE`, `GK_DIVE_AT_FEET_PROMPT` and `GK_BOX_ENTRY_PROMPT` are pure two-button panels with no board interaction: add them to whatever "no piece is selectable" default the store already applies to non-interactive phases, and make sure entering any of them clears `selectedPieceId`.
</action>
