**Reordered applyRoll's PASS branch so the D-03 FIRST_TIME_PASS_MOVE transition runs before the generic occupant-check, restoring the repositioning prompt for first-time passes aimed at a teammate's hex (the realistic, dominant case in live play).**

## Accomplishments

- Fixed the diagnosed root cause from `.planning/debug/ftp-no-reposition-prompt.md`: the FIRST_TIME_PASS_MOVE transition was unreachable whenever the pass target hex was occupied, because a pre-existing occupant-check early-return ran first for all pass types except HIGH_PASS
- Reordered the two blocks so FIRST_TIME_PASS_MOVE is checked immediately after the interception loop, before the occupant-check
- Corrected the PASS-02 regression test that had locked in the buggy pre-fix behavior (`phase === 'PASS'`, direct delivery to occupant) — it now asserts the correct `FIRST_TIME_PASS_MOVE` transition with `ball.carrierId === null` and `passTargetHex` preserved

- Confirmed via full server suite run that the reorder introduced no new failures — all 4 failing tests are pre-existing, unrelated stubs (2 MOVE-06 FREE_MOVE scaffolding gaps, 2 abandoned pre-17.1 `firstTimePassStep` sub-state design tests already documented as "Eliminated" in the debug doc)
