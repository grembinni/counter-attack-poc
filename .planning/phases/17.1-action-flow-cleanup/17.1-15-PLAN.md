<objective>
Close Review-CR-02 (Gap B of the third Phase 17.1 verification cycle): the FIRST_TIME_PASS ball
delivery at the end of the DEFENDER repositioning slot looks up the receiver with a TEAM-RESTRICTED
filter, so a defending-team piece that legally repositions onto passTargetHex is ignored — the ball is
delivered as carrierId:null on a hex a defender physically occupies, with phase PASS (not LOOSE_BALL)
and possession unchanged: an invalid board state with no possession-transfer recovery path.

Root cause (independently confirmed by the verifier against the live codebase, 17.1-VERIFICATION.md
gaps block lines 15, 24-25, 29-30, 70, 85, 111): in gameHandlers.ts the GAME_END_TURN
FIRST_TIME_PASS_MOVE DEFENDER-slot-complete branch (lines 698-733) computes the delivery receiver at
lines 708-713 as `ftpEndState.pieces.find((p) => p.teamId === ftpEndState.attackingTeam && p.position.q
=== targetHex.q && p.position.r === targetHex.r)` — restricted to the attacking team. Everywhere else
that a pass is delivered to an occupied hex (STANDARD_PASS / LONG_BALL), the engine uses the
team-AGNOSTIC BUG-04 pattern (gameEngine.ts:1272-1297): it finds ANY occupant at the target hex,
transfers possession when that occupant is on the opposing team, and makes the occupant the carrier.
The FTP delivery handler predates the BUG-04 fix (it was modeled on HIGH_PASS_MOVE's team-restricted
receiver) and was never reconciled with it. The defender-on-target scenario is directly reachable:
gameHandlers.ts:524-531 (the GAME_MOVE FTP occupancy check) does not exclude passTargetHex as a
defender destination, and plan 17.1-13's own fixture places a defender exactly 1 hex from the target.

Fix: make the FTP delivery receiver lookup team-agnostic, mirroring gameEngine.ts BUG-04 (1272-1297).
Find ANY piece occupying passTargetHex regardless of team. If an occupant exists and is on the
DEFENDING team (occupant.teamId !== ftpEndState.attackingTeam), transfer possession: set ball.carrierId
to the occupant's id, set ball.position to the occupant's position (passTargetHex), and set both
attackingTeam and activeTeam to the occupant's team. If the occupant is on the attacking team,
possession is unchanged and that piece carries (current happy-path behavior). If there is no occupant,
deliver to the empty target hex with carrierId:null and possession unchanged (current empty-target
behavior). Apply the BUG-04 rule exactly — do NOT invent a new LOOSE_BALL transition or new design; the
phase stays PASS as it does for STANDARD_PASS/LONG_BALL occupant delivery.

Purpose: make the FTP delivery produce a consistent board state when a defender occupies the target,
matching the established team-agnostic pickup rule used for every other pass type.
Output: the team-agnostic delivery lookup in gameHandlers.ts plus an integration test for the
defender-on-target case (zero coverage today).
</objective>
