<objective>
Close the fifth (and only remaining) defect of success criterion 3 — the FIRST_TIME_PASS self-pass /
reclaim exploit (the fresh review's CR-01), independently confirmed by the cycle-4 verifier
(17.1-VERIFICATION.md). FIRST_TIME_PASS has no equivalent of HIGH_PASS's highPassCarrierId field, so
nothing identifies or excludes the original passer. Because the FTP transition clears ball.carrierId but
never moves the passer's own piece, and passValidator.ts permits a 1-hex first-time pass (only dist===0
is rejected), the passer can — on an ordinary, in-range FTP target exactly 1 hex away — reposition their
own piece onto the empty passTargetHex during the ATTACKER slot and have the now-team-agnostic delivery
lookup (added by 17.1-15) hand the ball straight back to them. This is a STRIDE Elevation-of-Privilege
exploit (a player bypassing missing server-side validation to reclaim possession with zero risk), not a
cosmetic gap.

Root cause (verifier-confirmed against the live codebase):

- No firstTimePassCarrierId field on GameState (codebase-wide grep: zero matches).
- gameHandlers.ts GAME_MOVE FIRST_TIME_PASS_MOVE handler (488-550) gates only on
  team/lock/pace/adjacency/pitch/occupied-by-other — no passer-identity exclusion.
- gameHandlers.ts FTP delivery occupant lookup (714-716, team-agnostic since 17.1-15) matches ANY piece
  at passTargetHex by position only — including the passer.
- useGameStore.ts selectPiece FTP branch (375-406) gates only on team/lock/pace — same gap on the client.

Fix (mirror the existing highPassCarrierId pattern exactly — do NOT invent a new design):

1. Add firstTimePassCarrierId?: string | null to GameState (types.ts), mirroring highPassCarrierId
   (line 462) in type and JSDoc.
2. Set it to the passer's id (carrier.id, the in-scope const at gameEngine.ts:1020) in the FIRST_TIME_PASS
   transition (gameEngine.ts:1256-1276).
3. Reject pieceId === firstTimePassCarrierId in the server GAME_MOVE FTP handler (gameHandlers.ts ~495-500)
   with GAME_ERROR WRONG_PIECE.
4. Exclude p.id === firstTimePassCarrierId from the delivery occupant lookup (gameHandlers.ts ~714-716).
5. Clear firstTimePassCarrierId: null at delivery alongside the other slot/lock resets
   (gameHandlers.ts ~730-732). Do NOT clear it in applyUndo's lockReset — the pass is still in flight
   when an FTP_MOVE is undone.
6. Mirror the exclusion on the client selectPiece FTP branch (useGameStore.ts ~375-406).
7. Add server + client regression tests in both directions (passer rejected; non-passer accepted).

Out of scope (do NOT touch): the 4 documented pre-existing test failures (2 MOVE-06 FREE_MOVE, 2 abandoned
firstTimePassStep stubs); the already-closed CR-01-old/CR-01-new/CR-02-new/Review-CR-01/Review-CR-02 logic
beyond adding the field and the three exclusion checks. HIGH_PASS itself is documented (see
<artifacts_produced>) as having the identical missing repositioning-exclusion defect — it is NOT fixed
here; only FIRST_TIME_PASS is fixed in this plan.

Purpose: make a first-time pass actually move the ball to a different piece (or an empty hex) without the
passer being able to instantly reclaim it, restoring success criterion 3's "delivers the ball [correctly]"
for the ordinary 1-hex FTP case.
Output: the new firstTimePassCarrierId field + its set/exclude/clear sites across shared/server/client,
plus server and client regression tests covering the self-pass-reclaim path in both directions.
</objective>
