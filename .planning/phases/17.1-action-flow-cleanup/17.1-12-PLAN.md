<objective>
Close CR-01-new (the first of the two newly-confirmed Phase 17.1 verification gaps): a human player
cannot select or move ANY piece during FIRST_TIME_PASS_MOVE in the browser, even though the server
(gameHandlers.ts:488-545) and ActionPanel.tsx panel are fully implemented for it.

Root cause (confirmed by the verifier against the live codebase, 17.1-VERIFICATION.md gaps block):
useGameStore.ts's selectPiece (lines 296-451) has dedicated branches for KICK_OFF_SETUP /
HIGH_PASS_MOVE / GK_KICK_MOVE / SNAPSHOT_DEFLECT but NONE for FIRST_TIME_PASS_MOVE. A click during
this phase falls through to the generic MOVE-phase branch (line 438), which calls validateMove(),
whose first guard (movementSlot === null → WRONG_SLOT) always fires because this phase tracks
position via the separate firstTimePassMovementSlot field, never movementSlot. So validMoveHexes is
always empty. HexGrid.tsx has zero FIRST_TIME_PASS_MOVE references: no canSelectFirstTimePassMove
analog to canSelectHighPassMove, so isClickable (lines 621-629) never enables this phase. And
setGameState's sticky-selection branch (line 506) omits FIRST_TIME_PASS_MOVE.

This is a scope gap, not a regression: plan 17.1-06 built the ActionPanel UI for this phase but
explicitly scoped only ActionPanel.tsx, never HexGrid.tsx / useGameStore.ts.

The fix mirrors the existing, structurally-identical HIGH_PASS_MOVE wiring, adjusted for the
FIRST_TIME_PASS_MOVE pace cap (1 hex, not 3) and its own slot fields (firstTimePassMovedPieceId /
firstTimePassPaceUsed instead of highPass\*). No new server work and no new emit path are needed —
clicking a populated valid-move hex already routes through the existing emitMove → GAME_MOVE path,
and the server's GAME_MOVE handler already handles FIRST_TIME_PASS_MOVE (gameHandlers.ts:488-545).

Purpose: restore the browser-side "reposition one player ≤1 hex" capability for FIRST_TIME_PASS_MOVE,
satisfying success criterion 3.
Output: a selectPiece FIRST_TIME_PASS_MOVE branch, a canSelectFirstTimePassMove derivation + wiring,
a sticky-selection extension, and HexGrid.test.tsx coverage of an actual selection during this phase.
</objective>
