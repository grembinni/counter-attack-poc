## Accomplishments

- Closed Review-CR-02 (Gap B of the third Phase 17.1 verification cycle): the FIRST_TIME_PASS
  DEFENDER-slot delivery receiver lookup in `gameHandlers.ts` was restricted to
  `p.teamId === ftpEndState.attackingTeam`, so a defending-team piece that legally repositioned
  onto `passTargetHex` was ignored entirely.
- Replaced the lookup with a team-agnostic occupant search mirroring `gameEngine.ts` BUG-04
  (lines 1272-1297): find ANY piece at the target hex regardless of team, then transfer
  possession (`attackingTeam`/`activeTeam` set to the occupant's team, `ball.carrierId` set to
  the occupant's id) only when the occupant is on the defending team.
- Preserved both existing behaviors: an attacking-team occupant still carries with possession
  unchanged; an empty target still delivers `carrierId:null` with possession unchanged.
- Added two new integration tests in `game.integration.test.ts` driving the wire layer through
  the FTP DEFENDER slot — one seeding a defending-team piece on `passTargetHex` (asserts
  possession transfer), one seeding an empty target (asserts preserved empty-target behavior).
