## Accomplishments

- `selectPiece` in `useGameStore.ts` now has a dedicated `FIRST_TIME_PASS_MOVE` branch (own-team-only, locked to `firstTimePassMovedPieceId`, pace cap 1 via `firstTimePassPaceUsed`, adjacent on-pitch unoccupied valid hexes) that returns early and never calls `validateMove()` — eliminating the WRONG_SLOT fall-through that was the CR-01-new root cause.
- `setGameState`'s sticky-selection branch now also covers `FIRST_TIME_PASS_MOVE`, keeping the locked piece selected across same-slot server broadcasts (matching existing HIGH_PASS_MOVE/GK_KICK_MOVE behavior).
- `HexGrid.tsx` gained a `firstTimePassMovedPieceId` selector and a `canSelectFirstTimePassMove` derivation, wired into both the `isClickable` OR-chain and the `handleClick` ternary chain — an active player's own piece is now clickable/selectable during this phase, and clicking a valid hex reuses the existing `emitMove` → `GAME_MOVE` path the server already handles.
- `HexGrid.test.tsx` gained a 4-case describe block (`HexGrid — CR-01-new: FIRST_TIME_PASS_MOVE piece selection`) asserting happy-path selection, opponent rejection, non-active-player rejection, and pace-exhausted empty hexes — closing the verifier's "zero HexGrid.test.tsx coverage of this phase" finding.
