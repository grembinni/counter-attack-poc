<objective>
Close the single remaining Phase 17.1 verification gap (17.1-VERIFICATION.md success criterion 3,
"undo is available at the FTP_REPOSITION boundary" — FALSE at runtime). This is CR-01 from
17.1-REVIEW.md, independently reproduced live by the verifier against the built dist.

Root cause: `gameHandlers.ts` emits `'FTP_MOVE'` events during FIRST_TIME_PASS_MOVE repositioning
(gameHandlers.ts:533-540) and `'HP_MOVE'` events during HIGH_PASS_MOVE (gameHandlers.ts:322-329) —
never `'MOVE'`. But `applyUndo` (gameEngine.ts:838-852) and `ActionPanel.tsx`'s `canUndo`
(ActionPanel.tsx:119) both hardcode a search for `evt.type === 'MOVE'`, so the move is never found:
the server returns `NOTHING_TO_UNDO` and the client Undo button renders permanently disabled. The
slot-boundary detection (FTP_REPOSITION / HP_REPOSITION) is already correct in both places — only
the downstream move-presence/move-lookup check is wrong.

The fix is already fully specified in 17.1-REVIEW.md CR-01 (read that section before implementing).
This plan translates that diagnosis into four executable changes; it does not re-investigate.

This is NOT a new regression from this phase — it also affects the pre-existing HIGH_PASS_MOVE phase
— but Phase 17.1 explicitly claims FTP undo works as success criterion 3, so it is fixed here, and
HIGH_PASS_MOVE is fixed alongside it since it is the same one-line discriminant.

No new symbols are introduced. This plan corrects existing logic inside two existing functions
(`applyUndo` and the `canUndo` IIFE) and updates/extends test fixtures and tests. The
`FTP_MOVE`/`HP_MOVE`/`FTP_REPOSITION`/`HP_REPOSITION` ActionEvent variants already exist in
`packages/shared/src/types.ts` (lines 245-272) and already carry the same `pieceId`/`from`/`to`
shape as `MOVE`, so the existing piece-reversal cast/logic in applyUndo is reused unchanged.

Purpose: Make FTP/HP repositioning undo actually function at runtime, satisfying SC3's undo clause.
Output: Phase-aware applyUndo + canUndo, de-masked unit fixtures, and a new end-to-end wire test.
</objective>
