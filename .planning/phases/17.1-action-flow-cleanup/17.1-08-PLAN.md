<objective>
Fix the diagnosed root cause of UAT Test 6 (gap closure for Phase 17.1): `LOOSE_BALL_DIRECTIONS`
in `scoreUtils.ts` is a stale table of fixed axial-style `(q,r)` deltas (referencing a
no-longer-existent `AXIAL_DIRECTIONS` coordinate system per a stale comment), applied directly to
the live pitch's ODD-Q offset coordinates. For the four diagonal directions (NE/NW/SW/SE), a true
single-step neighbor delta on an ODD-Q offset grid must alternate depending on column parity —
applying the same fixed delta repeatedly (as both `computeLooseBall` and the `gameEngine.ts`
D-08 clamp walk currently do) causes NE and SW specifically to overshoot the true hex distance for
every roll with distance >= 2. The reported case (21,4) -> (24,1) is direction=NE, distance=3 under
the buggy formula, but the TRUE hex distance for that displacement is 5, not 3.

Root cause and fix direction are already fully diagnosed in
`.planning/debug/loose-ball-scatter-rolls.md` — this plan applies that fix directly using the
project's own canonical hex geometry (`hex.ts`), it does not re-investigate.

Purpose: Make loose-ball scatter behave as a true single-direction, single-distance straight line
on the actual ODD-Q offset pitch grid, for all 6 directions and both column parities.
Output: Corrected `computeLooseBall`; corrected `gameEngine.ts` LOOSE_BALL clamp walk sharing the
same trajectory logic; comprehensive parity/direction regression test.
</objective>
