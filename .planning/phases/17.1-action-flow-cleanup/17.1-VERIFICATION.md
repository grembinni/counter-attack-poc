# Phase 17.1: Action Flow Cleanup Verification Report

**Phase Goal:** The codebase is aligned with the corrected Counter Attack v1.4.1 phase/action model — GamePhase enum renamed, aerial stat consolidated, ZoI exclusion fixed, first-time-pass repositioning phase added, and GK restart / loose-ball / shot-range mechanics corrected.

**Re-verification:** Yes — fifth cycle.

**History:**

- **Cycle 1:** found the undo clause of success criterion 3 broken (old CR-01 — wrong move-type lookup in `applyUndo`/`canUndo`). Closed by plan 17.1-11.
- **Cycle 2:** re-verified the undo fix as genuinely correct, but a fresh code review then surfaced two further Critical defects: CR-01-new (client could not select/move any piece during FIRST_TIME_PASS_MOVE — feature completely unusable) and CR-02-new (the server's interception loop could shadow the FIRST_TIME_PASS_MOVE transition for a defender-nearby pass). Closed by plans 17.1-12/17.1-13.
- **Cycle 3:** independently re-confirmed CR-01-new/CR-02-new genuinely fixed, but a further fresh code review surfaced two more Critical defects: Review-CR-01 (`applyUndo` never reset the FTP/HP repositioning lock fields, permanently dead-ending the slot after one Undo) and Review-CR-02 (the FTP delivery receiver lookup was team-restricted to the attacking team, ignoring a defender who legally repositioned onto the target hex). Assigned to gap-closure plans 17.1-14/17.1-15.
- **Cycle 4:** independently re-confirmed Review-CR-01 and Review-CR-02 genuinely fixed by direct code reads, but a fresh review surfaced ONE NEW Critical defect — the FTP self-pass/reclaim exploit (review's CR-01): no `firstTimePassCarrierId` tracking field existed, so the original passer could reposition onto and reclaim their own first-time pass on any ordinary 1-hex FTP target, with zero test coverage in either direction. Assigned to gap-closure plan 17.1-16.
- **Cycle 5 (this report):** independently re-confirmed plan 17.1-16's self-pass-reclaim fix is genuinely correct and complete (server + client + tests, no regressions). A further fresh **deep** code review (`17.1-REVIEW.md`) surfaced ONE NEW Critical client-side finding — `setGameState`'s `slotChanged` check never detects the FTP/HP/GK_KICK_MOVE internal ATTACKER->DEFENDER slot hand-off (it only inspects the MOVE-phase `movementSlot` field) — which this verification independently confirmed is real and accurately traced. However, this verification's own severity assessment (see Truth 3 below) determines this is a non-blocking UX staleness gap, not a correctness defect that breaks success criterion 3's contract: the server remains the authoritative guard and correctly rejects any resulting stale click. This is logged as a follow-up gap rather than continuing to block phase closure for a sixth consecutive cycle.
