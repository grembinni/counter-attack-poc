# Phase 17.1: Action Flow Cleanup Verification Report

**Phase Goal:** The codebase is aligned with the corrected Counter Attack v1.4.1 phase/action model — GamePhase enum renamed, aerial stat consolidated, ZoI exclusion fixed, first-time-pass repositioning phase added, and GK restart / loose-ball / shot-range mechanics corrected.
**Verified:** 2026-06-20T02:10:00Z
**Status:** gaps_found
**Re-verification:** Yes — fourth cycle.

**History:**

- **Cycle 1:** found the undo clause of success criterion 3 broken (old CR-01 — wrong move-type lookup in `applyUndo`/`canUndo`). Closed by plan 17.1-11.
- **Cycle 2:** re-verified the undo fix as genuinely correct, but a fresh code review then surfaced two further Critical defects: CR-01-new (client could not select/move any piece during FIRST_TIME_PASS_MOVE) and CR-02-new (the server's interception loop could shadow the FIRST_TIME_PASS_MOVE transition for a defender-nearby pass). Closed by plans 17.1-12/17.1-13.
- **Cycle 3:** independently re-confirmed CR-01-new/CR-02-new genuinely fixed, but a further fresh code review surfaced two more Critical defects in the surrounding code: Review-CR-01 (`applyUndo` never reset the FTP/HP repositioning lock fields, permanently dead-ending the slot after one Undo) and Review-CR-02 (the FTP delivery receiver lookup was team-restricted to the attacking team, so a defender repositioning onto `passTargetHex` was ignored, producing an invalid board state). Assigned to gap-closure plans 17.1-14/17.1-15.
- **Cycle 4 (this report):** independently re-confirmed Review-CR-01 and Review-CR-02 are now genuinely fixed by direct code reads (not by trusting the latest review's prose) — `gameEngine.ts` `applyUndo`'s phase-conditional `lockReset` (lines 906-929) and `gameHandlers.ts`'s team-agnostic FTP delivery occupant lookup (lines 707-720) both confirmed present, correct, and covered by passing tests. However, a fresh code review run after plans 17.1-14/17.1-15 landed surfaced ONE NEW Critical defect — the FTP self-pass/reclaim exploit (review's CR-01) — which this verification independently confirmed is real, directly reachable on ordinary 1-hex first-time passes, and has zero test coverage in either direction.
