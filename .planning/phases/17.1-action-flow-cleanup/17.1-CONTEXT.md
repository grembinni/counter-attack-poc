# Phase 17.1: Action Flow Cleanup — Context

**Gathered:** 2026-06-14 (updated 2026-06-15)

<domain>
## Phase Boundary

Align the codebase with the corrected phase/action design established in the v1.4.1 plan session.
This is a rules-correctness and structural-consistency pass — no new game features, no UI redesign.
Every change here fixes a gap between the current implementation and the intended Counter Attack
1.4.1 rules model.

Changes fall into five areas:

1. Stat model — remove the duplicate `heading` stat; consolidate to `aerialAbility`
2. Player flags — per-player `stealAttemptedByIds` / `tackleAttemptedByIds` arrays with correct
   ZoI exclusion logic and reset timing
3. Phase flow — new FIRST_TIME_PASS_MOVE phase; GK dive gate on all three shot paths;
   GK_RESTART trigger at end of MOVE_PHASE; header challenge multi-contestant selection;
   headed shot to goal line routes through GK_DIVE_PHASE
4. Mechanics — board-edge clamping for loose ball; correct DEFLECT_ACTION thresholds for
   passes; shoot target range validation; GK save spill routes to GK_RESTART
5. GamePhase enum rename — rename 8 phase values to match the v1.4.1 plan document naming
   (MOVEMENT→MOVE, PASS→CHOOSE_ACTION, etc.); rename sweep must land BEFORE other changes

**Out of scope for Phase 17.1:**

- Out-of-bounds rules (throw-ins, goal kicks, corners) — flagged as pending in two places;
  deferred until a dedicated out-of-bounds phase
- New LastActionType values (e.g. QUICK_THROW distinct from STANDARD_PASS) — current reuse
  of STANDARD_PASS eligibility is acceptable for now
- First-time pass max-range enforcement (6 hex per 1.4.1) — include only if trivially
  co-located with FIRST_TIME_PASS_MOVE work, otherwise defer
- Injury mechanic (all stats −1 per 1.4.1) — no injury trigger exists yet; deferred
- Header contestant multi-team duel resolution formula — implement single-best-roll-per-team
- CSV loader for packages/shared/src/data/\*.csv — CSV files are present but unused; fix
  teams.ts directly; CSV loader is a separate data-migration phase
- BallMarker.tsx / HexCell.tsx visual changes — already done (uncommitted); include in
  17.1 commit but no further visual work planned in this phase

### D-02: Player Flags — `stealAttemptedByIds` and `tackleAttemptedByIds`

**Decision: OPTION A — keep GameState arrays** (per-piece booleans rejected as too invasive).

`GameState.stealAttemptedByIds: readonly string[]` — IDs of defenders who have faced a
steal attempt from the ball carrier this sequence.
`GameState.tackleAttemptedByIds: readonly string[]` — IDs of defenders who have made a
tackle attempt this sequence.

**ZoI exclusion — KEY FIX (gameplay currently broken):**
In `moveValidator.ts` ZoI calculation, exclude flagged defenders from their respective
action type ONLY:

- Defender whose id is in `tackleAttemptedByIds` → still projects STEAL ZoI, but NOT tackle ZoI
- Defender whose id is in `stealAttemptedByIds` → still projects TACKLE ZoI, but NOT steal ZoI
- Defender flagged in BOTH → no ZoI at all

Effect: once a defender has attempted a tackle, the attacker can freely move next to them
for the rest of the movement phase without triggering another tackle challenge. Same for steal.

**Reset timing fix:**
Reset both arrays to `[]` at every transition where `nextPhase = 'CHOOSE_ACTION'`
(the post-rename name for PASS). Fix all of:

- `applyEndTurn` ATTACKER_2 → CHOOSE_ACTION branch
- `applyRoll` LOOSE_BALL → CHOOSE_ACTION branch
- Any other `phase: 'CHOOSE_ACTION'` spread in gameEngine.ts

Current reset in `applyStartMovement` (gameEngine.ts:249-250) remains — keep it as an
additional safety net for CHOOSE_ACTION → MOVE transitions.

### D-03: FIRST_TIME_PASS_MOVE — New Server Phase

Add `'FIRST_TIME_PASS_MOVE'` to the `GamePhase` union (renamed from FIRST_TIME_PASS_MOVEMENT
to match the new \_MOVE suffix convention from D-11).

Flow: target hex selected in FIRST_TIME_PASS sub-state → server transitions to
FIRST_TIME_PASS_MOVE → both teams reposition 1 player ≤1 hex each → both End Turn →
ball delivered to target (no interception check) → CHOOSE_ACTION
(lastActionType = 'FIRST_TIME_PASS').

Ball does not move during FIRST_TIME_PASS_MOVE. Target hex stored in existing
`passTargetHex?: HexCoord | null` field.

Active team alternates between attackingTeam (ATTACKER slot) and defending team (DEFENDER slot),
same pattern as HIGH_PASS_MOVE. Undo is available with the same HP_REPOSITION boundary
logic (add an FTP_REPOSITION ActionEventType).

### D-06: GK_RESTART Trigger at End of MOVE Phase

When ATTACKER_2 End Turn fires AND the GK is the ball carrier AND the GK is positioned in
their own penalty area → transition to GK_RESTART instead of CHOOSE_ACTION.

Detection (in `applyEndTurn`, after computing ATTACKER_2 done, before CHOOSE_ACTION branch):

```typescript
const carrier = state.ball.carrierId
  ? state.pieces.find(p => p.id === state.ball.carrierId)
  : null;
if (carrier?.role === 'GK') {
  const ownArea = carrier.teamId === 'home'
    ? PITCH_REGIONS.homePenaltyArea
    : PITCH_REGIONS.awayPenaltyArea;
  if (isInRegion(carrier.position, ownArea)) {
    return { ok: true, state: { ...state, phase: 'GK_RESTART', ... } };
  }
}
```

### D-10: DEFLECT_ACTION Thresholds — Pass Intercept clarification

**Shot deflect — CONFIRMED DONE:** Band A/B classification and thresholds are fully
implemented. No changes needed.

**Pass intercept — THREE CASES (confirmed 2026-06-15):**

1. **Destination IS the defender's hex** (attacker passes directly to a defender):
   - Allow the pass. Defender auto-intercepts (no roll).
   - The defender's hex IS a valid selectable target — must be highlighted in the UI.

2. **Path passes THROUGH defender's hex (destination is BEYOND the defender)**:
   - Keep `PATH_BLOCKED` — destination hex stays non-targetable.
   - Hexes beyond an on-path defender must NOT be highlighted as valid targets.
   - This preserves current blocking behavior.

3. **ZoI-only (defender within 1 hex of path, not on the path)**:
   - Roll: `die === 6 || combined >= 10`.
   - Threshold at gameEngine.ts:1106 already matches — no change needed.

**Return type change (cases 1 and 3 only; case 2 still returns PATH_BLOCKED):**

```typescript
// Case 2 still returns (unchanged):
{ ok: false; reason: 'PATH_BLOCKED' }

// Case 1 + 3 combined result:
{ ok: true; autoIntercepts: PlayerPiece[]; rollIntercepts: PlayerPiece[] }
```

`autoIntercepts` = defenders whose hex IS the destination hex (case 1 — direct pass to defender)
`rollIntercepts` = ZoI defenders from `getZoIDefenders` who are NOT the destination (case 3)

**In `applyRoll` PASS interception loop:**
Process `autoIntercepts` first (no die roll, immediate interception); if none auto-intercepted,
iterate `rollIntercepts` with the `die === 6 || combined >= 10` threshold.

**`validatePass` change scope:**

- Remove `PATH_BLOCKED` ONLY for the case where the destination hex itself is occupied by
  a defender (case 1). This is new behaviour: previously you couldn't pass to an occupied hex.
- KEEP `PATH_BLOCKED` for intermediate hex blocking (case 2) — the existing guard at
  passValidator.ts:76-82 remains in place for that case.

**Test update:** Add a test for case 1 (pass to defender's hex → autoIntercepts populated).
Existing PATH_BLOCKED tests for case 2 (intermediate blocking) remain valid and unchanged.
Do not break existing PATH_BLOCKED test coverage.

- **D-11 implementation order:** Rename sweep FIRST as a standalone commit. Use global
  find-and-replace for each old→new value. The PASS→CHOOSE_ACTION rename requires care:

  Pass them as parameters or as part of the state argument. The exclusion is per-action-type:
  filter `tackleAttemptedByIds` out of TACKLE candidates; filter `stealAttemptedByIds` out
  of STEAL candidates. A defender can appear in tackleAttemptedByIds AND still project steal ZoI.

  landing hex (same as it's used for high-pass target storage).
