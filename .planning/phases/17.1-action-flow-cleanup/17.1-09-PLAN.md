<objective>
Fix the two diagnosed root causes of UAT Test 2 (gap closure for Phase 17.1): the D-02 ZoI
tackle/steal exclusion fix from phase 17.1 plan 02 was applied asymmetrically.

(1) `moveValidator.ts`'s tackle branch (lines ~106-124) returns `{ok:false,
reason:'TACKLE_ALREADY_ATTEMPTED'}` for a defender who already attempted a tackle, REJECTING the
move outright — instead of allowing the move (`ok:true`) without the `TACKLE_ATTEMPT` effect, the
way the sibling steal branch (lines ~95-104) correctly does. Because
`useGameStore.ts`'s `selectPiece`/`setGameState` derive BOTH `validMoveHexes` and
`tackleRiskHexes` from this same `validateMove()` result, rejecting the move strips the hex from
the defender's valid-move set entirely (not just the risk tint).

(2) `HexGrid.tsx`'s `zoiRiskSet` (steal-risk tint) is computed via a RAW, unfiltered call to
`getZoIDefenders` that never references `state.stealAttemptedByIds` at all (confirmed via grep: no
client file references either exclusion array) — so the steal-risk tint never clears after a
failed steal attempt.

Root causes and fix directions are already fully diagnosed in
`.planning/debug/zoi-tackle-steal-exclusion.md` — this plan applies those fixes directly, it does
not re-investigate.

Purpose: Make D-02's cross-type ZoI exclusion (17.1-CONTEXT.md) behave symmetrically for both
tackle and steal — excluded defenders keep their move validity and only lose the specific risk
effect/tint tied to the action type they already attempted.
Output: Corrected moveValidator tackle branch; corrected HexGrid steal-risk computation; new test
coverage for both.
</objective>
