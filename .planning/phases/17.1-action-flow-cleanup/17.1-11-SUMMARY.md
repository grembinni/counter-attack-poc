**Made GAME_UNDO actually reverse FTP_MOVE/HP_MOVE repositioning by fixing a hardcoded `'MOVE'` event-type discriminant in both `applyUndo` (server) and `canUndo` (client) to be phase-aware.**

## Accomplishments

- `applyUndo` (gameEngine.ts) now searches the event log for `HP_MOVE` during `HIGH_PASS_MOVE` and `FTP_MOVE` during `FIRST_TIME_PASS_MOVE`, instead of always searching for `MOVE` — fixing both the `lastMoveRelIdx` lookup and the `hasPriorMoves` fallback check
- `ActionPanel.tsx`'s `canUndo` computation mirrors the identical phase-aware mapping, so the Undo button now actually enables after a real reposition in FTP/HP phases
- De-masked two `gameEngine.phase17.test.ts` fixtures (`highPassMovementStateWithMove`, `ftpMoveStateWithMove`) and one `ActionPanel.test.tsx` fixture that had hand-fabricated `MOVE` events standing in for the real `HP_MOVE`/`FTP_MOVE` shapes gameHandlers.ts actually emits — these fabrications previously made the unit/component tests pass despite the runtime bug
- Added two new end-to-end wire tests in `game.integration.test.ts` that emit `GAME_UNDO` over a real Socket.io connection during `FIRST_TIME_PASS_MOVE` and `HIGH_PASS_MOVE` (seeded with real `FTP_REPOSITION`+`FTP_MOVE` / `HP_REPOSITION`+`HP_MOVE` events) and assert the moved piece is restored to its from-hex via the resulting `GAME_STATE` — proving the `gameHandlers.ts GAME_UNDO` handler → `applyUndo` path works end-to-end, not just in isolation

## Decisions Made

- Widened `applyUndo`'s `moveToUndo` cast to `Extract<ActionEvent, { type: 'MOVE' | 'HP_MOVE' | 'FTP_MOVE' }>` rather than introducing a separate code path per phase, since all three variants share the identical `pieceId`/`from`/`to` shape used by the downstream reversal logic — this matches the plan's explicit instruction to reuse the cast/reversal logic unchanged.
- Did not extract the phase-aware mapping into a shared `packages/shared` helper. Both the server and client sites are short, single-use expressions, and the plan scoped this fix as a one-line discriminant mirror, not a refactor; introducing a shared helper would be a larger structural change than CR-01 calls for.
