## Critical

### CR-01: `isGoal` hardcoded `false` on the `GOAL` ActionEvent branch

**File:** `packages/client/src/components/ActionLog.tsx:392`

The `GOAL` case in `formatEvent` returns `isGoal: false` (BUG-15 changed all three sites to `false` to remove amber styling). While the render ternary itself was also removed, the `isGoal` field is still part of the `Formatted` type. Any downstream consumer branching on `isGoal` will never fire. The change was intentional per the plan, but warrants review: if `isGoal` is now fully unreferenced after the render ternary change, remove the field entirely; otherwise restore `isGoal: true` on the `GOAL` case.

**Fix:** Confirm `isGoal` is fully unreferenced (grep the codebase) and either remove the field from `Formatted` or restore `isGoal: true` on the `GOAL` case.

### CR-02: Multi-tackle loop uses `state.ball.position` (stale) on FAIL path

**File:** `packages/server/src/gameEngine.ts:~716-718`

On the FAIL path of the BUG-13 additional-tackler loop, `addBallAfter` is `{ position: state.ball.position, carrierId: state.ball.carrierId }`. `state.ball.position` is the carrier's position **before** the move; the carrier has already been moved via `newPieces`. The event log records a stale hex for `ballAfter` on failed subsequent tackles, causing `buildReplayFrames` to show the ball at the wrong position during multi-tackler replay sequences.

**Fix:** Use `{ position: carrier.position, carrierId: carrier.id }` on the FAIL path (where `carrier` is the moved piece from `newPieces`).

---

### CR-03: `applyFreeKickReady` stage 3 — no guard when no kicker on `freeKickHex`

**File:** `packages/server/src/gameEngine.ts:~4037-4062`

When `stageIndex === 3` and no kicking-team piece occupies `freeKickHex`, `kicker` is `undefined` and the function falls back to `ball: state.ball` (carrierId: null), transitioning to `phase: 'PASS'` with a loose ball — a broken game state.

**Fix:** Return `{ ok: false, reason: 'WRONG_PHASE' }` when `kicker` is `undefined` at stage 3.

### CR-04: `ActionPanel.tsx` has no `FREE_KICK_SETUP` branch — active player sees blank panel

**File:** `packages/client/src/components/ActionPanel.tsx`

The active player during `FREE_KICK_SETUP` falls through all phase checks and returns `null`. No instructions or "Confirm Placement" button is shown, making the phase effectively unplayable without external guidance.

**Fix:** Add a `FREE_KICK_SETUP` branch rendering stage description, eligible pieces, and a "Confirm Placement" button emitting `end_turn`.

## Warnings

### WR-01: `applyFreeMove` emits `MOVE` events with `slot: 'ATTACKER_2'` — semantically wrong

**File:** `packages/server/src/gameEngine.ts:~358`

Free-move actions are not part of the 4-5-2 slot sequence. Hard-coding `slot: 'ATTACKER_2'` groups free-move steps under `[MOVE 2]` in the ActionLog's `consolidateEvents`, which is misleading.

**Fix:** Use a dedicated sentinel slot value or add an `isFreeMove: true` discriminant.

---

### WR-02: `buildReplayFrames` doesn't flush `moveGroup` before `KICK_OFF_SETUP` events

**File:** `packages/server/src/gameEngine.ts:~4291-4296`

If a `KICK_OFF_SETUP` event for piece X immediately follows a `MOVE` event for the same piece X, the step is appended to the existing `moveGroup` entry rather than treated as a new batch, causing both moves to animate together in replay.

**Fix:** Call `flushMoveGroup()` before accumulating `KICK_OFF_SETUP` events.

---

### WR-03: `applyHalfTimeStart` carries over `offsidePieceIds` from first half

**File:** `packages/server/src/gameEngine.ts:~4095-4130`

Returned state spreads `...state` without resetting `offsidePieceIds`. Players flagged offside at the whistle start the second half still flagged.

**Fix:** Add `offsidePieceIds: []` to the returned state.

---

### WR-04: `SNAPSHOT_DEFLECT` panel has no Undo button despite server-side support

**File:** `packages/client/src/components/ActionPanel.tsx:~223-242`

BUG-18 wired Undo server-side for `SNAPSHOT_DEFLECT` and `canUndo` correctly evaluates it, but the panel renders only "End Turn" with no Undo button. The fix is unreachable from the UI.

**Fix:** Add an Undo button to the `SNAPSHOT_DEFLECT` panel branch, mirroring the `HIGH_PASS_MOVE` pattern.

---

### WR-05: `applyUndo` in FREE_MOVE phases doesn't restore `freeMoveUsedPace`

**File:** `packages/server/src/gameEngine.ts:~1361-1373`

`applyUndo` reverses piece position and clears `movedPieceIds`, but `freeMoveUsedPace[pieceId]` is never decremented. Undone steps still count against the 6-hex budget.

**Fix:** Add a `FREE_MOVE_ATTACK | FREE_MOVE_DEFENSE` case to the `lockReset` block in `applyUndo` that decrements `freeMoveUsedPace[pieceId]` by 1 (clamped to 0).

---

### WR-06: `applyFreeMoveZoneCheck` missing `KICK_OFF_SETUP` guard

**File:** `packages/server/src/gameEngine.ts:~1128-1187`

Early-return guard list covers `HALF_TIME`, `FULL_TIME`, `FREE_MOVE_*`, and `MOVE`-with-slot, but not `KICK_OFF_SETUP`. A future coordinate change could expose a spurious free-move trigger.

**Fix:** Add `'KICK_OFF_SETUP'` to the early-return conditions.

---

### WR-07: `fmtStatRoll` renders `- 0` when penalty is zero — misleading display

**File:** `packages/client/src/components/ActionLog.tsx:~139-147`

Displays `Shooting 10 + 4 - 0 = 14` which is player-visible noise.

**Fix:** Omit the penalty term when `penalty === 0`:

```tsx
const penaltyPart = penalty !== 0 ? ` - ${Math.abs(penalty)}` : '';
```
