## What Was Built

### Task 1 — BUG-19: Jersey Number Source of Truth

**PieceOverlay.tsx:** Replaced the 7-line `idx`/`playerNumber` derivation block (using `piece.id.slice(piece.id.lastIndexOf('-'))` plus a `piece.role === 'ST' ? '9'` ternary for special cases) with a single statement:

```typescript
const playerNumber = String(piece.number);
```

This mirrors the D-08 pattern already established in `PlayerStatsPanel.tsx` (line 35). The `piece.number` field is the canonical CSV-seeded roster jersey number set during Phase 16.

**ActionLog.tsx:** Rewrote `pieceNum()` from a regex-on-id approach to a store lookup mirroring `pieceName()`:

```typescript
function pieceNum(pieceId: string): string {
  const pieces = useGameStore.getState().gameState.pieces;
  const piece = pieces.find((p) => p.id === pieceId);
  return piece !== undefined ? String(piece.number) : pieceId;
}
```

Fallback is the raw `pieceId` string (graceful degradation, matching `pieceName()`'s null-safe pattern).

### Task 2 — BUG-15: Remove Goal Amber Styling

Changed all three `isGoal: true`/`isGoal: event.outcome === 'GOAL'` assignment sites to `isGoal: false`:

- GOAL case (~line 386)
- SHOT_ATTEMPT snapshot-branch duel subKind (~line 485)
- SHOT_ATTEMPT regular-duel branch (~line 518)

Changed the render span from the conditional ternary to unconditional `.content`:

```tsx
// Before:
<span className={isGoal ? styles.goalContent : styles.content}>{content}</span>
// After:
<span className={styles.content}>{content}</span>
```

Also removed `isGoal` from the destructuring in the render loop (unused after ternary removal). Removed `.goalContent` class from `ActionLog.module.css` (no longer referenced).

### Task 2 — BUG-16: PNamed in FTP/HP Move Logs

Replaced `<P pieceId={...} prefix={team|ftpTeam} />` with `<PNamed pieceId={...} />` in both the `HP_MOVE` case and `FTP_MOVE` case:

```tsx
// Before HP_MOVE: <P pieceId={event.pieceId} prefix={team} /> where team = 'A'/'D'
// After:          <PNamed pieceId={event.pieceId} />

// Before FTP_MOVE: <P pieceId={event.pieceId} prefix={ftpTeam} /> where ftpTeam = 'A'/'D'
// After:           <PNamed pieceId={event.pieceId} />
```

`GK_KICK` and `GK_KICK_MOVE` use of `<P prefix="GK"/"K"/"O">` left untouched — those are legitimate role labels, not the redundant A/D pattern.
