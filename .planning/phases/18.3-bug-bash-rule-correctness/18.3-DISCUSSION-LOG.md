## BUG-14: Snapshot After Pace Exhaustion

| Option                                  | Description                                                                              | Selected |
| --------------------------------------- | ---------------------------------------------------------------------------------------- | -------- |
| Drop the `movedPieceIds` check entirely | Snapshot stays available all MOVE phase as long as carrier is in the penalty-area region |          |
| Allow only once pace is fully exhausted | Snapshot unavailable while carrier still has pace, available once pace hits 0            |          |

**User's choice:** Neither preset option — user gave a third, more precise design: keep the `movedPieceIds` check as the gating mechanism, but change WHEN the carrier is added to `movedPieceIds`. Don't flag the carrier as "activated" (added to `movedPieceIds`) purely because they exhausted pace on their own move step — defer that addition until the player selects and moves a _different_ piece next, mirroring the existing "abandoned piece" deferral pattern already used for pieces that stop moving without exhausting pace.
**Notes:** Investigated `gameEngine.ts`'s `computeMovedPieceIds`/`abandonedIds` mechanism (~lines 329-331, 453-463) to confirm this deferral pattern already exists for the "didn't use full pace, player moved on" case — it just doesn't yet apply to the "did use full pace" case. The fix closes that one remaining asymmetry.

## BUG-17: Kickoff-Setup Replay Visibility

**User's choice:** Replay needs to show all player positions resetting at kickoff after a score.
**Notes:** Root-caused to `GAME_KICK_OFF_MOVE` (`gameHandlers.ts`) pushing zero `ActionEvent`s to `eventLog` — confirmed no `KICK_OFF_SETUP`-related event type exists in `shared/src/types.ts`. ## BUG-18: Undo Scope

| Option                                           | Description                                                                                                 | Selected |
| ------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- | -------- |
| Coverage gap — extend to all move-bearing phases | Add Undo to GK_KICK_MOVE, SNAPSHOT_DEFLECT, FREE_MOVE_ATTACK/DEFENSE, HEADER repositioning, FREE_KICK_SETUP |          |
| Specific regression in an existing Undo phase    | User describes exact broken behavior in one of the 3 already-supported phases                               |          |

**User's choice:** Both, effectively — user clarified Undo is "never enabled in the move phase" (a regression in an already-"supported" phase), AND asked for consistent behavior "across all move actions" (the coverage-gap option).
**Notes:** Investigation found the regression: `ActionPanel.tsx`'s `canUndo` returns `false` whenever `lastDiceRoll` is truthy, and `gameEngine.ts`'s `applyStartMovement` (the dominant PASS/KICK_OFF/LOOSE_BALL → MOVE transition) never resets `lastDiceRoll: null` — unlike the GK_RESTART movement branch, which does. Since most possession changes route through a dice roll before reaching MOVE, this explains "never enabled." Confirmed `validUndoPhases` server-side only covers 3 of the many move-bearing phases. User explicitly flagged "consider replay impacts when fixing" — tied to the BUG-17 finding that some movement paths don't produce eventLog entries at all.
