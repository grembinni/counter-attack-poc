## Trust Boundaries

| Boundary                                           | Description                                                                                                                                                           | Data Crossing                            |
| -------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| client → `DRAFT_PICK` / `DRAFT_REARRANGE` handlers | Untrusted card id, destination slot/bench ref, and any implicit side claim cross here; server is sole authority on legality and state                                 | card id, destination ref                 |
| client → `LINEUP_CONFIRM` handler                  | Untrusted confirm signal crosses here; starting-order data is deliberately never read from the client payload                                                         | confirm signal only (payload ignored)    |
| reconnect handshake → private draft view           | A reconnecting socket (identified by session token / `socket.data.playerSlot`) triggers server-driven re-emission of draft state; must never leak the opponent's pack | own-side `DraftClientView` only          |
| server RNG → pack assignment & bench numbering     | Fairness-affecting randomness (pack-to-player shuffle, keeper safety, bench numbers) must be CSPRNG, not predictable                                                  | none (internal)                          |
| private view projection (`buildDraftView`)         | Choke point that must never serialize the opponent's pack/lineup/bench into either side's emitted view                                                                | own-side draft state only                |
| client render → user (carousels, drag gestures)    | `DraftPackCarousel`/`BenchCarousel` are pure display + drag sources; hold no authoritative state and validate nothing themselves                                      | server-supplied card data (display only) |
| client-only render state (bench scroll stability)  | `benchCards`/`benchKey` memoization is presentational only — no external input, no trust boundary                                                                     | none (internal React state)              |
