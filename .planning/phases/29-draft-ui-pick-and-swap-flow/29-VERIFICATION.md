## Gaps Summary

### Critical Gaps (Block Progress)

1. **Real-time WebSocket coordination integrity: 3 unresolved CRITICAL findings from 29-REVIEW.md, independently confirmed present in the current code**

   These are **pre-existing** (present before 29-10, not introduced by it) and were **explicitly out of scope** for 29-10's task list (which was scoped only to the `applyRearrange` slot-swap fix). They are included here because they directly bear on ROADMAP.md's Phase 29 Success Criteria #2 ("via real-time WebSocket coordination") and #5, and because Phase 29 is the last phase in the current v1.4 roadmap — there is no later phase to defer them to.
   - **CR-01 — `LINEUP_CONFIRM` (draft mode) never checks `draftSession.draftComplete`** (`roomHandlers.ts:690-738`, confirmed by direct read). A player can fill all 11 lineup slots by end of cycle 3 (12 cards drafted, guaranteed a keeper every pack) and confirm a full-but-mechanically-incomplete draft a full cycle early. If both players do this, the match starts with the draft unfinished.
   - **CR-02 — `DRAFT_PICK` never checks `room.gameState !== null` or requester-confirmed status** (`roomHandlers.ts:809-899`, confirmed by direct read), asymmetric with `DRAFT_REARRANGE`'s existing guard. Composes with CR-01: once a match starts with `draftComplete` still false, a player can keep emitting `DRAFT_PICK`, which mutates `draftSession` and broadcasts `DRAFT_STATE_UPDATED` to both sockets — pulling both players' clients off the live game board back onto the draft screen mid-match (via `App.tsx`'s unconditional `setScreen('LINEUP_ASSIGNMENT')`).
   - **CR-03 — reconnect sends no re-sync event during the "draft complete, not yet both-confirmed" window** (`createServer.ts:140-153`, confirmed by direct read). This is a plain network-hiccup scenario (not adversarial): a player who disconnects after finishing their draft but before both players have confirmed gets no `GAME_STATE` (gameState is still null) and no `DRAFT_STATE_UPDATED` (guard excludes this window) on reconnect — stranded on the wrong screen. This directly contradicts the CLAUDE.md-documented Socket.io reconnection-with-state-recovery architecture value.
   - **No test coverage exists for any of the three** (WR-02 in 29-REVIEW.md, confirmed) — every integration test that reaches `LINEUP_CONFIRM` in draft mode first drives `draftComplete` to true, and both reconnect tests disconnect while still mid-draft.
   - **Fix:** see the three code snippets in `29-REVIEW.md`'s CR-01/CR-02/CR-03 sections (already-drafted, minimal, guard-only fixes mirroring `DRAFT_REARRANGE`'s existing pattern) — recommend a new gap-closure plan (e.g. `29-11`) scoped to exactly these three guards plus the regression tests WR-02 recommends.
