## Gaps Summary

### Critical Gaps (Block Progress)

1. **Bench carousel scroll instability during drag (DRAFT-09 / roadmap SC #4) — NEW, in-scope, confirmed by direct code read**

   `LineupAssignmentScreen.tsx`'s `benchCards` array is recomputed via `.map()/.filter()` on every render with no memoization, so it gets a new object reference on every render of the parent regardless of whether the bench actually changed. `BenchCarousel`'s scroll-reset `useEffect` depends on that reference (`[cards]`), so it fires far more often than intended — confirmed to include every native `dragover` tick while a user drags any card over any lineup slot (`handleDraftSlotDragOver` calls `setDraftDropTargetIndex` unconditionally on every tick). The bench carousel's scroll position snaps back to the leftmost card mid-drag and on other incidental re-renders. This directly undermines the "dynamically-sized bench carousel" deliverable (D-21, DRAFT-09) whenever the bench holds enough cards to require scrolling — exactly the scenario this phase's own bench-carousel rework (29-08) was built to handle.
   - **Fix:** `useMemo(() => draftView.benchIds.map(resolveTieredCard).filter(...), [draftView.benchIds, cardCache])` in `LineupAssignmentScreen.tsx`, or change `BenchCarousel`'s effect dependency to a content-derived key.
   - **Test:** add a regression test asserting the scroll-reset effect does not fire on an unrelated re-render but does fire on a genuine bench-content change.
