## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage                                                                        |
| ----- | ----- | ---------------------------------------------------------------------------- |
| xs    | 4px   | Icon/glyph gaps, stat-chip row gaps (`row-gap: 3-4px` rounds to this bucket) |
| sm    | 8px   | Card internal gaps, column gaps, carousel card-to-card gap                   |
| md    | 16px  | Section gaps, formation-column gaps, carousel row padding                    |
| lg    | 24px  | Screen outer padding (`.screen` padding)                                     |
| xl    | 32px  | Reserved — no new usage this phase beyond existing screens                   |
| 2xl   | 48px  | Reserved — matches existing `confirmButtonGreen` horizontal padding bucket   |
| 3xl   | 64px  | Reserved — not used this phase                                               |

Exceptions (carried over verbatim from `LineupAssignmentScreen.module.css` / `UniformSelectionScreen` for visual parity — do not invent new off-scale values beyond these):

- Card internal padding `6px 8px` (existing `.statCardBase` — the draft-pack and bench cards reuse this exact card shape per D-18/D-21, so the 6px exception carries over unchanged)
- Confirm button padding `14px 48px` (existing `.confirmButtonGreen` — unchanged, reused as-is once draft completes and the existing Confirm flow takes over)
- Carousel nav-arrow hit target: 32px square minimum (touch-target floor; not on the 8pt scale by design, matches the "icon-only touch target" exception class called out in spacing guidance)

## Typography

Sizes and weights match the existing bold, chunky sports-UI aesthetic already established across every prior setup screen (`LineupAssignmentScreen`, `UniformSelectionScreen`, `TeamSelectionScreen`, `GameSettingsScreen`) — no lighter/regular (400) weight exists anywhere in the client; do not introduce one for this phase.

| Role                                                                                | Size | Weight | Line Height |
| ----------------------------------------------------------------------------------- | ---- | ------ | ----------- |
| Micro (badges, stat abbreviations)                                                  | 9px  | 700    | 1.2         |
| Body / Label (card name, role, stat chips, cycle/pick counters)                     | 12px | 700    | 1.4         |
| Subheading (status lines: "waiting for opponent", pick prompts, rejection messages) | 14px | 700    | 1.4         |
| Heading (screen title: "MATCH SETUP: STEP 4 — DRAFT")                               | 22px | 800    | 1.2         |

Only two weights in use project-wide: **700** (default for nearly all text) and **800** (screen headings only). Do not add a 600 or 900 weight.

Card rarity is communicated by a colored border/frame around the whole card (D-19), not a corner badge or icon (per D-18: card content itself is unchanged).

| Tier     | Border Color | Notes                                                                                                                                          |
| -------- | ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| Chase    | `#f5c518`    | Reuses the existing accent gold — do not introduce a separate "chase gold" hex                                                                 |

| Uncommon | `#cd7f32`    | Bronze — new token, this phase only                                                                                                            |

## Component Notes for Executor (non-template, supplementary)

These are not part of the standard template sections but are load-bearing for implementation consistency — kept here rather than omitted, since the checker/executor need them and no other artifact captures them.

1. **Draft-pack carousel** (new component, D-20): standard left-right navigable carousel, generic over pack size (must render correctly for both a 7-card pack and the 6-card keeper-safety pack in cycle 4 — do not hardcode a 7-slot grid). Sorts rarest-first (Chase → Rare → Uncommon → Common → Keeper) and resets scroll position to the leftmost card every time a new pack loads. Cards use the exact `LineupStatCard` visual base (D-18) plus the new tier border (D-19).
2. **Bench carousel** (D-21): identical carousel card style to the draft-pack row, positioned below the main lineup grid, replacing the existing structural-only dashed placeholders (`.benchPlaceholders`/`.benchSlot`) with real card data once drafting begins. Dynamically sized — grows as more cards are benched, no fixed slot count (D-09 requirement).
3. **Drag-and-drop**: reuse `LineupAssignmentScreen.tsx`'s existing `handleDragStart`/`handleDragOver`/`handleDrop`/`handleDragEnd` pattern verbatim for lineup↔bench rearrangement (D-08). Extend (do not fork) that pattern for row→lineup and row→bench picks (D-05/D-06), enforcing the one-way constraint: cards leaving the draft-pack row can never be dragged back into it (D-06).
4. **GK slot lock**: existing GK-slot-is-never-a-drop-target-for-non-GK logic (`handleDragOver` early-return on `idx === 0`) must be extended to the reverse case too — a GK card must also be blocked from every non-GK slot (D-09, new rule this phase adds; the existing code only blocks the "wrong card type onto GK slot" direction, not "GK card onto wrong slot").
5. **Keeper auto-placement** (Claude's discretion, resolved): auto-selected keeper (DRAFT-08 cycle-4 safety net) is auto-placed directly into the GK slot if it is still empty; otherwise it lands on the bench. This is the more polished default per CONTEXT.md's discretion note — implement this behavior, do not prompt the player to place it manually.
