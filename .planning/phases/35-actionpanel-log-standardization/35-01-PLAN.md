<objective>
Create the single shared CTA color-state helper required by D-06, delete the unreachable
`FREE_KICK_SETUP` block from `ActionPanel.tsx` (also D-06), and propagate dynamic
orange→green color state to every ActionPanel phase that tracks an eligible-remaining
count (D-02).

Purpose: PANEL-03 demands one color-state logic shared across every button in the
ActionPanel render slot (D-05 component set). Today `ctaButtonClass` is a private function
inside `ActionPanel.tsx` used by only 2 of 8 phases, and `FreeKickSetupPanel.tsx` has a
second, divergent implementation (`endTurnColorClass`). This plan establishes the single
implementation and makes ActionPanel a consumer of it. `FreeKickSetupPanel` is converted to
the same helper in plan 35-03.

Output: new `packages/client/src/utils/ctaColorClass.ts` + unit tests; `ActionPanel.tsx`
with all 7 CTA buttons driven by the shared helper and ~70 lines of dead FREE_KICK_SETUP
code removed.

    `export function ctaColorClass(eligibleRemaining: number, classes: { ready: string | undefined; pending: string | undefined }, enabled = true): string`

    Behavior contract (implements D-06 and preserves both existing implementations exactly):
    - When `enabled === false`, return `''` — no color class at all. This reproduces
      `FreeKickSetupPanel.tsx`'s `constraintsMet ? … : ''` branch, whose purpose is that a
      constraint-blocked (disabled) button must show neither ready-green nor pending-orange.
    - When `eligibleRemaining <= 0`, return `classes.ready ?? ''`.
    - Otherwise return `classes.pending ?? ''`.

    The function takes the CSS-module class-name strings as parameters rather than importing
    a CSS module, because it is consumed by two components that each own their own CSS
    module (`ActionPanel.module.css` and `FreeKickSetupPanel.module.css` both define
    `ctaButtonReady`/`ctaButtonPending`). Do NOT import any `.module.css` file, any React
    symbol, or `useGameStore` into this file — it must stay callable from anywhere,
    including non-component helpers, matching `teamAccentColor`'s stated guarantee.

    Add a file-header docblock stating: the D-06 origin (single color-state logic shared by
    `ActionPanel` and `FreeKickSetupPanel`, replacing two divergent implementations); that
    `?? ''` guards exist because CSS-module typings surface classes as
    `string | undefined`; and that `enabled=false` deliberately yields no class.

    Create `packages/client/src/utils/ctaColorClass.test.ts` with a `describe('ctaColorClass')`
    covering exactly these cases using a fixed stub `{ ready: 'READY', pending: 'PENDING' }`:
    1. `eligibleRemaining` of `3` returns `'PENDING'`.
    2. `eligibleRemaining` of `0` returns `'READY'`.
    3. A negative `eligibleRemaining` (`-1`) returns `'READY'` (the `<= 0` boundary).
    4. `enabled` of `false` returns `''` even when `eligibleRemaining` is `0`.
    5. `enabled` of `false` returns `''` when `eligibleRemaining` is `3`.
    6. `{ ready: undefined, pending: undefined }` returns `''` for both a `0` and a `3`
       remaining count (the `?? ''` fallback).
