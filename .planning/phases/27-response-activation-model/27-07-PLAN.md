<objective>
Build the FINAL_THIRD_RESPONSE movement mechanic itself (D-04/D-13/D-21): per-piece pace
budget, undo-friendly event logging, sequential attacker-then-defender sub-phases. This plan
does NOT build the zone-crossing entry trigger or the keeper auto-reposition (Plan 27-08) —
it only builds the phase's internal movement engine, exactly mirroring
`applyFreeMove`/`applyFreeMoveEnd`'s SHAPE while being a genuinely separate function with
OPPOSITE eligibility direction (research Anti-Pattern: do not extend `applyFreeMoveZoneCheck`
in place — this plan creates parallel, independent code).

Purpose: isolate "how a final-third response move works" from "when it starts" so each
concern gets its own focused plan and its own test surface.
Output: `applyFinalThirdMove`/`applyFinalThirdEnd` + their `GAME_MOVE`/`GAME_END_TURN`
handler branches, exercised via hand-constructed states that already have
`finalThirdEligibleIds` populated (Plan 27-08 wires the real trigger).
</objective>
