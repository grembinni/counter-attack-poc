<objective>
Build the genuinely-new sequential attacker-then-defender single-selection positioning
pre-step for HEADER (D-02). This is NOT a retrofit of the existing `GAME_HEADER_CONTESTANT`
multi-select simultaneous-nomination handler (research Pitfall 3: that handler accepts
`string[]`, both teams act simultaneously, no movement) — it is new sequencing state and a
new `GAME_MOVE` branch inserted AHEAD of the untouched contestant/duel/target flow.

Purpose: per D-02, once both sides have positioned exactly one contestant, the EXISTING
`GAME_HEADER_CONTESTANT`/`computeHeaderDuelDetail`/`GAME_HEADER_TARGET` machinery must fire
unmodified. This plan achieves that by extracting the "both confirmed → fire duel" block
(currently inline in `GAME_HEADER_CONTESTANT`) into a shared, behavior-preserving helper
callable from both the old entry point (still reachable, now effectively dead in normal
play but kept working) and the new positioning-complete path.
Output: server-side HEADER positioning turn engine + handler branch. Client wiring is
Plan 27-06.
</objective>
