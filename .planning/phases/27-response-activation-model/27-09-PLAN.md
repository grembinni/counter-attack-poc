<box_vs_final_third_precedence>
Penalty area is a strict SUBSET of its side's final third (`homePenaltyArea` q∈[0,5] ⊂
`homeThird` q∈[0,10]). A ball movement that lands directly in the box, skipping the outer
part of the third, is simultaneously a fresh crossing for BOTH the final-third trigger and
the box trigger. This plan's resolution (documented, not silently assumed): GK_BALL_IN_BOX
takes priority and "consumes" the crossing for that action — the keeper snap (D-15, always
unconditional) still fires first, THEN the box trigger overlays `GK_BALL_IN_BOX` instead of
`FINAL_THIRD_RESPONSE`. `FINAL_THIRD_RESPONSE` for the OTHER eligible pieces in that third is
skipped for that specific action (their zone-crossing opportunity was "used" by the box
interrupt) — a plain "ball already in the third" state persists, so a later action that keeps
the ball in the same third without re-crossing will not retroactively grant them one. This is
a defensible minimal-risk simplification given neither CONTEXT.md nor RESEARCH.md specifies
the interaction; flag to the user if a specific ordering was intended.
</box_vs_final_third_precedence>
