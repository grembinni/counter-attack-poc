<objective>
Build Corner Kick's two repositioning windows: CORNER-03's alternating strict-pairs 6-hex window
(the single most novel design surface in this phase) and CORNER-06's pre-kick one-piece-per-team
3-hex window.

Both windows use Corner Kick's own dedicated phase values and `cornerKick*` state per D-07/D-08 —
only pure helpers are shared with Goal Kick, never phases or fields.

Purpose: CORNER-03 has no single existing precedent — it fuses `FREE_KICK_STAGES`'s
alternating-sides/max-distinct-pieces-per-stage structure with `applyGoalKickReposition`'s
per-piece cumulative hex budget. Neither pattern alone satisfies D-05. CORNER-06 by contrast is a
direct field-shape copy of `GOAL_KICK_MOVE`'s slot alternation.

Output: 5 new pure engine functions with unit coverage, including explicit tests for the
Pitfall-4 rule that the per-piece pace ledger must NOT reset between stages.
</objective>

## Trust Boundaries

| Boundary                 | Description                                                                                                                                                                                |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| handler → engine         | `pieceId`, `to` and the confirming team all originate client-side. These engine functions are the authoritative budget/turn-order enforcement point.                                       |
| stage state → turn order | Whose turn it is must be derived from `cornerKickStageIndex`/`cornerKickMoveSlot` + `cornerKickTeam`, never from a client claim and never from the mutable `activeTeam` convenience field. |
