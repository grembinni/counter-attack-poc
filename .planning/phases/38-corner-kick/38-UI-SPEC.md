# Phase 38 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Design System

| Property          | Value                                                                                                                                                                                                                   |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tool              | none                                                                                                                                                                                                                    |
| Preset            | not applicable                                                                                                                                                                                                          |
| Component library | none — hand-rolled React function components + CSS Modules (no headless-UI/Radix layer anywhere in the codebase)                                                                                                        |
| Icon library      | none — text glyphs / HTML entities only (e.g. `&hellip;`); no icon font or SVG icon set                                                                                                                                 |
| Font              | `system-ui, -apple-system, BlinkMacSystemFont, 'Segoe UI', sans-serif` (`App.module.css`, app-wide default). Monospace font is reserved for scoreboard/clock digit displays only — not used by this phase's new panels. |

**shadcn gate note:** `components.json` was not found and this is a React + Vite project, which would normally trigger the shadcn init prompt. This project is 37 phases into an established hand-rolled design system (CSS Modules + `tokens.css` custom properties, formalized in Phase 33 THEME-03, documented in `docs/HIGHLIGHT-REFERENCE.md`). Phase 37 already made this same call for Goal Kick/Throw-In and it holds identically here — introducing shadcn mid-project would fork the component architecture against 37 phases of precedent. Decision: **Tool: none** — this phase extends the existing system, not a new one.

**Component reuse for this phase** (per CONTEXT.md D-09 and RESEARCH.md's Recommended Project Structure): the new `CornerKickSetupPanel.tsx` should structurally mirror `packages/client/src/components/GoalKickSetupPanel.tsx` — one panel component, branching internally by `phase`, covering all of Corner Kick's new phases the same way `GoalKickSetupPanel` covers Goal Kick's five. `FreeKickSetupPanel.tsx`'s alternating-stage UI (`FREE_KICK_STAGES` display, the "N left" constraint row, the soft `withEndTurnGuard`/`pendingEndTurn` confirm dialog) is the closer structural analog specifically for CORNER-03's alternating-pairs window, since it is the only existing panel that already renders a multi-round alternating-side reposition sequence. No new game-creation toggle work is needed this phase — GOALKICK-06/OOB-05's existing "Out-of-Bounds / Restarts" toggle (shipped Phase 37) already covers corner kick per its own requirement text; `GameSettingsScreen.tsx` is untouched by this phase.

**Visual hierarchy for this phase:** the primary visual anchor for every one of Corner Kick's new panel states is the state-colored CTA button (`--color-cta-ready-bg` green when the current step's constraint is satisfied, `--color-cta-pending-bg` orange when not) — identical focal-point convention to `FreeKickSetupPanel`/`GoalKickSetupPanel`. The High-Pass/Low-Pass choice buttons (mirrors Goal Kick's Kick/Standard-Pass pair) are co-equal, un-colored (`.ctaButton` default), differentiated only by label and `title` tooltip — no color-coding one option as "preferred," matching the existing Kick-vs-Standard-Pass precedent exactly.

**Highlight/tint mapping for this phase** (D-09 — reuse only, no new `HexHighlightType` members added to `HIGHLIGHT-REFERENCE.md`):

| Corner Kick moment                                                   | Reused tint/ring                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GK reposition destination hexes (CORNER-01)                          | `safe` (valid placement) — same green semantic as any valid-move highlight                                                                                                                                                                                               |
| Fixed corner-taker hex (CORNER-02)                                   | `ring="required"` gold ring (mirrors kick-off's "must place kicker here" marker) on the single fixed hex                                                                                                                                                                 |
| Alternating 6-hex reposition destinations (CORNER-03)                | `safe` for the currently-selected piece's reachable hexes, exactly like Goal Kick's/Free Kick's reposition windows                                                                                                                                                       |
| Pre-kick 3-hex window destinations (CORNER-06)                       | `safe`, direct copy of `GOAL_KICK_MOVE`'s reposition-destination tinting                                                                                                                                                                                                 |
| High Pass corner target (any hex, unlimited in-box / ≤15 elsewhere)  | `pass-target` for the eligible teammate-head targets                                                                                                                                                                                                                     |
| Header-contest zone preview once a High Pass corner target is chosen | `shot-path` / `shot-path-action` (upgrading where also a valid response-move destination) + `HeaderTargetRing`'s gold bullseye at the target hex — direct reuse of the Plan 37-19/37-18 `GOAL_KICK_MOVE` pattern, extended to Corner Kick's equivalent post-target phase |
| Ball location during every new Corner Kick phase                     | `BallLocationRing`'s white hex-edge marker — `BALL_MARKER_PHASES` must be extended with Corner Kick's new phase values (implementation detail, flagged here since it is the same UI marker Phase 37 extended for Goal Kick/Throw-In)                                     |

Declared values (must be multiples of 4):

| Token | Value | Usage                                                                                                                      |
| ----- | ----- | -------------------------------------------------------------------------------------------------------------------------- |
| xs    | 4px   | Icon/glyph gaps, tight inline padding — the new `CornerKickSetupPanel`'s internal spacing (`gap: 4px`, `padding: 4px 8px`) |
| sm    | 8px   | Compact row/section gaps (constraint-row gaps, button gaps)                                                                |
| md    | 16px  | Default element spacing                                                                                                    |
| lg    | 24px  | Section-level padding (not directly used by this phase's new panel, listed for completeness)                               |
| xl    | 32px  | Not used by this phase's new components                                                                                    |
| 2xl   | 48px  | Not used by this phase's new components                                                                                    |
| 3xl   | 64px  | Not used by this phase's new components                                                                                    |

Exceptions: none. Per Phase 37's explicit correction, the legacy 3px/6px micro-scale found in `FreeKickSetupPanel`/`KickOffSetupPanel` is **not** to be propagated. `CornerKickSetupPanel.tsx` uses the standard `xs` token (`gap: 4px`, `padding: 4px 8px`) throughout, fully 4-multiple-compliant.

## Typography

| Role    | Size | Weight | Line Height |
| ------- | ---- | ------ | ----------- |
| Body    | 13px | 400    | 1.5         |
| Label   | 11px | 400    | 1.5         |
| Heading | 12px | 700    | 1.2         |
| Display | 20px | 700    | 1.2         |

Only two weights are used app-wide: 400 (regular) and 700 (bold/emphasis) — no intermediate weights (500/600) exist in the codebase. Do not introduce one for this phase.

Role mapping for this phase's new components:

- **Heading (12px/700)** — `CornerKickSetupPanel`'s panel title, `"Corner Kick"`, rendered identically across all of this phase's sub-phases (mirrors `GoalKickSetupPanel`'s single unchanging `"Goal Kick"` heading across its five sub-phases).
- **Label (11px/400/1.5)** — constraint/status rows inside the panel (`.constraintRow`), error text (`.errorText`, `--color-danger`), CTA/choice button text.
- **Body (13px/400/1.5)** — not directly used by this phase's new components (no settings-screen or list-view surface touched).
- **Display (20px/700/1.2)** — not used by this phase; listed for completeness only.

## Color

| Role            | Value                                                                                                                                 | Usage                                                                            |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Dominant (60%)  | `#121212` (`--color-bg-page`)                                                                                                         | Page background behind the board                                                 |
| Secondary (30%) | `#1c1c1c` (`--color-bg-surface`) / `#262626` (`--color-bg-surface-alt`)                                                               | `CornerKickSetupPanel`'s container background                                    |
| Accent (10%)    | `#27ae60` / `#f39c12` (`--color-cta-ready-bg` / `--color-cta-pending-bg`), `--team-accent` (`#b08b08` fallback, runtime team-derived) | See "Accent reserved for" below                                                  |
| Destructive     | `#ef4444` (`--color-danger`)                                                                                                          | Inline validation/error text only — no destructive _actions_ exist in this phase |

Accent reserved for:

- `--color-cta-ready-bg` (green) / `--color-cta-pending-bg` (orange) — `CornerKickSetupPanel`'s primary Confirm button background across the GK reposition, alternating-window, and pre-kick windows, state-derived from whether the current step's constraint is met (mirrors `GoalKickSetupPanel`'s `ctaColorClass` pattern exactly). The High Pass / Low Pass choice buttons and the corner-taker piece-selection interaction are **not** color-coded — they use the default `.ctaButton` styling, same as Goal Kick's Kick/Standard-Pass pair.
- `--team-accent` — CTA button hover state only, consistent with every existing sidebar panel.
- The existing hex-tint/ring highlight system (`docs/HIGHLIGHT-REFERENCE.md`) governs all in-pitch highlighting for this phase (see Design System's highlight-mapping table above). Out of scope for this 60/30/10 chrome-color split; governed separately by `HexCell.tsx`/`PieceOverlay.tsx`/`BallLocationRing.tsx`/`HeaderTargetRing.tsx`.

## Copywriting Contract

| Element                                                  | Copy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Panel heading (all sub-phases)                           | `"Corner Kick"` — unchanging across every one of this phase's new phases, mirrors `GoalKickSetupPanel`'s single unchanging `"Goal Kick"` heading.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| GK reposition constraint row (CORNER-01)                 | `"Goalkeeper: choose a new position, then Confirm."` — no "up to N hexes" qualifier, matching RESEARCH.md's Assumption A1 (uncapped placement, unlike CORNER-03/06's explicit hex caps). If planning confirms A1 is wrong and a cap applies, this copy must be revised to state the cap explicitly (mirrors CORNER-03/06's phrasing pattern below).                                                                                                                                                                                                                                                                                                          |
| GK reposition waiting-state (non-active player)          | `"{Attacking/Defending} team is repositioning…"` — verbatim reuse of the Phase 35/37 locked convention.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Corner-taker selection constraint row (CORNER-02)        | `"Choose a player to take the corner kick."` — the kicking manager clicks any own on-pitch piece; it teleports to the fixed corner hex on confirm (mirrors the Throw-In placement's one-shot model). No distance/count qualifier since this is a single-piece pick, not a budgeted reposition.                                                                                                                                                                                                                                                                                                                                                               |
| Corner-taker selection waiting-state                     | `"{Team} is choosing a corner-taker…"`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Alternating reposition window constraint row (CORNER-03) | `"{N} players still eligible to move this round — up to 2, unlimited distance."` plus a second row `"A player who has been repositioned is done for this window."` — CORRECTED in gap-closure plan 38-18 (38-15 defect 1): the original per-piece hex-count cap this row previously advertised was a bug, not a rule — CORNER-03 reposition movement is uncapped; the real per-window limit is that a piece may be activated (moved) exactly once, which is what makes "up to 6 players" mean six DISTINCT players per side (D-GAP-03).                                                                                                                      |
| Alternating 6-hex window waiting-state                   | `"{Team} is repositioning…"` — same locked convention, shown to the non-acting side during each round.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Pre-kick 3-hex window constraint row (CORNER-06)         | `"Reposition 1 player — up to 3 hexes."` — mirrors `GOAL_KICK_MOVE`'s equivalent constraint phrasing exactly (same 1-piece/≤3-hex shape, different trigger timing per RESEARCH.md §5.4).                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Pre-kick 3-hex window waiting-state                      | `"{Team} is repositioning…"`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Primary CTA (every reposition/window Confirm)            | `"Confirm"` — locked convention from Phase 35 (CONTEXT.md D-09), used identically across every one of this phase's reposition/window steps, same as Free Kick/Goal Kick/Throw-In.                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Primary CTA (High/Low Pass choice, CORNER-04/05)         | Two co-equal buttons: `"High Pass"` / `"Low Pass"` — mirrors Goal Kick's `"Kick"` / `"Standard Pass"` button pair exactly (same panel shape, same un-colored default styling). Tooltips: High Pass — `"High Pass — any hex in the penalty area with no distance limit, elsewhere up to 15 hexes; needs a combined score of 8 or more; receiver must attempt a header"`. Low Pass — `"Low Pass — needs a combined score of 8 or more; no header required"`.                                                                                                                                                                                                   |
| Empty state                                              | Not applicable — this phase adds no list or data-collection view; every new panel state always renders active game state (a reposition window, a piece/pass choice) with no zero-item condition.                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| Error state                                              | Inline `.errorText`/`.constraintRow` red text (`--color-danger`), stating the specific unmet constraint plus the concrete next action — mirrors `FreeKickSetupPanel`/`GoalKickSetupPanel`'s existing pattern exactly, e.g. `"Corner-taker: select a player at the fixed corner hex first — required before any other move."` No modal/toast for validation errors; always inline, paired with a disabled CTA + matching `title` tooltip. Server-rejected actions (`gameError` from the store) render via the same `.errorText` row.                                                                                                                          |
| Destructive confirmation                                 | None in this phase — no delete/discard/irreversible actions are introduced. Reuse the existing **soft** "pieces remaining" guard (`withEndTurnConfirm`/`pendingEndTurn`) for the alternating 6-hex window and the pre-kick 3-hex window if a manager tries to Confirm with eligible pieces still unmoved: `"{N} players left to reposition, are you sure you want to end your turn?"` with `"Cancel"` / `"Yes, end turn"` buttons — non-destructive dialog styling (`.confirmOverlay`/`.confirmCard`), not danger-styled. This directly resolves CONTEXT.md D-06's discretion: early-confirm-with-0-moves is allowed, following Goal Kick's pattern exactly. |
| New settings toggle                                      | Not applicable — no new toggle this phase. `"Out-of-Bounds / Restarts"` (shipped Phase 37) already covers corner kick per GOALKICK-06/OOB-05.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
