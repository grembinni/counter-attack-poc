<objective>
Expose the whole Corner Kick chain over Socket.io: two new handlers for the goalkeeper-placement
and corner-taker steps, corner branches inside the existing `GAME_MOVE` and `GAME_END_TURN`
handlers for both reposition windows, the penalty-area-conditional range override for a High Pass
corner, and every `GamePhase`-keyed registration list on the server side.

Handlers address Corner Kick's own dedicated phases per D-07/D-08; the CORNER-03/CORNER-06
windows reuse the existing `game:move`/`game:end-turn` events, and D-06 allows confirming a
window with zero moves made.

Purpose: the engine work in 38-02..38-04 is unreachable until the socket surface exists. This plan
is also where the STATE.md-documented "new GamePhase values are invisible unless registered in
every consuming list" bug class is defended against on the server.

Output: a complete, mutex-protected, team-guarded server socket surface for Corner Kick, with
handler-level tests.
</objective>

## Trust Boundaries

| Boundary                | Description                                                                                                                                                                                          |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| client socket → handler | Every payload in this plan (`pieceId`, `to`, `passType`, `targetHex`) is fully attacker-controlled. Handlers are the first validation layer; the pure engine functions are the authoritative second. |
| socket identity → team  | `socketTeam(socket)` is the only trusted source of which team a connection controls. No handler may accept a team from the payload.                                                                  |
