## Spacing Scale

Declared values (multiples of 4):

| Token      | Value | Usage                                                                         |
| ---------- | ----- | ----------------------------------------------------------------------------- |
| xs         | 4px   | MiniTokenBadge gap to header text; playerMeta item gaps                       |
| sm         | 8px   | Column card stack gap; stat row gap between cards; jersey badge inner padding |
| card-inner | 12px  | Card inner padding for LineupStatCard                                         |
| md         | 16px  | Screen column gap; screen horizontal padding                                  |
| lg         | 24px  | Screen vertical padding (top/bottom); bench row top margin                    |
| xl         | 32px  | Not used in this phase                                                        |
| 2xl        | 48px  | Not used in this phase                                                        |
| 3xl        | 64px  | Not used in this phase                                                        |

Exceptions:

- `card-inner` (12px): Used as the `padding` value on `.statCard`. Sits between the 8px and 16px standard tokens; 8px is too cramped for the 9-stat layout and 16px wastes horizontal space in a screen that must fit 11 cards side by side.
- Stat row internal gap: 4px (override to 4px in LineupStatCard — do NOT inherit 3px from `PlayerStatsPanel.module.css`)
- Column header vertical padding: 4px top/bottom (8px combined — tighter than md to keep column header compact)
- Drag-over border width: 2px (not a spacing token — a visual state override)


### Column slot count by formation

| Formation | GK  | DEF | MID | FWD |
| --------- | --- | --- | --- | --- |
| 4-4-2     | 1   | 4   | 4   | 2   |

## Interaction Contract

### Drag-and-Drop States

| User Action                                  | Visual Change                                                                         | Data Change                                                             |
| -------------------------------------------- | ------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Mouse down on outfield card                  | `cursor: grabbing` on card                                                            | `draggable` attr is on element                                          |
| Drag starts (`onDragStart`)                  | Card opacity drops to 0.5; `dataTransfer.setData('slotIndex', index)`                 | Store source slot index in drag event                                   |
| Drag over valid outfield card (`onDragOver`) | Target card border becomes 2px `#f5c518`; box-shadow `0 0 0 2px rgba(245,197,24,0.3)` | `event.preventDefault()` to allow drop                                  |
| Drag over GK card                            | No drop-target highlight (GK not a valid drop target)                                 | `event.preventDefault()` NOT called — browser shows no-drop cursor      |
| Drag leave (`onDragLeave`)                   | Target card returns to default border                                                 | None                                                                    |
| Drop on outfield card (`onDrop`)             | Cards remain in current visual positions until server responds                        | Emit `LINEUP_SWAP { slotIndexA: sourceIndex, slotIndexB: targetIndex }` |
| `LINEUP_ASSIGNMENT_UPDATED` received         | All cards re-render from new `PlayerId[]` order; drop-target style cleared            | Update local assignment state from server payload                       |
| Drop rejected (server returns error)         | Swap rejection message appears below status line; auto-clears after 2000ms            | No assignment update                                                    |
| GK drag attempt                              | No visual feedback; `draggable` attribute absent on GK card                           | No event fires                                                          |

### Confirmation States

| State                                    | Card appearance                                                                                    | Button                                            |
| ---------------------------------------- | -------------------------------------------------------------------------------------------------- | ------------------------------------------------- |
| Active (not yet confirmed)               | Outfield cards: `cursor: grab`, full opacity; GK: `opacity: 0.7, cursor: default`                  | Green "Confirm Lineup" button, enabled            |
| Post-confirm (this player confirmed)     | All outfield: `.statCardConfirmed` (opacity 0.85, cursor default); GK: unchanged `.statCardLocked` | Button hidden (removed from DOM after confirm)    |
| Waiting (other player not yet confirmed) | Same as post-confirm                                                                               | No button visible; status line shows waiting copy |
| Both confirmed                           | Screen transitions to `GAME_BOARD`                                                                 | Not applicable                                    |

### Swap Rejection Message

Element: `<p className={styles.swapRejection}>` — rendered conditionally.

Copy: "Swap rejected — GK cannot be moved."

Style:

```
font-size: 12px;
font-weight: 700;
color: #ef4444;
text-align: center;
margin: 0;
```

Lifecycle: Appears immediately when server sends rejection; component sets a `setTimeout(() => setRejectionMessage(null), 2000)` — cleared automatically. No user action required.

| Element                | Copy                                                                                               |
| ---------------------- | -------------------------------------------------------------------------------------------------- |
| Screen heading         | `MATCH SETUP: STEP 3 — {HOME\|VISITOR} PLAYER ({YOU\|OPPONENT})`                                   |
| Active status          | `Make your selections now!`                                                                        |
| Waiting status         | `Waiting for {Home\|Visitor} Player to Lock in their Selection.`                                   |
| Primary CTA            | `Confirm Lineup`                                                                                   |
| Column header GK       | `GK`                                                                                               |
| Column header DEF      | `DEF`                                                                                              |
| Column header MID      | `MID`                                                                                              |
| Column header FWD      | `FWD`                                                                                              |
| GK card locked badge   | `LOCKED`                                                                                           |
| Bench section label    | `BENCH`                                                                                            |
| Swap rejection         | `Swap rejected — GK cannot be moved.`                                                              |
| Bench slot (empty)     | _(no copy — empty placeholder visual only)_                                                        |
| No empty state         | _(screen only renders after server sends complete 11-player assignment — no empty state possible)_ |
| No destructive actions | _(none in this phase)_                                                                             |

Heading step logic:

- Step number is always 3 for both players (the combined team+uniform+formation screen was Step 1 for home and Step 2 for visitor; lineup is Step 3 for both).
- `currentPlayerLabel` = "HOME" for player slot 1; "VISITOR" for player slot 2.
- `youOrOpponent` = "YOU" when the current player's slot matches `playerSlot`; "OPPONENT" otherwise.
- Since both players act in parallel on lineup, both see "YOU" — the opponent label only appears if lineup could be shown from the opponent's perspective, which it cannot (CONTEXT.md D-16).

Active/waiting copy strings are verbatim from `UniformSelectionScreen.tsx` lines 185-187. Do not paraphrase.
