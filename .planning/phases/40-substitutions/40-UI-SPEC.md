## Typography

**Scope of this contract:** the table below caps the fonts **newly authored by Phase 40** (`SubstitutionButton`, the substitution modal chrome, the sub-counter chip, the "OUT" unavailable badge, and the new `.cardChip`/`.injuryChip` instances on sub-roster rows). It does NOT govern the reused `LineupAssignmentScreen` internals (22px/800 `.matchSetupHeading`, 20px/800 `.confirmButtonReady`, 12px/700 card meta, etc.) — those are pre-existing, unchanged, and out of this phase's authoring scope per the D-01 "reuse verbatim" decision. Phase 40 introduces **zero new font sizes**: every new element reuses an existing role size already established by a sibling component.

| Role    | Size | Weight | Line Height |
| ------- | ---- | ------ | ----------- |
| Body    | 13px | 400    | 1.5         |
| Label   | 11px | 400    | 1.2         |
| Heading | 14px | 700    | 1.2         |
| Display | 22px | 800    | 1.2         |

Only two weights are newly authored by this phase: 400 (regular) and 700 (bold). The 22px/800 Display row is a **direct verbatim reuse** of `.matchSetupHeading`'s pre-existing 800 weight (the modal's title bar inherits this heading unchanged when the reused `LineupAssignmentScreen` renders inside it) — not a new weight introduced by this phase.

Role mapping for this phase's new elements:

- **Heading (14px/700/1.2)** — modal title bar text ("Substitution" — see Copywriting Contract), matches `.statusActive`/`.statusWaiting`'s existing 14px/700 size in `LineupAssignmentScreen.module.css`.
- **Label (11px/400/1.2)** — sub-counter chip text, "OUT" unavailable badge text, `SubstitutionButton`'s vertical label text — matches `.cardChip`/`.injuryChip`'s existing 11px/400 exactly (D-05's explicit "visually match" instruction).
- **Body (13px/400/1.5)** — any new helper/status line inside the modal (e.g. permanent-slot-cap note, rejection messages reusing `.swapRejection`'s existing pattern) — matches `ActionPanel`'s `.confirmText` and every prior restart panel's body-text precedent.
- **Display (22px/800/1.2)** — inherited verbatim from `.matchSetupHeading` when `LineupAssignmentScreen` renders inside the modal; not independently authored this phase.

## Color

| Role            | Value                                                                   | Usage                                                                                                |
| --------------- | ----------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `#121212` (`--color-bg-page`)                                           | Page background behind the board; modal backdrop scrim                                               |
| Secondary (30%) | `#1c1c1c` (`--color-bg-surface`) / `#262626` (`--color-bg-surface-alt`) | `.substitutionModalCard` container background (matches `.confirmCard`)                               |
| Accent (10%)    | `#27ae60` (`--color-cta-ready-bg`), `--team-accent`                     | See "Accent reserved for" below                                                                      |
| Destructive     | `#ef4444` (`--color-danger`)                                            | Not used for new UI this phase — substitution is not a destructive action (see Copywriting Contract) |

Accent reserved for:

- `--color-cta-ready-bg` (green) — the modal's "Substitute" CTA only. No pending/orange state (unlike End Turn) — a substitution is a single-click atomic action, always either enabled or not, never "some pieces still need attention."
- `--team-accent` — `SubstitutionButton`'s enabled-state hover color and the sub-counter chip's active-team accent border, consistent with every existing sidebar/panel hover treatment.
- The existing hex-tint/ring highlight system is entirely out of scope this phase (no pitch interactions added).

**New semantic tokens required this phase:** none. Every new element reuses an existing `tokens.css` value under its existing semantic name — no new colour value is introduced.

**Correction to CONTEXT.md's `.lockedBadge` reuse note:** `.lockedBadge` (the existing "LOCK" GK badge) uses `--color-accent-gold` (`#f5c518`), which is reserved for gold "this is special/required" markers (kickoff placement rings, required-target hexes) — not appropriate for a "this player is unavailable" negative-state badge. The new "OUT" badge uses `--color-text-tertiary` (`#808080`) text on a `--color-bg-surface-alt` pill background instead — same 9px/700 sizing and letter-spacing as `.lockedBadge`, different (neutral, not gold) color, since "OUT" communicates unavailability, not a positive constraint.

**Sub-counter chip color:** reuses `--color-text-secondary` (`#a0a0a0`) on `--color-bg-surface-alt`, identical to `.injuryChip`'s existing treatment — a neutral informational chip, not accent-colored (it is not interactive and does not indicate urgency at 0/3 or 1/3; only at 3/3 does the chip additionally gain `--color-danger` text color to signal "cap reached," mirroring how `.errorText` uses the same danger token for constraint violations elsewhere in the codebase).
