<objective>
Close the single open BUG-09 verification gap (18.2-VERIFICATION.md, status: gaps_found, score 4/5): the SNAPSHOT_DEFLECT non-exhausted sticky-recompute case in `setGameState`. Today, after a defender moves 1 of their 2 SNAPSHOT_DEFLECT pace hexes in a single click, the server re-broadcasts, the piece stays selected (`selectedPieceId` preserved), but `validMoveHexes` is forced to `[]` — a dead-end UX regression — because SNAPSHOT_DEFLECT falls through the sticky special-case block (which handles only HIGH_PASS_MOVE / GK_KICK_MOVE / FIRST_TIME_PASS_MOVE) to the generic `computeMovementValidHexes`, which is unconditionally rejected by `validateMove`'s `WRONG_SLOT` guard (SNAPSHOT_DEFLECT never sets `movementSlot`).

Purpose: BUG-09's contract requires the active piece's move-ring highlight to clear AND recompute correctly for all four named response-move phases including SNAPSHOT_DEFLECT. The "clear" half is fully correct and tested; only the "recompute" half for SNAPSHOT_DEFLECT's partial-budget case is broken. This plan fixes that one path and locks it in with a regression test.

Output: A SNAPSHOT_DEFLECT-aware sticky-recompute path in `useGameStore.ts` routing through the already-built `computeResponseMoveValidHexes` helper, plus a regression test in the existing BUG-09 describe block.
</objective>
