<objective>
Close BUG-09: the `setGameState` clear-vs-retain selection gate in `useGameStore.ts` only inspects the plain `MOVE`-phase `movementSlot` field (and `movedPieceIds` for activation), so it never fires for response-move sub-phases. Purpose: Broaden the existing OR-chain staleness pattern (NOT a new generic diff utility — RESEARCH.md "Don't Hand-Roll") to cover the response-move slot and pace-exhaustion fields, matching the established `slotChanged`/`activationComplete` style.

Output: Broadened clear-condition gate in `setGameState`; regression tests for slot hand-off and pace exhaustion; folded todo deleted.
