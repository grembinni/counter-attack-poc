# Phase 18.2 Plan 02: BUG-08 Re-verification + DESIGN-04 Dead Code Removal Summary

## What Was Built

**Task 1 (BUG-08 re-verification):** Added a new `describe('HexGrid — BUG-08: tackleRiskSet excludes tackleAttemptedByIds defenders', ...)` block to `HexGrid.test.tsx`, mirroring the existing steal-tint exclusion tests at lines 184-237. Two tests:

1. **Regression guard** — tackle-risk tint is present when a non-carrier defender's candidate move lands adjacent to the ball carrier and the defender is NOT in `tackleAttemptedByIds` (confirms the test actually exercises the tint path, seeded via `tackleRiskHexes: [CANDIDATE_HEX]`).
2. **Exclusion** — tackle-risk tint is ABSENT when the same defender's id IS in `tackleAttemptedByIds`, while the underlying move remains valid (`validMoveHexes` still includes the hex; `tackleRiskHexes` is empty, mirroring what `moveValidator.ts`'s D-02 fallthrough fix produces).

Both tests pass with **NO production code change**. BUG-08 is confirmed already-correct end-to-end:

- `moveValidator.ts` lines 109-124 already fall through to plain `{ ok: true }` (no `TACKLE_ATTEMPT` effect) for an excluded tackler, instead of rejecting the move outright (the D-02 fix landed in Phase 17.1-09, prior to this plan).
- `useGameStore.ts`'s `selectPiece` (lines 577-588) derives `tackleRiskHexes` directly from `validateMove`'s effect presence per candidate hex — so the validator fix automatically produces correct `tackleRiskHexes`.
- `HexGrid.tsx`'s `tackleRiskSet` (line 186-187) reads `tackleRiskHexes` from the store verbatim with no separate client-side filter — so no client wiring gap exists (unlike the steal-tint case, which required an explicit `stealAttemptedByIds` filter in `HexGrid.tsx` itself, already fixed and tested in Phase 17.1-09).

This plan closes the one confirmed actionable gap from RESEARCH.md: missing render-level test coverage for the tackle-tint path (steal-tint had 3 tests; tackle had zero — now both have symmetric coverage).
