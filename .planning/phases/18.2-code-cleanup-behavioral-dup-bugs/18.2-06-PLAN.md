<objective>
Close the single remaining BUG-09 verification gap (18.2-VERIFICATION.md, status: gaps_found, score 4/5, verified 2026-06-22): the regression test added by plan 18.2-05 (Test 7 in `useGameStore.test.ts`) is hollow and does not discriminate the fix it claims to guard.

The production fix is correct and stays untouched: `setGameState`'s `SNAPSHOT_DEFLECT` sticky branch (`useGameStore.ts:758-777`) was directly traced and confirmed by the verifier — it returns 6 valid hexes for a non-exhausted piece where the old fallthrough returned 0. That code does NOT change.

The defect is in the test fixture: `snapshotDeflectState()` (`useGameStore.test.ts:385-394`) spreads `...mockMovementState` and overrides `phase`/`activeTeam`/`attackingTeam`/`snapDeflectMovedPieceId`/`snapDeflectPaceUsed`, but never overrides `movementSlot`. So it inherits `mockMovementState.movementSlot === 'ATTACKER_4'` (`mockMovementState.ts:72`) — a non-null value the real game NEVER has during SNAPSHOT_DEFLECT (gameEngine.ts nulls `movementSlot` well before that phase). The verifier empirically proved that under this inherited `'ATTACKER_4'` value the OLD fallthrough path returns the SAME 6 hexes as the new fixed path — so Test 7 passes identically whether or not the Task-1 fix exists. It provides zero revert protection.

Purpose: BUG-09's REQUIREMENTS.md contract is "fixed AND covered by regression tests." The fix half is satisfied; this plan satisfies the "covered by regression tests" half by making Test 7 actually exercise the WRONG_SLOT failure mode (via `movementSlot: null`) and empirically proving it now fails when the production branch is reverted.

Output: A one-field fix to `snapshotDeflectState()` (`movementSlot: null`) plus an empirical proof-of-discrimination step (temporarily revert `useGameStore.ts:758-777`, confirm Test 7 goes RED, restore, confirm GREEN). No production code ships changed.
</objective>
