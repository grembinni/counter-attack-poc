<objective>
Fix BUG-31: the eligible-players-remaining message and the End Turn button color (`ctaButtonClass`) only update once a piece is fully activated (pace exhausted and locked into `movedPieceIds`), not the moment it starts moving. Redefine "started" as "has ANY `paceUsedByPieceId` entry" (D-03/D-04) by reusing the existing started signal (`Object.keys(paceUsedByPieceId).length`, mirroring `activatedCount` at HexGrid.tsx:702), so both surfaces update on the first hex step. The Undo case (D-05) falls out for free because the server's `applyUndo` already deletes the piece's `paceUsedByPieceId` entry and re-broadcasts — this plan proves it with a test.

Purpose: Players need immediate, honest feedback on how many moves remain in the slot; the current lag makes the counter and button appear "stuck" mid-move.
Output: A simplified, correct `remaining` derivation in `ActionPanel.tsx` and regression coverage in `ActionPanel.test.tsx`.
</objective>
