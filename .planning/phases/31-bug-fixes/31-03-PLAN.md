<objective>
Fix BUG-32: the goalkeeper can currently be selected as an eligible deflection responder during SNAPSHOT_DEFLECT; it must never be selectable. Apply the project's server-authoritative two-layer pattern (D-06, ARCH-01..07): add a client selection gate (`piece.role !== 'GK'` in `canSelectSnapDeflect`) AND a server-side rejection in the SNAPSHOT_DEFLECT move handler so a modified/buggy client cannot submit a GK deflection move the server would otherwise accept. Remove the now-dead SNAP-02 GK-penalty-recompute branch that only existed to compensate for the defect being fixed.

Purpose: The GK moving during an opponent's snapshot deflection is a rule violation that also corrupts the GK-penalty calculation; both the UI and the authoritative server must forbid it.
Output: Client gate in `HexGrid.tsx`, server rejection in `gameHandlers.ts` (dead branch removed), and regression tests on both layers.
</objective>
