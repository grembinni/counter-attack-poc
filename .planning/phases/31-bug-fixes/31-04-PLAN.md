<objective>
Close the folded header-winner-eligibility todo (`2026-07-12-bug-header-winner-piece-ineligible-next-phase.md`) — same eligibility / `movedPieceIds`-locking class as BUG-31. After winning a header duel and targeting a hex on a non-goal route, the winning piece should be marked activated/spent for the next MOVE phase (added to `movedPieceIds`) so it shows a grey ring and `canSelect` is false, but currently it is treated as a fresh player with full movement. Fix `applyResolveHeaderTarget` in `gameEngine.ts` to append the winner's id to `movedPieceIds` on both non-goal branches, guarding against the null (uncontested/declined) winner. The goal-line route (GK_DIVE) is intentionally untouched.

Purpose: A header winner has already acted this turn; letting it move again in the following MOVE phase is a rule/eligibility bug that gives the attacking team a free extra activation.
Output: Guarded `movedPieceIds` append on both non-goal branches of `applyResolveHeaderTarget`, plus assertions in `gameEngine.rule11.test.ts`.

This plan is Wave 2 because it edits `packages/server/src/gameEngine.ts`, which Plan 31-01 also edits in Wave 1; sequencing avoids a concurrent-edit conflict on the same file (there is no logical dependency on 31-01's output).
