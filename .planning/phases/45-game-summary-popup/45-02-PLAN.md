<objective>
Instrument every shot-resolution branch in the server engine so that shot counts (STATS-07) and accumulated xG (STATS-08) are written into `GameState.matchStats` at the exact moment each shot resolves, using the defender positions in scope at that moment. This is CONTEXT.md D-03's requirement in code form: xG must be captured at standard shots, snapshot/deflection, headed shots and penalties alike, because no single shared hook covers all of them today. Also seed `matchStats` at match start, record whether Referee Leniency was manually overridden (STATS-03), and carry both plus the remaining rule toggles into replay frames.

This is the highest-risk plan in the phase. 45-RESEARCH.md Pitfall 1 (shot events are constructed at seven independent literal sites across two files, not one shared function) and Pitfall 2 (a goal overwrites `state.pieces` with a fresh kickoff formation inside the very same return statement that builds the goal event) both apply here, and both silently produce wrong numbers rather than errors if missed.

Purpose: make the two shot-derived statistics correct at their source, where the data still exists.
Output: seeded and replay-safe `matchStats`, xG/shot capture at all seven logical shot-resolution sites, and a server test suite that fails if any site is missed.
</objective>

- `RefereeCard.wasManualOverride?: boolean`

Planner decisions carried forward from 45-01: PD-01 (shot hex is the SHOOTER's hex), PD-02 (home attacks q=36 and counts defenders in `away*` regions; away attacks q=0 and counts `home*`), PD-05 (no new `ActionEvent` type or field — counters are written into the returned state only).
