<objective>
Build `MatchSummaryContent` — the single reusable block that renders the whole match summary: the settings/toggle recap in D-12's inline parenthetical format covering D-13's six match-rule toggles (STATS-03), and eight statistic rows covering possession, completed passes, tackles and steals with success rate, shots, expected goals, fouls, yellow cards and red cards (STATS-04 through STATS-09).

It computes only pure display ratios (percentages and bar widths) from those raw counts, per 45-RESEARCH.md Open Question 3 and this project's server-authoritative convention.

<planner_decisions>
- **PD-14 — possession denominator is `actionCount`, not the sum of the two team counters.** STATS-04 says "possession as a percentage of elapsed match minutes", and 45-UI-SPEC.md's possession row specifies a neutral remainder segment for time attributed to neither team. Dividing by `home + away` would always sum to exactly 100% and make that remainder segment dead code. Dividing by `actionCount` — the same value that drives the MM:00 clock — makes the remainder meaningful and matches the requirement's wording literally. When `actionCount` is 0, both percentages are 0 and the whole track renders neutral.
- **PD-15 — zero-attempt tackle success rate renders `0 (0%)`.** 45-UI-SPEC.md's Empty state row states every statistic has a valid zero default and that no dedicated empty-state UI is needed, so no em-dash or "n/a" special case is introduced.
- **PD-16 — xG values render with exactly two decimal places** (`toFixed(2)`), matching how expected-goals figures are conventionally presented. The stored value stays an unrounded float per PD-04; rounding is display-only. The diverging bar for the xG row uses the unrounded values so the bar and the numerals never disagree by a rounding step.
- **PD-17 — settings-recap word pairs.** `Fouls`, `Booking`, `Injury` and `Out-of-Bounds` render `Active` when enabled and `Off` when not; `Tackle/Steal Decline` renders `On` / `Off`. This reproduces D-12's verbatim example exactly for the state combination it shows (`(Fouls: Off) (Booking: Active) ... (Tackle/Steal Decline: On)`) while giving every toggle a fixed word pair. Referee Leniency renders `Manual — {value}` when `refereeCard.wasManualOverride === true` and `Auto — {value}` otherwise, per 45-UI-SPEC.md's Copywriting Contract, using an em dash surrounded by spaces.
- **PD-18 — no import of `computeShotXg` (or any other engine computation) into this component.** The client renders `matchStats.xg` as broadcast. Importing the formula client-side would create a second source of truth and a tampering surface (threat T-45-01). This is enforced by an acceptance-criteria grep.
</planner_decisions>
