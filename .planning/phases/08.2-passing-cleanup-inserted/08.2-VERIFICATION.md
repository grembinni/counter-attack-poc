### Key Behavioral Note: HEADER Resolution (Roll Header button deviation)

The PLAN (08.2-05) specified a "Roll Header button enabled only after both teams confirm their contestant." The IMPLEMENTATION auto-resolves the header on the server side when both teams' `headerConfirmed` flags become true (via `GAME_HEADER_CONTESTANT` handler, lines 1155-1168 of gameHandlers.ts). ActionPanel shows only "Confirm Selection" / "Decline" / "Waiting for opponent..." — no separate Roll Header button exists.

This deviation is intentional and functionally equivalent (the duel still only fires after both teams act), but it differs from the plan spec. The plan 06 human verification was conducted with this behavior already in place and reported PASS.
