# Phase 08.2 Plan 03: HEADER Duel Reads headerContestants + HEAD-05 Exclusion Summary

## One-liner

HEADER duel rewritten to read per-team selected contestants from `state.headerContestants`; uncontested auto-wins, neither-selected routes to LOOSE_BALL, and contested pieces are excluded from the next Movement Phase via HEAD-05.

## What Was Built

### Task 1: Rewrite HEADER branch to read headerContestants (D-17, D-19, HEAD-02)

Replaced the nearest-defender auto-selection loop in `applyRoll case 'HEADER'` with a contestant-lookup pattern that reads `state.headerContestants.home/.away` directly.

**Branch logic implemented:**

- **(c) Neither selected** (both null): → `LOOSE_BALL` from `ball.position` (D-19)
- **(b) Uncontested** (defender null, attacker selected): attacker auto-wins with NO dice roll (HEAD-02) → `PASS` with attacker holding ball
- **(a) Both selected**: contested duel using `computeCombinedScore` with HEAD-01 penalty via `validateHeading`; attacker wins on tie-or-higher → `PASS` (D-22); defender wins → `MOVEMENT`

All attacker-wins outcomes set `contestedPieceIds` to the selected ids and clear `headerContestants`/`headerConfirmed` to null (D-21). Old nearest-defender auto-select loop and GK aerial challenge paths removed.

### Task 2: applyStartMovement clears contestedPieceIds; applyMove rejects contested pieces (HEAD-05, D-21)

- `applyStartMovement`: returns `contestedPieceIds: []` in the new state — consumes the exclusion list after exactly one Movement Phase (Pitfall 6)
- `applyMove`: added guard step 2.5 — rejects movement of any piece whose id is in `state.contestedPieceIds` with `MOVE_INVALID / CONTESTED_PIECE`
- Plan-01 HEAD-05 RED scaffold tests now GREEN
