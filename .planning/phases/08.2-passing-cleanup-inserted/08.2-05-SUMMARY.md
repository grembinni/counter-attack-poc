# Phase 08.2 Plan 05: Client-Side Passing UI Summary

**Zustand pass-target store slices with validatePass-driven green/amber hex highlights, three-step PASS flow in ActionPanel, and HEADER contestant ring toggle with two-team gated Roll Header**

## Accomplishments

- Pass type selection now computes valid target hexes client-side by calling validatePass across all PITCH_HEXES, splitting results into safe (green) and interception-risk (amber) O(1) sets — no per-render .some() loops
- Three-step PASS flow in ActionPanel: chooser → "click a target hex" prompt → Roll Dice; all state in Zustand store (not local useState) so setGameState phase-change clearing handles reset automatically
- HEADER phase contestant selection wired end-to-end: clicking eligible own pieces (≤2 hexes from ball) toggles a green ring; Confirm emits GAME_HEADER_CONTESTANT; Roll Header gated on both headerConfirmed.home and .away (Pitfall 5)

- `packages/client/src/components/PieceOverlay.tsx` - Added optional isHeaderContestant prop; renders green ring (r=14, stroke #22c55e, strokeWidth 2.5) when true

## Decisions Made

- PassType type exported from useGameStore.ts so ActionPanel can import it from the same module, avoiding a circular import from shared
- setSelectedPassType iterates all 962 PITCH_HEXES rather than a distance-filtered subset — pass range varies per type (STANDARD ≤11, HIGH ≤15, LONG unbounded) so all-hexes iteration is simpler and correct
- Confirmed pass target shows gold-outline ring, not green/amber — confirmed state takes visual priority over the safe/risk classification
- Roll Header button always rendered (disabled when not both confirmed) to avoid layout shift when the opponent confirms mid-sequence
