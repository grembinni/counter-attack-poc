<objective>
Close the three verification gaps from 05-VERIFICATION.md that block Phase 5's goal. All three live in `packages/server/src/gameEngine.ts`:

1. **Gap 1 (BLOCKER):** Every MOVEMENT phase produced by `applyGKRestart` inherits `movementSlot: null` from the GK_RESTART spread, so `applyMove`'s guard (`phase !== 'MOVEMENT' || movementSlot === null`) rejects all subsequent moves with `WRONG_SLOT`. The same defect exists in `applyRoll`'s `LOOSE_BALL` phase case (it transitions to MOVEMENT without setting `movementSlot`), which becomes reachable once Gaps 2 and 3 route ties through LOOSE_BALL.
2. **Gap 2 (BLOCKER):** A tied SHOT duel transitions to `phase: 'MOVEMENT'` using biased shot-duel dice for the loose-ball landing instead of transitioning to `phase: 'LOOSE_BALL'` for a fresh independent roll.
3. **Gap 3 (WARNING):** The PASS-inaccurate branch double-bounces (computes a landing inline AND sets LOOSE_BALL phase) and the HEADER-tie branch transitions to MOVEMENT using correlated duel dice instead of routing to the LOOSE_BALL phase for fresh dice.

Purpose: Make the GK-restart MOVEMENT phase playable (SHOT-05 currently PARTIAL) and make every tie/inaccuracy resolve its loose ball with unbiased independent dice via the existing LOOSE_BALL phase.

Output: Corrected `gameEngine.ts` branches plus updated unit and integration tests proving moves are accepted after restart and that ties land in the LOOSE_BALL phase.
</objective>
