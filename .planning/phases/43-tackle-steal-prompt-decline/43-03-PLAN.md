<objective>
Wire the TACKLE-01 game-creation toggle end to end — settings screen checkbox (default ON) →
`ROOM_SETTINGS_CONFIRM` payload → server allow-list validation → `Room` storage →
`ROOM_SETTINGS_CONFIRMED` echo → `buildInitialGameState` parameter (default OFF) →
`GameState.tackleStealDeclineEnabled` — mirroring `outOfBoundsEnabled`'s established
client-default-on / server-default-off split byte for byte.

Purpose: the engine plan (43-04) branches on `state.tackleStealDeclineEnabled === true`. That
flag has to arrive from the host's settings screen, and the server-side default must stay
`false` so every existing code path that constructs a `GameState` without the new argument
keeps today's immediate-resolution behaviour (TACKLE-04).

Output: a live, validated, persisted toggle with no consumer yet — entering the prompt phase
is 43-04's job.
</objective>
