# Phase 18 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** Phase 18 is a polish/bug-bash phase. The overwhelming majority of its requirements (DESIGN-01..04, REPLAY-06, MATCH-06, BUG-06..11) are non-visual (logic/text consolidation, dead-code removal, replay correctness). This UI-SPEC covers only the requirements with a visual or interaction surface: **UX-07 through UX-14**, plus the DESIGN-01 naming-convention sweep (a text/copy contract, not a layout contract). No new screens are introduced — all work modifies existing components in place. 18-CONTEXT.md already locked almost every literal value; this contract fills in only what CONTEXT.md explicitly left to "Claude's Discretion," plus restates the locked values so the executor has one place to look.

## Design System

| Property          | Value                                                                                                                         |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| Tool              | none                                                                                                                          |
| Preset            | not applicable                                                                                                                |
| Component library | none — plain React + CSS Modules                                                                                              |
| Icon library      | none — text/emoji glyphs only (e.g. `&#8250;`/`&#8249;` chevrons in GameBoard.tsx)                                            |
| Font              | system default (no `font-family` set at root; `'Courier New', Courier, monospace` used locally for score/clock numerals only) |

This project has no shadcn, no Tailwind, no design-token file. Every component owns a sibling `ComponentName.module.css` with literal hex values and px sizes repeated per-file. This UI-SPEC documents the _de facto_ tokens already in consistent use across the codebase (sourced from `GameBoard.module.css`, `ActionPanel.module.css`, `TeamSelectionScreen.module.css`) so Phase 18 additions match the existing dark-navy theme exactly. Phase 18 does not introduce a token system — it is out of scope (DESIGN-03/04 call for _consolidating duplicate logic_, not introducing new abstractions; D-02 in 18-CONTEXT.md explicitly says "implement as data... do not introduce a templating engine").

shadcn gate: project is React + Vite, but `components.json` is absent and the existing UI is 100% hand-rolled CSS Modules with a fully consistent dark theme already in place. Introducing shadcn now would require re-skinning every existing component to avoid a visual seam — far outside this polish phase's scope. Per the gate's "If N" branch: `Tool: none` is recorded above; registry safety gate is not applicable.

## Spacing Scale

The codebase does not use a formal spacing scale, but its actual literal values already cluster tightly on an effective 4px-ish micro-grid (2/3/4/6/8/12/16/24px). Phase 18 additions should reuse these exact values — do not introduce a new scale.

| Token | Value | Usage                                                                    |
| ----- | ----- | ------------------------------------------------------------------------ |
| xs    | 4px   | Icon/inline gaps (`.statRow` gap, `.ctaButton` padding-y)                |
| sm    | 8px   | Compact element spacing (`.topBandLeft` padding, `.ctaButton` padding-x) |
| md    | 16px  | Section gaps (`.grid` gap in TeamSelectionScreen, `.overlayCard` gap)    |
| lg    | 24px  | Section padding (`.overlayCard` padding, `.screen` padding)              |

Exceptions for this phase:

- UX-09's final-third marker line uses a `strokeWidth` of 3px (see Color/Visual section below) — this is an SVG stroke property, not a layout-spacing value, so it is exempt from the 4px grid.
- UX-14's banner uses 1-second total duration (timing, not spacing) — see Copywriting Contract / Interaction Timing below.

## Typography

The codebase's actual font sizes already cluster at 10/11/13/20/36/56px (verified in `GameBoard.module.css`, `ActionPanel.module.css`, `TeamSelectionScreen.module.css`). Phase 18 introduces no new screens, so no new type sizes are needed — every UX-07..14 addition reuses one of the four roles below, matching whichever existing sibling element it sits next to.

| Role             | Size    | Weight        | Line Height | Existing precedent                                                                     |
| ---------------- | ------- | ------------- | ----------- | -------------------------------------------------------------------------------------- |
| Micro-label      | 10–11px | 400 (regular) | 1.2         | `.statLabel`, `.phaseLabel`, `.gkLabel`, `.errorText`                                  |
| Body             | 13px    | 400 (regular) | 1.5         | `.helperLine2`, `.statusLine`, `.overlayBody`                                          |
| Emphasis/Heading | 13px    | 700 (bold)    | 1.2         | `.helperLine1`, `.teamName`, `.playerCardName`                                         |
| Display          | 20px+   | 700 (bold)    | 1.2         | `.heading` (TeamSelectionScreen, 20px), `.clockDisplay` (36px), `.scoreNumeral` (56px) |

Only 2 weights exist anywhere in the codebase: **400 (regular)** and **700 (bold)**. Phase 18 must not introduce a third weight (e.g. no 600/semibold) — this matches the existing contract exactly.

Per-requirement typography assignments:

- **UX-07 speed selector** (TeamSelectionScreen.tsx): label uses Body role (13px/400); selected-option uses Emphasis role (13px/700), matching `.statusLine`/`.teamName` sibling elements already on that screen.
- **UX-08 confirmation dialog text**: "{N} players left to move, are you sure you want to end your turn?" renders at Body role (13px/400), matching `.overlayBody`.
- **UX-10/UX-11 helper text**: reuses the existing two-line `.helperBlock` pattern verbatim — Line 1 = Emphasis role (`.helperLine1`, 11px/700), Line 2 = Micro-label role (`.helperLine2`, 10px/400). Do not invent new classes; extend the existing `.helperLine1`/`.helperLine2` pair with the new copy.
- **UX-12/UX-13 tooltips**: native browser tooltip rendering (no custom typography — see Interaction Contract below).
- **UX-14 event banner**: Display role. Specific size below in Visual Treatment.

### UX-08 button color states (orange → green)

CONTEXT.md locks the _behavior_ (orange while eligible moves remain, green once all eligible pieces have moved/placed) but leaves exact tokens to discretion. Use the codebase's existing amber/green pair rather than inventing new ones:

| State                    | Token                         | Rationale                                                                                                      |
| ------------------------ | ----------------------------- | -------------------------------------------------------------------------------------------------------------- |
| Orange (moves remain)    | `#f39c12`                     | Matches `.statBubbleYellow` — the codebase's existing "caution/incomplete" semantic color                      |
| Green (all moved/placed) | `#27ae60`                     | Matches `.statBubbleGreen` / connection-status-OK dot — the codebase's existing "complete/good" semantic color |
| Transition               | `background-color 0.15s ease` | Matches `.ctaButton`'s existing `transition: background 0.15s`                                                 |

Apply as a `background` override on the existing `.ctaButton` class (End Turn / Confirm Selection button) via a new modifier class (e.g. `.ctaButtonPending` / `.ctaButtonReady`) rather than inline styles — follow the same pattern `statBubbleClass()` already uses in GameBoard.tsx (a small classname-selector function based on a numeric/boolean condition), so the executor extends an established pattern instead of inventing a new one. Text color stays `#ffffff` in both states (unchanged from `.ctaButton`'s base white text — `#fff` reads at sufficient contrast on both `#f39c12` and `#27ae60`).

### UX-14 event banner

CONTEXT.md locks the literal copy ("GOOOOOAL!!!", "INTERCEPTION!!", "Tackle! Turnover!") and the 1-second transient duration. Visual treatment left to discretion:

| Property         | Value                                                                                                                                                                                                                                                                                                                                                                                                     | Rationale                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |

Interception/tackle use the existing amber "notable event" color already established by `.statBubbleYellow`, distinguishing "good news for the active viewer" from "the decisive event" without inventing a third banner color.                                                                                                      |
| Background       | `rgba(0,0,0,0.75)` rounded rect behind text                                                                                                                                                                                                                                                                                                                                                               | Matches the existing `.overlay`/`.overlayCard` half-time/full-time backdrop pattern (`rgba(0,0,0,0.6)` for full-screen dim; banner uses a slightly darker, smaller pill so it reads as a transient toast, not a modal)                                                                                                                                                                                                                                     |
| Font size        | 28px, weight 700                                                                                                                                                                                                                                                                                                                                                                                          | One step below `.heading`-class display sizes (36/56px) since this is a transient toast, not a primary scoreboard element, but must still be readable at a glance across the board — bigger than any existing 20px heading                                                                                                                                                                                                                                 |
| Position         | `position: fixed`, centered horizontally and vertically over the pitch area (`top: 50%; left: 50%; transform: translate(-50%, -50%)`), z-index above `.overlay` (z-index 10) — use z-index 20                                                                                                                                                                                                             | Per locked copy "centered on screen"; must render above the pitch but the spec does not require it above the HALF_TIME/FULL_TIME overlay since those phases can't co-occur with goal/interception/tackle events                                                                                                                                                                                                                                            |

| Implementation   | New standalone component (e.g. `EventBanner.tsx` + `.module.css`), mounted once near the top of `GameBoard.tsx`'s pitch container, subscribed to `eventLog` (same source `ActionLog.tsx` already reads) and tracking "is the most recent event new since last render" via a ref-based diff, matching the `lastPieceRef`-style "ref tracks last seen value" pattern already used in `GameBoard.tsx` (D-03) | No new event types needed per CONTEXT.md — reuses `GOAL`, `STEAL_ATTEMPT`/`TACKLE_ATTEMPT` success cases already logged                                                                                                                                                                                                                                                                                                                                    |

## Interaction Contract (UX-12 / UX-13 tooltip implementation)

CONTEXT.md explicitly left this to discretion ("whichever is more consistent with existing patterns once the planner/executor reads the current component structure"). Codebase scan resolves this:

**Decision: use the native HTML `title` attribute.** Confirmed precedent already exists in 4 places in the codebase (`KickOffSetupPanel.tsx:115`, `FreeKickSetupPanel.tsx:137`, `GameBoard.tsx:234,333`) — all render a plain `title="..."` on a `<button>` or `<span>` for hover-disclosed context. No custom tooltip component exists anywhere in the codebase. Introducing one now (a positioned `<div>` with hover-state JS, portal logic, or a new dependency) would be a net-new abstraction for a single-line label — exactly what DESIGN-03's "consolidate, don't proliferate" intent argues against.

| Target                                                                      | Tooltip text source                                                                                                                                                                                                                                                                                                                                     |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| UX-12 stat bubble (`StatRow` in GameBoard.tsx, also `PlayerStatsPanel.tsx`) | Add `title={fullStatName}` to the existing `.statRow`/`.statLabel` wrapping element. New `STAT_FULL_NAME: Record<string, string>` lookup table (same shape as `PHASE_LABEL`/`SLOT_PREFIX`) mapping `'TKL'` → `'Tackling'`, `'PAC'` → `'Pace'`, etc. for all abbreviations already rendered (`PAC`, `DRB`, `AA`, `SHT`/`SAV`, `HPS`, `RES`, `TAC`/`HND`) |
| UX-13 action button (`ActionPanel.tsx` `.ctaButton` instances)              | Add `title={actionSummary}` to each `<button className={styles.ctaButton}>`. One-line summary per action label, e.g. Standard Pass → "Pass to a nearby teammate; may be intercepted." Exact wording is executor discretion per-button (CONTEXT.md gives the pattern, not literal text)                                                                  |

No CSS changes needed for either — this is a zero-visual-footprint change (browser-native tooltip rendering, no new `.module.css` rules).
