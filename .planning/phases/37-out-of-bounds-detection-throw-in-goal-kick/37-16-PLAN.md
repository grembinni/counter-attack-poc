## Decisions locked by this plan

- **D-16-01 — The humaniser is a pure function in `utils/`, not a component-local map.** Three panels render `gameError` today (`ThrowInSetupPanel`, `GoalKickSetupPanel` ×4 sites, `FreeKickSetupPanel`) and Phase 38 will add a fourth. `packages/client/src/utils/` already holds exactly this kind of shared presentational helper (`ctaColorClass.ts`, with its own colocated test), so the new module mirrors that file's shape and test style.
- **D-16-02 — Unknown codes fall back to readable text, never to the raw token and never to an empty string.** The wire protocol is not a closed TypeScript union at the client boundary (`gameError` is typed `string | null` at `useGameStore.ts:65`, and handlers emit both literal strings and `result.reason` values). A `Record` lookup that misses must produce a sentence such as "That move isn't allowed right now." rather than leaking the code or blanking the banner — a blank banner would be a worse regression than the raw code.
- **D-16-03 — Scope is the three restart-setup panels only.** `ActionPanel.tsx` renders `gameError` at seventeen sites and `KickOffSetupPanel.tsx` at one more. `37-UAT.md`'s gap names exactly "GoalKickSetupPanel/ThrowInSetupPanel/FreeKickSetupPanel". Widening to eighteen further call sites would turn a targeted UAT fix into a full-app copy pass with a much larger regression surface. The remaining call sites must be recorded in the SUMMARY as a carried follow-up so they are not lost.
- **D-16-04 — Only `ThrowInSetupPanel`'s duplicated line is deleted.** `GoalKickSetupPanel` has the structurally identical `Goal Kick` heading plus `Goal Kick!` constraint row at lines 128-129, 160-161, 195-196 and the `Ball in Air!` variant at 225-226. The UAT report named only the throw-in panel, and `Goal Kick!` also currently doubles as the phase announcement on screens where the heading is the only other text. Record the identical redundancy in the SUMMARY as an observation for the user rather than changing unreported copy.
- **D-16-05 — The `THROW_IN_SETUP` branch selects but shows no valid-move hexes.** Throw-in placement is a teleport to `throwInHex` executed by `emitThrowInPlace(pieceId)` (`ThrowInSetupPanel.tsx:94`); the destination is fixed by the server and is already tinted by `HexGrid`'s `isThrowInHexTint` plus `BallLocationRing`. There is no per-piece destination set to compute, so the branch sets `selectedPieceId` with `validMoveHexes: []` and `tackleRiskHexes: []`. It must also reject a piece belonging to the other team, mirroring the `deriveMyTeam`/`piece.teamId !== myTeam` guard shape used by every sibling branch.

## Deliberately NOT done in this plan

- **`ActionPanel.tsx` and `KickOffSetupPanel.tsx` error humanisation** — see D-16-03. Carried as a follow-up in the SUMMARY.
- **Any change to what the server emits.** The wire codes stay exactly as they are; this is a presentation-layer fix only. Changing server codes would break the socket-level tests that assert on them.
- **The `HexGrid.tsx` clip-path repair** that the same Test 8 diagnosis names as a compounding cause — owned by `37-14-PLAN.md`, which runs in the same wave against a disjoint file set.
- **`GoalKickSetupPanel`'s hardcoded `'Attacking'`/`'Defending'` waiting-state label** (the WR-01-class twin deferred by 37-13). Still deferred; it is not a UAT gap and belongs with Phase 38's panel reuse.
