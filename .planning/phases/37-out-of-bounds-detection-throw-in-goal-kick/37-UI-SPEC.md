Introducing shadcn at Phase 37 would fork the component architecture mid-project against 36 phases of precedent. Decision: **Tool: none** — this phase extends the existing system, not a new one. Flag to the user if a future phase wants to revisit this.

**Component reuse for this phase** (per CONTEXT.md canonical_refs): the new Throw-In Setup and Goal Kick Setup panels should structurally mirror `packages/client/src/components/FreeKickSetupPanel.tsx` (`.module.css`) and `KickOffSetupPanel.tsx` (`.module.css`) — both are the closest existing analogs for a staged/gated sidebar panel with constraint rows, a gated CTA, and a waiting-state message for the non-active player. The new "Out-of-Bounds/Restarts" game-creation toggle should mirror the checkbox-row pattern in `GameSettingsScreen.tsx` (`toggleDraftPool`/`.poolRow`).

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage                                                                                                                                      |
| ----- | ----- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| xs    | 4px   | Icon/glyph gaps, tight inline padding (panel internal padding: `4px 6px`, matching `FreeKickSetupPanel`/`KickOffSetupPanel`)               |
| sm    | 8px   | Compact row/section gaps (`.section { gap: 8px }`, checkbox-row gaps, button gaps)                                                         |
| md    | 16px  | Default element spacing, card padding (`GameSettingsScreen .card { padding: 24px }` uses lg — 16px is the inter-section default elsewhere) |
| lg    | 24px  | Card/section-level padding (`GameSettingsScreen.module.css .card`)                                                                         |
| xl    | 32px  | Not used by this phase's new components                                                                                                    |
| 2xl   | 48px  | Not used by this phase's new components                                                                                                    |
| 3xl   | 64px  | Not used by this phase's new components                                                                                                    |

Exceptions: sidebar panels (`FreeKickSetupPanel`, `KickOffSetupPanel`) use a tighter established micro-scale (3px gap, 4px 6px padding) for the compact sidebar-panel family — this is a pre-existing, intentional exception documented in those components, not a new deviation. New Throw-In/Goal Kick panels should match this established sidebar-panel micro-scale exactly rather than introducing the standard 8px scale into that specific component family, for visual consistency with `FreeKickSetupPanel`/`KickOffSetupPanel`.

## Typography

| Role    | Size | Weight | Line Height |
| ------- | ---- | ------ | ----------- |
| Body    | 13px | 400    | 1.5         |
| Label   | 11px | 400    | 1.5         |
| Heading | 12px | 700    | 1.2         |
| Display | 20px | 700    | 1.2         |

Only two weights are used app-wide: 400 (regular) and 700 (bold/emphasis) — no intermediate weights (500/600) exist in the codebase. Do not introduce one for this phase.

Role mapping for this phase's new components:

- **Heading (12px/700)** — sidebar panel titles, e.g. `"Throw-In"` / `"Goal Kick"` (mirrors `FreeKickSetupPanel`'s `.panelHeading`, "Offside — Free Kick").
- **Label (11px/400/1.5)** — constraint/status rows inside sidebar panels (`.constraintRow`), error text (`.errorText`, colored `--color-danger`), CTA button text inside sidebar panels.
- **Body (13px/400/1.5)** — `GameSettingsScreen` section labels and checkbox-row text for the new Out-of-Bounds/Restarts toggle (mirrors `.sectionLabel`, `.poolRow`).
- **Display (20px/700/1.2)** — pre-existing `GameSettingsScreen` page heading (`"Game Settings"`); unchanged by this phase, listed for completeness only.

## Color

| Role            | Value                                                                                                                                 | Usage                                                                                              |
| --------------- | ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------- |
| Dominant (60%)  | `#121212` (`--color-bg-page`)                                                                                                         | Page background behind all screens/board                                                           |
| Secondary (30%) | `#1c1c1c` (`--color-bg-surface`) / `#262626` (`--color-bg-surface-alt`)                                                               | Panel/card backgrounds — new Throw-In Setup and Goal Kick Setup panel containers, settings card    |
| Accent (10%)    | `#27ae60` / `#f39c12` (`--color-cta-ready-bg` / `--color-cta-pending-bg`), `--team-accent` (`#b08b08` fallback, runtime team-derived) | See "Accent reserved for" below                                                                    |
| Destructive     | `#ef4444` (`--color-danger`)                                                                                                          | Inline validation/error text only — no destructive _actions_ exist in this phase (see Copywriting) |

Accent reserved for:

- `--color-cta-ready-bg` (green) / `--color-cta-pending-bg` (orange) — the Throw-In/Goal Kick panel's primary CTA button background, state-derived from whether all repositioning constraints are currently met (mirrors `FreeKickSetupPanel`'s `ctaColorClass` pattern). Never used for passive/decorative elements.
- `--team-accent` — CTA button hover state only (`.ctaButton:hover:not(:disabled)`), consistent with every existing sidebar panel.
- The existing hex-tint highlight system (`docs/HIGHLIGHT-REFERENCE.md`) governs all in-pitch repositioning-window highlighting (throw-in placement hex, goal-kick final-third reposition zones, ball-travel movement windows). Per CONTEXT.md D-08, this phase must map onto existing tint types (e.g. `kickoff` for neutral repositioning-zone info, `safe` for valid placement hexes) — **do not add new tint types** to `HIGHLIGHT-REFERENCE.md` unless something genuinely doesn't fit any existing type. This system is out of scope for the 60/30/10 chrome-color split above; it is governed separately by `HexCell.tsx`/`PieceOverlay.tsx`.

## Copywriting Contract

| Element                             | Copy                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Primary CTA (repositioning confirm) | `"Confirm"` — locked convention from Phase 35 (CONTEXT.md D-07), used identically across `FreeKickSetupPanel`/`KickOffSetupPanel`/`ActionPanel`. Applies to: Goal Kick's two reposition windows (goalkeeper's-team-first, then opposing team) once each side has finished placing.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| Primary CTA (throw-in step choice)  | Three co-equal action buttons after Movement Phase 1 (and again after Movement Phase 2, minus "Move"): `"Standard Throw-In"` / `"High Throw-In"` / `"Move"` — per CONTEXT.md D-09's exact per-step decision model. Second decision point (after Movement Phase 2) shows only `"Standard Throw-In"` / `"High Throw-In"` (hard cap at 2 movement phases).                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| Primary CTA (goal kick kick choice) | `"Kick"` / `"Standard Pass"` — two co-equal buttons for the goalkeeper's GOALKICK-03 choice, mirroring the existing GK_RESTART Kick-vs-Standard-Pass button pair referenced in CONTEXT.md canonical_refs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| Waiting-state (non-active player)   | `"{Team} is repositioning…"` — locked convention from Phase 35 (CONTEXT.md D-07), verbatim reuse of `FreeKickSetupPanel`'s existing waiting phrasing: `"{Attacking/Defending} team is repositioning…"`. Applies to both new panels whenever it isn't the viewing player's turn/stage.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| Empty state                         | Not applicable — this phase adds no list or data-collection view; every new screen/panel always renders active game state (a reposition window, a throw/kick choice) with no zero-item condition.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Error state                         | Inline `.errorText`/`.constraintRow` red text (`--color-danger`), stating the specific unmet constraint plus the concrete next action — mirrors `FreeKickSetupPanel`'s existing pattern exactly, e.g. `"Kicker: move a player onto the free-kick hex first — required before any other move"`. No modal/toast for validation errors; always inline, always paired with a disabled CTA + matching `title` tooltip. Server-rejected actions (`gameError` from the store) render via the same `.errorText` row beneath the CTA, matching `GameSettingsScreen`'s `gameError` handling.                                                                                                                                                                                                        |
| Destructive confirmation            | None in this phase — no delete/discard/irreversible actions are introduced. The one confirmation dialog pattern this phase should reuse is the existing **soft** "pieces remaining" guard (`withEndTurnConfirm`/`pendingEndTurn` in `FreeKickSetupPanel`): if a manager tries to end a repositioning window (Goal Kick's 6-hex reposition) with eligible pieces still unmoved, show the existing confirm-card copy pattern — `"{N} players left to reposition, are you sure you want to end your turn?"` — with `"Cancel"` / `"Yes, end turn"` buttons. This is a caution confirmation, not a destructive one (no data loss), and should use the same non-destructive dialog styling already established (`.confirmOverlay`/`.confirmCard`), not a red/danger-styled destructive pattern. |
| New settings toggle                 | Checkbox row label: `"Out-of-Bounds / Restarts"` (matches the requirement's own naming, GOALKICK-06/OOB-05), placed in `GameSettingsScreen.tsx` mirroring the existing `.poolRow` checkbox pattern (label + `<input type="checkbox">`, no separate "coming soon" disabled state — this toggle is fully functional in this phase).                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
