<objective>
Make the ball leaving the pitch a real event: hook out-of-bounds classification into the `LOOSE_BALL` scatter clamp — the single convergence point every relevant ball-exit path reaches — and route the result into a throw-in or goal-kick restart, gated behind `outOfBoundsEnabled` (OOB-02, OOB-04, OOB-05, THROWIN-01, THROWIN-05).

Purpose: RESEARCH.md §3 established that inaccurate Standard/High/Long passes, tied shot duels, deflections and failed tackles all converge on `applyRoll`'s `LOOSE_BALL` case, so one hook covers them all — including a throw-in's own overthrown delivery, which is why THROWIN-05/D-04 needs no special-casing. OOB-05 requires the disabled path to be provably unchanged, so the branch is an early split, not interleaved conditionals.

Output: `triggerOutOfBoundsRestart` engine helper, the toggle-gated clamp branch, the free-move-interrupt guard, and the `gameEngine.outOfBounds.test.ts` Wave-0 test file.
</objective>

## Decisions locked by this plan

- **Corner-kick fallback (Phase-37 boundary):** `classifyOutOfBounds` returns the theoretically correct `CORNER_KICK` when a defender of that byline touched the ball last (OOB-03), but Phase 37 must NOT award a restart for it — OOB-03 and the corner flow are Phase 38 scope. A `CORNER_KICK` result therefore falls through to today's clamp behaviour (ball stays in play at the last in-bounds hex). Awarding a goal kick instead would hand the ball to the wrong team, which is a rule violation; clamping preserves exactly today's behaviour and leaves Phase 38 a clean insertion point.
- **Untouched-ball throw-in award:** when `ball.lastTouchedBy` is `null` and the ball crosses a touchline, the throw-in is awarded to the team that is NOT `state.attackingTeam`.
- **Restart hex:** the throw-in is taken from `resolveThrowInHex(lastInBoundsHex, pieces)` — the last in-bounds hex the ball crossed, relocated to the nearest free on-pitch hex if occupied, so placement can never dead-end.
