### Gaps Summary

Three of four roadmap success criteria are fully verified with solid, tested implementations: continuous last-toucher tracking (OOB-01), byline/goal-kick classification and the full 5-phase goal-kick flow (OOB-04, GOALKICK-01..06), and the OOB-05 disabled-toggle preservation guarantee. The fourth — the throw-in flow (success criterion #2) — is substantially implemented and passes all of its own dedicated tests, but has one confirmed, reachable, CRITICAL-severity defect carried over from `37-REVIEW.md` (CR-01): the two Movement-Phase-tracking fields that drive the "choose 1 or 2 Movement Phases" flow are not cleared when a tackle or steal ends a Movement Phase early, because those code paths return directly from `applyMove` without going through `applyEndTurn`'s teardown logic. This can cause a stale throw-in context to silently re-activate on a later, unrelated Movement Phase, corrupting that team's available next actions and displaying an incorrect "Throw-In!" prompt. This is not a hypothetical: the exact reachable sequence is documented in `37-REVIEW.md` and independently confirmed here by direct code inspection. It is not covered by any existing test.

This does not represent a missing feature or a stub — the throw-in flow works correctly end-to-end in the common case (all 15 `throwIn.integration.test.ts` tests pass) — but it is a real correctness bug directly inside the mechanism success criterion #2 requires ("choose 1 or 2 Movement Phases"), reachable through ordinary gameplay (any tackle or steal attempt during a throw-in's Movement Phase), and rated CRITICAL by the phase's own code review. Per the adversarial verification standard, an unresolved CRITICAL finding touching the exact mechanism under test blocks a clean pass for success criterion #2.

**Recommended next step:** address CR-01 (clear the three `throwIn*` fields on `applyMove`'s tackle-success and steal-success early returns, or replace the `carrier.teamId === state.throwInTeam` inference with an explicit in-progress marker) and add the missing regression test before considering Phase 37 fully closed.
