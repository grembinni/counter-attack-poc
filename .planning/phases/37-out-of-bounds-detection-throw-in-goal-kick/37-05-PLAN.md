<objective>
Implement the throw-in setup and the D-09 per-step Movement Phase choice model (THROWIN-02, THROWIN-03).

Purpose: THROWIN-02 requires the attacking manager to select a player and place them, with the ball, at the exit hex. THROWIN-03's "1 or 2 Movement Phases" is modelled per D-09 as a per-step decision, not an upfront pick: Movement Phase 1 is mandatory, then the manager chooses throw-Low / throw-High / Move, and after a second Movement Phase the Move option is gone. RESEARCH.md §4.1 established that "Movement Phase" means the real 4-5-2 `MOVE` phase, so this plan reuses the existing movement engine wholesale and adds only the counting branch in `applyEndTurn` plus the placement step.

Output: `applyThrowInPlace`, the `applyEndTurn` throw-in branch, and the `GAME_THROW_IN_PLACE` handler. The throw itself (6-hex cap, Low/High delivery) is Plan 37-06.
</objective>

## Decisions locked by this plan

- **Possession loss clears the throw-in context.** If the ball changes hands during a throw-in Movement Phase (steal/tackle), the `applyEndTurn` throw-in branch does not fire; instead the throw-in fields are cleared and the generic branch runs. Concretely the branch is gated on `state.ball.carrierId` belonging to `state.throwInTeam`. Without this, a defender who wins the ball would inherit the throw-in's 6-hex-capped pass options.
- **Placement is a teleport, not a move.** The chosen piece is repositioned to `state.throwInHex` regardless of distance and gains the ball. `state.throwInHex` is guaranteed unoccupied by `resolveThrowInHex` (Plan 37-01/37-04), so no swap or displacement logic is needed.
