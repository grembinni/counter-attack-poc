<objective>
Build the pure out-of-bounds classification module and add the `ball.lastTouchedBy` tracking field that every downstream plan in this phase depends on (OOB-01, D-06).

Purpose: `lastTouchedBy` is the single source of truth for deciding which team is awarded a restart. Output: new `packages/shared/src/outOfBounds.ts` + `outOfBounds.test.ts`; `BallState.lastTouchedBy` required; every ball construction site across shared/server/client updated.
</objective>

1. `export type OutOfBoundsExit = 'SIDELINE' | 'BYLINE' | null;`
2. `export type OutOfBoundsRestart = 'THROW_IN' | 'GOAL_KICK' | 'CORNER_KICK';`
3. `export function classifyExit(hex: HexCoord): OutOfBoundsExit` — compute `qOut = hex.q < 0 || hex.q > 36` and `rOut = hex.r < 0 || hex.r > 25`; return `null` when neither is true; return `'BYLINE'` when `qOut` (checked FIRST, so the ambiguous both-out corner case resolves to byline per D-05); otherwise `'SIDELINE'`. 4. `export function bylineOwner(hex: HexCoord): 'home' | 'away' | null` — returns `'home'` when `hex.q < 0` (q=0 is `PITCH_REGIONS.homeGoal`'s column, so the negative-q byline is home's own goal line), `'away'` when `hex.q > MAX_Q`, `null` otherwise. This is the "whose goal line did the ball cross" helper the restart-award logic needs; it is NOT the same question as "who last touched the ball".
5. `export function classifyOutOfBounds(exit: 'SIDELINE' | 'BYLINE', lastTouchedByTeam: 'home' | 'away' | null, bylineOwnerTeam: 'home' | 'away' | null): OutOfBoundsRestart` — `'SIDELINE'` returns `'THROW_IN'`. For `'BYLINE'`: return `'CORNER_KICK'` when `lastTouchedByTeam !== null && lastTouchedByTeam === bylineOwnerTeam` (a defender of that goal line touched it last — OOB-03, Phase 38 scope), otherwise `'GOAL_KICK'` (attacker touched last, or untouched — OOB-04). Document in a JSDoc block that Phase 37 callers must NOT route the `CORNER_KICK` result into a restart flow (Plan 37-04 owns that decision) and that Phase 38 only has to add the consumer branch, never edit this function's logic.
6. `export function resolveThrowInHex(preferred: HexCoord, pieces: readonly { position: HexCoord }[]): HexCoord` — returns `preferred` when no piece occupies it. Otherwise scan `hexesInRange(preferred, radius)` for `radius` 1..6, filtering to hexes that satisfy `isPitchHex` and are unoccupied, and return the first candidate after sorting by `hexDistance(preferred, candidate)` ascending, then `q` ascending, then `r` ascending. If nothing is found within radius 6, return `preferred` unchanged (documented last-resort fallback). This exists so the throw-in placement hex is guaranteed free and the Plan 37-05 placement step can never dead-end on an occupied exit hex.

Create `packages/shared/src/outOfBounds.test.ts` with one `describe` per exported function, asserting every case listed in `<behavior>` above, plus a determinism assertion that two consecutive `resolveThrowInHex` calls with identical inputs return the identical coordinate.
