## Decisions locked by this plan

- **D-12-01 — Keep the "<Side> team is repositioning…" sentence; fix the label, not the sentence.** `37-REVIEW.md` suggests replacing the whole line with "Opponent is placing the thrower…". Rejected: `ActionPanel.tsx` uses `` `${actingSideLabel} team is repositioning…` `` at four separate call sites (lines ~306, ~346, ~616, ~649) with `actingSideLabel = activeTeam === attackingTeam ? 'Attacking' : 'Defending'`, and `ThrowInSetupPanel`'s own doc comment cites Phase 35's D-07 "verbatim waiting-state phrasing" lock. Reusing that derivation fixes the wrong word, keeps the locked sentence shape, and keeps the two pre-existing `/team is repositioning/` regex assertions green.
- **D-12-02 — Derive the label rather than hardcoding "Attacking".** `triggerOutOfBoundsRestart`'s `THROW_IN` branch sets `attackingTeam: throwInTeam` and `activeTeam: throwInTeam`, so in every real `THROW_IN_SETUP` state the label resolves to `'Attacking'`. Hardcoding the literal would be correct today and silently wrong if that invariant ever changes; deriving it costs one store selector and mirrors `ActionPanel` exactly.
- **D-12-03 — Correct the test fixture rather than assert the fixture's wrong value.** `throwInSetupState` currently sets `throwInTeam` while inheriting `attackingTeam: 'home'` / `activeTeam: 'home'` from `mockMovementState`, so `throwInSetupState('away')` describes a state the server cannot produce. The fixture is updated to set `attackingTeam` and `activeTeam` to the throwing team; the new assertion then pins the real-world string.
- **D-12-04 — Gate the handler's `rollDice()`, do not change the engine signature.** `applyGoalKickMoveEnd(state, kickDie)` stays total and deterministic (ARCH-01 forbids rolling inside the pure engine, and `37-09`'s doc comment already documents `kickDie` as ignored on the `KICKER` slot). Splitting the function or making the parameter optional would churn a 25/25-green state machine for no behavioural gain.
