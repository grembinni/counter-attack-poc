## Trust Boundaries

| Boundary                              | Description                                                           |
| ------------------------------------- | --------------------------------------------------------------------- |
| public internet → Render web service  | Untrusted HTTP/WSS requests from remote browsers cross here           |
| Express filesystem → HTTP response    | Static file serving exposes only the files under packages/client/dist |
| Vite build → production client bundle | Build-time inlined env values become attacker-visible in shipped JS   |

## STRIDE Threat Register

| Threat ID | Category                 | Component                                              | Disposition | Mitigation Plan                                                                                                                                                       |
| --------- | ------------------------ | ------------------------------------------------------ | ----------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| T-09-01   | Information Disclosure   | express.static static-serving block in createServer.ts | mitigate    | Serve ONLY `path.resolve(__dirname, '../../client/dist')` — never repo root or server source; D-03 scopes express.static to the client dist directory exclusively     |
| T-09-02   | Spoofing (false-healthy) | /healthz vs SPA fallback ordering in createServer.ts   | mitigate    | Register `/healthz` BEFORE express.static and `app.get('*')`; staticServing.test.ts asserts /healthz body is 'ok' and not index.html                                  |
| T-09-03   | Elevation of Privilege   | client socket URL in socket.ts production bundle       | mitigate    | D-04: remove `'http://localhost:3001'` fallback so production client connects to its own page origin, never a hardcoded host an attacker could shadow                 |
| T-09-04   | Information Disclosure   | CORS wildcard in production (existing main.ts warn)    | accept      | Single-service same-origin architecture (D-01) means cross-origin WS is a non-issue for the POC; existing warn-but-continue behavior documented and accepted per D-09 |

</threat_model>
