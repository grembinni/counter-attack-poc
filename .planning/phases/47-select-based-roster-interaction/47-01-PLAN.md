## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input (click/keydown) → React component | Untrusted gesture crosses into client component state |
| client → Socket.io server (`DRAFT_PICK`, `DRAFT_REARRANGE`) | Not crossed by this plan — `DraftPackCarousel` emits nothing; it only reports `onCardClick(cardId)` to its parent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-01 | Tampering | `DraftPackCarousel` client-side eligibility/disabled gating | accept (already mitigated upstream) | Client gating is UX-only. This plan changes ONLY the input gesture (drag→click); the server handlers `DRAFT_PICK`/`DRAFT_REARRANGE` remain the sole authority and are not touched by this phase (CONTEXT.md Integration Points). A crafted payload is rejected server-side exactly as today. |
| T-47-02 | Tampering | Stale/stomped selection across rapid clicks | mitigate | `DraftPackCarousel` holds NO selection state — `selectedCardId` is parent-owned and passed down (the "parent owns all resolution state" convention preserved from the drag implementation). A rapid double-click cannot produce a card-local stale value because no card-local value exists. |
| T-47-03 | Elevation of Privilege | `disabled` (waiting-for-opponent) bypass via keyboard | mitigate | When `interactive` is false, no `onClick`, no `onKeyDown`, no `role="button"`, and no `tabIndex` are attached — the card is neither clickable nor focusable. Verified by Task 3's disabled-click assertion. |
| T-47-SC | Tampering | npm/pip/cargo installs | mitigate | Not applicable — this plan installs zero packages (RESEARCH.md §Environment Availability confirms no new dependencies this phase). No `[ASSUMED]`/`[SUS]` package checkpoint is required. |
</threat_model>
