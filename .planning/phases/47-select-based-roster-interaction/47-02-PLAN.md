## Trust Boundaries

|----------|-------------|
| user input (click/keydown) → React component | Untrusted gesture crosses into client component state |
| client → Socket.io server (`GAME_SUBSTITUTION`, `DRAFT_PICK`, `DRAFT_REARRANGE`) | Not crossed by this plan — `BenchCarousel` emits nothing; it reports indices to its parent only |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-47-04 | Tampering | Client-side bench eligibility used as authority | accept (already mitigated upstream) | Client eligibility is UX-only. This plan changes ONLY the input gesture; `GAME_SUBSTITUTION`/`DRAFT_PICK`/`DRAFT_REARRANGE` server handlers remain the sole authority and are untouched by this phase (CONTEXT.md Integration Points), so a crafted payload is rejected exactly as today. |
| T-47-05 | Tampering | Stale/stomped selection across rapid clicks | mitigate | `BenchCarousel` holds zero selection state — `selectedCardId` and `benchAreaEligible` are parent-owned props. | T-47-06 | Elevation of Privilege | Clicking an OUT / RED CARD / disabled bench card to initiate an illegal substitution | mitigate | `handleCardClick` returns early for `disabled === true` and for any id in `unavailablePlayerIds`/`redCardedPlayerIds` — the same guard set the drag implementation enforced. | T-47-07 | Tampering | Bubbled card/nav click silently completing an unintended bench move | mitigate | Card and nav-button clicks call `stopPropagation`, and the container's `onClick` is attached only when `benchAreaEligible === true`. Regression-tested by Task 2 assertions 7 and 8. |
