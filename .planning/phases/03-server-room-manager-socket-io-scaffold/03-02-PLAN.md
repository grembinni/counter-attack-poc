<objective>
Implement the in-memory room store (Pattern 2 in RESEARCH.md) and the Socket.io reconnection middleware (Pattern 3 in RESEARCH.md) as pure-function modules with co-located unit tests. The room store is the source of truth for room lifecycle — code generation, slot assignment, status transitions, session-token lookup, and the broadcast helper that Plan 03 (and every Phase 4+ handler) calls after every state change. The middleware reads the handshake `sessionToken` and populates `socket.data` so the Plan 03 connection handler can distinguish reconnects from fresh connects.

Purpose: Two architectural pillars must be in place before Plan 03 wires the Socket.io server:

1. A single source of truth for room state with a discriminated-union API (joinRoom can fail in two distinct ways — NOT_FOUND vs NOT_WAITING — satisfying CONN-04).
2. A middleware that restores session identity from a token, enabling the 90-second grace-timer reconnect path that Plan 03 builds.

Both modules use named exports, `.js` extensions on local imports, `import type` for type-only imports (per `verbatimModuleSyntax: true`), and follow the moveValidator.ts naming/JSDoc/guard-first conventions documented in PATTERNS.md.
