## Interaction Contract

The following interaction contracts govern the three behavioral changes in Phase 25. This section supplements the standard design contract with phase-specific interaction rules.

### Pass Result Popup (D-20, UX-15)

**Trigger:** `HP_ACCURACY` ActionEvent appended to `eventLog`.

**Visual behavior:**

- Popup renders at center of viewport, fixed position, `z-index: 20`.
- Background: `rgba(0, 0, 0, 0.75)`, `border-radius: 8px`, `padding: 12px 24px`.
- Text: 28px / weight 700, color `#f39c12` (`.notable` variant).
- Animation: reuse existing `bannerFade` @keyframes (0% opacity:0 → 10% opacity:1 → 90% opacity:1 → 100% opacity:0).
- Duration: **1500ms** total (not the existing 1000ms EventBanner duration — slightly longer for reading time). (RESEARCH.md Pattern 2, D-20)
- DOM removal: JS `setTimeout` at 1500ms removes the element from DOM (same pattern as EventBanner.tsx lines 59-69).

**Auto-advance behavior:**

- The attacking player's client (`isActivePlayer && myTeam === attackingTeam`) auto-fires `emitHeaderAccuracyAck()` after 1500ms via `setTimeout`.
- The non-active player's client shows the EventBanner popup (event-log-driven) but does NOT emit the ack.
- The INACCURATE case (transition to `LOOSE_BALL`) auto-emits `emitRoll()` which is already present — no change to that path.
- The "Continue" push-button rendered in `ActionPanel.tsx` for `phase === 'HEADER' && headerAccuracyRollPending` is removed and replaced with the auto-advance + popup pattern.

**Anti-pattern:** Do not fire `emitHeaderAccuracyAck()` before the popup has rendered. The `setTimeout` must fire at 1500ms, not immediately.

### Eligible Counter (D-19, UX-15)

**Trigger:** `selectedPieceId` becomes non-null in MOVEMENT phase.

**Visual behavior:** The derived `remaining` count displayed in ActionPanel decrements by 1 when a piece is selected for movement, even before the destination is confirmed. The display is purely cosmetic — no new visual element, no animation, no color change.

**Decrement condition (all three must be true):**

1. `phase === 'MOVEMENT'`
2. `selectedPieceId !== null`
3. Selected piece is NOT already in `movedPieceIds` AND `paceUsedByPieceId[selectedPieceId]` is undefined or zero (piece is genuinely unmoved)

**Restore on undo:** When `emitUndo` is called, the server broadcasts a new state. The store's `selectedPieceId` returns to `null`. The `remaining` count restores automatically (derived from `selectedPieceId` being null again). No additional state management needed.

**Anti-pattern:** Do not decrement when an already-moved piece is selected for inspection in MOVE phase. Condition 3 prevents double-counting.

### Style 12 / Style 13 SVG Pattern Swap (D-18, UX-15)

**Target:** `packages/client/src/styles/uniformStyles.tsx` — `quarterHorizontal` (style 12) and `quarterDiagonal` (style 13) renderers.

**Contract after fix:**

| Style    | Name                 | Visual                                                     | SVG approach                                                                    |
| -------- | -------------------- | ---------------------------------------------------------- | ------------------------------------------------------------------------------- |
| Style 12 | `quarter-horizontal` | ╬ (cross/plus axis — horizontal + vertical dividing lines) | No `patternTransform` rotation; `x={cx - R}`, `y={cy - R}` for proper alignment |
| Style 13 | `quarter-diagonal`   | ✕ (diagonal axis — diagonal dividing lines, 45° rotation)  | `patternTransform={rotate(45 {cx} {cy})}`, `x={0}`, `y={0}` alignment           |

**Rule:** Both renderers must be updated in the same task. Fixing one without the other merely moves the error to the other style. Verify both styles in the uniform selection screen after the fix. (RESEARCH.md Pitfall 3)
