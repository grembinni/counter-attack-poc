<objective>
Fix the UX-15 header contestant selection clearing bug: when Player A confirms their header contestant selection, Player B's in-progress contestant selection (headerContestantIds) is cleared.

The suspected root cause (confirmed during Task 1 investigation): in `useGameStore.ts` the state-update handler resets `headerContestantIds: []` whenever `prevSelectedId === null` — which is always true in the HEADER phase because contestant selection uses `toggleHeaderContestant`, not `selectedPieceId`. This means every server broadcast during the HEADER phase (triggered by Player A's confirmation) clears Player B's pending selection.

Purpose: Stop opponent confirmation from wiping a player's pending header contestant picks (D-16), a bug surfaced in v1.3 playtesting.
Output: A targeted fix in `useGameStore.ts` that preserves `headerContestantIds` across in-HEADER state broadcasts, with root cause confirmed at the Task 1 checkpoint.
</objective>
