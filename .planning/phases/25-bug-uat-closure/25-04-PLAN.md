The root cause is unknown, so this plan is investigation-first (D-16, mandatory) — trace the socket-event path and component lifecycle, pause at a human-verify checkpoint to confirm the mechanism, then apply the minimal fix that preserves each player's pending selections across the opponent's confirmation event.

Purpose: Stop opponent confirmation from wiping a player's pending uniform/formation choices (D-16), a bug surfaced in v1.3 playtesting.
Output: A documented root cause plus a minimal, targeted fix in App.tsx and/or UniformSelectionScreen.tsx that preserves `selectedTeam`, `selectedStyle`, `selectedFormation`, and `jerseyType` across the opponent's confirm.
</objective>
