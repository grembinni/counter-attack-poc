<objective>
Fix the Style 12 (`quarterHorizontal`) pattern centering. The Plan 05 UAT (Task 3, item 5) confirmed that the diagonal quarter (✕) pattern is not centered correctly — the `rotate(45 cx cy)` transform is applied but the pattern origin is at `(0, 0)` instead of the piece centre offset `(cx-R, cy-R)`. As a result, the tile seam does not pass through the piece centre after rotation, so the four diamond sections are asymmetrically placed.

Root cause: `quarterHorizontal` uses `x={0} y={0}` for the SVG `<pattern>` element. With `patternUnits="userSpaceOnUse"`, `x` and `y` set the origin of the pattern tiling in user space. Because the origin is at (0,0) instead of (cx-R, cy-R), the tile junction does not land at the piece centre. After the `patternTransform="rotate(45 cx cy)"` is applied, the asymmetric placement becomes visible — the four colour sections are not equally distributed around the centre.

Fix: Change `x={0} y={0}` to `x={cx - R} y={cy - R}` in `quarterHorizontal`, mirroring the anchor used by `quarterDiagonal` (which is correct and must not change). The `patternTransform="rotate(45 cx cy)"` remains as-is — it rotates the correctly-anchored tile 45° around the piece centre, producing four symmetric diamond quarters.

Style 13 (`quarterDiagonal`, the ╬ cross-axis pattern) already uses the correct `x={cx - R} y={cy - R}` anchor and must NOT be changed.

Purpose: Fix the pattern tile origin in `quarterHorizontal` so the ✕ diagonal quarters are symmetrically centred around the piece.
Output: Single two-attribute change (`x`, `y`) inside `quarterHorizontal`'s `<pattern>` element.
</objective>
