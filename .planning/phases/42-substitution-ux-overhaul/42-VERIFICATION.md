### Gaps Summary

Phase 42 delivers a substantial, well-tested implementation of the drag-and-drop positioning mode, the staged substitution/confirm flow, and the SUB-16/17 chrome — all independently re-verified against the current codebase (not merely SUMMARY.md claims), with 4 of 5 top-level success criteria fully confirmed by code, tests, and live re-run of the relevant automated suites (247 tests re-run across client/server/shared, all green).

However, Success Criterion 5 / BUG-38 — "a red-carded player is removed from every gameplay computation... anywhere in the game" — is not fully achieved. The phase's own two originally-diagnosed live defects (DEFLECT_ATTEMPT, ZoI opponent list) are correctly fixed. But the phase's own audit mandate ("plus any other site an audit finds still treating them as on-pitch") was not fully executed: `packages/shared/src/passValidator.ts`'s LONG-pass landing-restriction check and `packages/shared/src/offside.ts`'s `opposingPiecesEqualOrAhead` (used live in offside determination via `evaluateOffside`, called from 6+ sites in `gameEngine.ts`) both still use raw, unfiltered `state.pieces` lists, directly contradicting `stoppagePhases.ts`'s own documented contract that "eligibility/occupancy/ZoI/interceptor lists, anywhere in `packages/shared`, must be built through this predicate." The `passValidator.ts` gap was already flagged by the phase's own code review (42-REVIEW.md, WR-01) written after the gap-closure round closed, but was not folded back into a gap-closure plan before the phase summary declared `passed`. The `offside.ts` gap was found independently during this verification and confirmed via an executed test (a red-carded opponent is still counted as a covering defender in live offside math).

Both are narrow, well-understood, mechanical fixes (apply the existing `isActivePiece` predicate at the two sites, matching the pattern already used at a dozen+ other sites in the same files) — this is not a design-level gap, but it is a real, currently-shipping correctness defect squarely within BUG-38's explicit scope and should be closed before the phase is marked complete.
