## What Was Built

### Task 1: LobbyScreen UX (D-02, D-03, D-04)

**JoinRoomScreen changes:**

- Added `useEffect` to React import
- Added `isJoining` local state (boolean, default false)
- `useEffect([roomError])` resets `isJoining` to false when a room error arrives from server
- `handleSubmit` guards on `input.length === 0 || isJoining` — prevents double-submit and empty submit
- `handleSubmit` calls `setIsJoining(true)` before emitting `room:join`
- Room-code input has `onKeyDown` handler: `if (e.key === 'Enter') handleSubmit()`
- Join button: `disabled={input.length === 0 || isJoining}` and renders `'Joining...'` when loading
- Removed both debug `console.log` lines from `handleSubmit`

**WaitingScreen text:** Updated `Share this code to invite someone:` to `Share the code above with your opponent.` (D-04)

**Tests (LobbyScreen.test.tsx):** 4 passing cases covering CONN-02:

1. Enter key emits `room:join` with the typed code
2. Join button disables and shows "Joining..." after click
3. Join button re-enables when `roomError` arrives in store
4. Empty input keeps button disabled and does not emit

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] ESLint unbound-method violation on vi.mocked(socket.emit)**

- **Found during:** Task 1 RED commit
- **Issue:** `vi.mocked(socket.emit)` triggers `@typescript-eslint/unbound-method` because `emit` is accessed as an unbound method reference. ESLint lint-staged pre-commit hook blocked commit.
- **Fix:** Used a `MockSocket` type alias and cast `socket as unknown as MockSocket` to access `emit` directly as the vi.fn() mock, bypassing the unbound-method rule.
- **Files modified:** packages/client/src/components/LobbyScreen.test.tsx
- **Commit:** 8f5558e (re-staged after fix)

**2. [Rule 3 - Blocking] Test 3 (re-enable on roomError) needed button role adjustment**

- **Found during:** Task 1 RED phase — test expected `/joining\.\.\./i` role name but before implementation `isJoining` didn't exist so button stayed as "Join Game"
- **Fix:** Adjusted test to look for `name: /join game/i` after `act(() => setState(roomError))` since once isJoining resets the button text reverts. This is correct post-implementation behavior.
- **Files modified:** packages/client/src/components/LobbyScreen.test.tsx
