<decisions>
## Implementation Decisions

### Team Kick-Off Positions

- **D-01:** Replace placeholder 25×16 coordinates in `packages/shared/src/teams.ts` with real positions on the 37×26 board. Claude approximates a **4-5-2 formation**: GK on own goal line, 4 defenders in own third, 5 midfielders spread through middle third, 2 forwards across the midline. Home team near q=0 (home goal), away team near q=36 (away goal). Layout is symmetric — away positions mirror home positions across q=18.

### Lobby & Join UX

- **D-02:** **Enter key submits the join form.** Pressing Enter in the room code input field triggers the same handler as the "Join Game" button. Standard web form keyboard UX.
- **D-03:** **Loading/disabled state on Join button.** After the Join Game button is clicked (or Enter pressed), the button disables and shows a spinner/loading label until the server responds (`room:joined` or `room:error`). Prevents double-submit and makes inflight state obvious.
- **D-04:** **WaitingScreen instructional text.** Add a clear instruction to the WaitingScreen: "Share the code above with your opponent." The room code and animated dots are already present; this text makes the user action explicit.

### Player Stats Panel

- **D-05:** **Stats panel triggered by piece selection.** When any piece on the board is clicked, a stats panel renders showing that player's name, position/role, and all attributes (Pace, Shooting, Tackling, Dribbling, Heading, Saving, Handling, Resilience, Aerial Ability). Panel is positioned **below the action buttons, above the game log** in the right-hand panel.
- **D-06:** **Both players can inspect any piece.** The non-active player can click any piece (their own or the opponent's) to view stats. This selection is **local client state only** — never emitted to the server. The active player's `selectedPieceId` in the Zustand store continues to drive movement highlights as before; stats display is additive.

### Field Design

- **D-07:** **SVG overlay for pitch markings.** All pitch line markings are rendered as SVG path/line/circle elements layered above the hex cells in the same SVG root. The hex grid remains the gameplay surface; lines are cosmetic.
- **D-08:** **Pitch markings in scope:** halfway line (vertical at q≈18), centre circle (centred on kickOffHex {q:18, r:13}), both penalty box outlines (home: ~q∈[0,5], away: ~q∈[31,36]), both 6-yard box outlines (inside each penalty area), corner arc markings at all 4 corners.
- **D-09:** **Goal net visual.** Each end of the pitch has a white rectangle with a mesh/grid pattern representing the goal net, positioned **just outside the pitch boundary** (beyond q=0 for home, beyond q=36 for away). Not a hex — a separate SVG element attached to the pitch edge.
- **D-10:** **Remove black goal-hex fill.** The hexes currently rendered with a dark/black fill (the homeGoal / awayGoal region hexes) should use the same alternating light/dark grass stripe pattern as the rest of the field. The goal is now represented by the SVG goal net element (D-09), not hex fill colour.
- **D-11:** **Difficult angle hexes repositioned to corner kick zones.** `DIFFICULT_ANGLE_HEXES` in `packages/shared/src/pitch.ts` are relocated to corner kick positions: approximately 4 hexes from each corner along the sideline and 7 hexes from each corner toward the goal line, forming a triangular zone at each of the 4 corners. The -1 dice penalty (PITCH-03) continues to apply at these hexes. White dot markers move with them.
- **D-12:** **Corner arc markings added** at each of the 4 corners as SVG arc/quarter-circle elements coinciding with the corner kick zone (D-11).

### Claude's Discretion

- Debug cleanup: remove `console.log` statements from `packages/client/src/App.tsx` and `packages/client/src/components/LobbyScreen.tsx`. These are diagnostic artifacts from Phase 7 development.
- Exact pixel coordinates for pitch line markings: calculated from the hex-to-pixel conversion (`axialToPixel` with HEX_SIZE=20, flat-top orientation) for the region boundaries defined in `packages/shared/src/pitch.ts`.
- Stats panel layout and styling: Claude decides the visual presentation within the constraint of "below action buttons, above game log."
- 4-5-2 formation exact r-coordinates for each position: Claude places pieces at appropriate r values centred around r=13 (pitch midpoint row) with realistic football spacing.

<code_context>

## Existing Code Insights

### Reusable Assets

- `HexGrid` / `HexCell` (`packages/client/src/components/`) — SVG rendering infrastructure. Pitch line markings (D-07) are new SVG elements inside the same `<svg>` root, rendered after hex cells for correct z-order.
- `useGameStore.selectedPieceId` — already drives valid-move highlight highlighting. D-06 stats panel reads this same field to know which piece to display stats for.
- `LobbyScreen` sub-screens (`CreateRoomScreen`, `JoinRoomScreen`, `WaitingScreen`) — self-contained components; each gets targeted changes without affecting the others.
- `PITCH_REGIONS` from `packages/shared/src/pitch.ts` — `homePenaltyArea`, `awayPenaltyArea`, `homeSixYardBox`, `awaySixYardBox`, `centreCircle`, `kickOffHex` provide the region boundaries for pixel-coordinate calculation of SVG overlay lines.
- `axialToPixel` (or equivalent) — hex-to-pixel conversion used by HexCell to place hexes; pitch line markings need the same conversion to align with the grid.

### Established Patterns

- **Single SVG root** for all overlay elements — new pitch line markings follow the existing pattern (DOM order = z-order).
- **Zustand per-slice selectors** — `useGameStore((s) => s.selectedPieceId)` pattern; stats panel uses the same approach.
- **Named exports, no defaults** — all new components follow this.
- **`socket.off(event, handler)` cleanup** — already enforced; no new socket listeners in Phase 7.1.
- **ODD-Q offset arithmetic** — used for visual adjacency checks in hex neighbours; not relevant to pitch line SVG overlay but don't mix with axial arithmetic for boundary coords.

### Integration Points

- `HexGrid` SVG root → add pitch line overlay SVG elements (halfway line, centre circle, penalty boxes, 6-yard boxes, corner arcs, goal nets)
- `useGameStore.selectedPieceId` + `gameState.pieces` → new PlayerStatsPanel component reads the selected piece's attributes from `gameState`
- `packages/client/src/components/` → new `PlayerStatsPanel.tsx` component placed in the action panel layout
- `packages/shared/src/pitch.ts` → update `DIFFICULT_ANGLE_HEXES` to corner kick zone positions (D-11); no other pitch.ts changes
- `packages/shared/src/teams.ts` → replace HOME_SQUAD and AWAY_SQUAD `position` fields with real 37×26 coordinates (D-01)

</code_context>
