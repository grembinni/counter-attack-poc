<objective>
Rewrite the server piece-placement engine to be formation-driven and extend the UNIFORM_CONFIRM
handler to carry, validate, and store formation choices. `buildSquadPieces` (D-15) now looks up positions
and jersey numbers from `FORMATIONS[formationId]` instead of `PoolPlayer.position`; it applies the
kick-off +4 shift and repositions the #9 striker to the kick-off hex. The handler validates
`formationId` against an allow-list, stores home/away formations on the room, and — critically —
does NOT build game state on away confirm (Phase 24 owns that); instead it emits
BOTH_FORMATIONS_CONFIRMED with both formations.

Purpose: FORM-04 (formation-driven placement + away mirror) and the server half of FORM-03
(both-confirm gating). This is the engine core of the phase.

Output: extended roomStore/roomHandlers, rewritten gameEngine placement functions with all
`buildKickOffPieces` callers updated, and a unit test suite proving placement correctness.
</objective>
