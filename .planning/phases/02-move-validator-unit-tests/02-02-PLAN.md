    - `WRONG_SLOT` when `state.movementSlot === null`

    - `OCCUPIED` when any piece in `state.pieces` has `position.q === to.q && position.r === to.r` (MOVE-03)
    - `PACE_EXCEEDED` when `paceUsed + 1 > piece.pace` for slot ATTACKER_4 or DEFENDER_5 (MOVE-02/D-11)
    - `PACE_EXCEEDED` when `paceUsed + 1 > 2` for slot ATTACKER_2 (D-11 flat cap)
    - `ALREADY_MOVED_IN_ATTACKER4` when slot === 'ATTACKER_2' and piece.id is in `movedPieceIds` (D-12)

    Accept cases:
    - `{ ok: true }` for a normal single-step move with no ZoI trigger and no snapshot opportunity
    - `{ ok: true, effect: { type: 'STEAL_ATTEMPT', defenders: [...] } }` when the moving piece is the ball-carrier (`state.ball.carrierId === piece.id`) AND `to` is distance-1 adjacent to one or more opponents (MOVE-04). Effect's `defenders` array contains all distance-1 opponent PlayerPiece objects.
    - Steal trigger does NOT fire when the moving piece is not the ball-carrier (D-03: outfield players without the ball move freely)
    - When the ball-carrier moves to a hex with no adjacent opponents, return plain `{ ok: true }` (not STEAL_ATTEMPT)

    Edge ordering rules (tests must verify the precedence):
    - `WRONG_SLOT` is checked first (before range, occupancy, pace)
    - `OUT_OF_RANGE` is checked before `OCCUPIED`
    - `OCCUPIED` is checked before pace/ATTACKER_2 restrictions
    - `ALREADY_MOVED_IN_ATTACKER4` is checked before `PACE_EXCEEDED` within the ATTACKER_2 branch
    - Pace uses `paceUsedByPieceId[piece.id] ?? 0` (default 0 when piece has not yet moved)

    Documented-but-deferred (verified via test that asserts the deferral comment exists OR via documented JSDoc):
