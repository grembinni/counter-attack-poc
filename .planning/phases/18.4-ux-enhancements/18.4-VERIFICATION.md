## Human Verification Required

### 1. Game Speed Clock Rate — Two-Player Session

**Test:** Open two browser tabs, create a room. Home player changes speed to Fast. Both players pick teams and start a match. Track the clock between MOVE completions.
**Expected:** Each completed MOVE action (ATTACKER_4→DEFENDER_5→ATTACKER_2→end) advances the match clock by 3 minutes. Slow=1, Standard=2, Fast=3.
**Why human:** End-to-end requires live server + two connected clients; clock rate not verifiable from static analysis.

### 2. End Turn Button Visual Color Transition

**Test:** During a MOVE phase, observe the End Turn button before and after all players have moved.
**Expected:** Button is orange (#f39c12) while any player remains unmoved; transitions to green (#27ae60) once all slot players have moved. Transition is smooth (0.15s ease).
**Why human:** CSS class application and color rendering require visual browser inspection.

### 3. Final-Third Marker Visibility

**Test:** Open the game board during a match.
**Expected:** Two distinct red vertical lines are visible on the pitch at approximately 30% and 70% from the left edge, spanning the full board height.
**Why human:** SVG rendering of specific x-coordinates and visual distinctiveness require browser inspection.

### 4. Stat Tooltip Hover Behavior

**Test:** During a match with player stats visible, hover over any stat abbreviation bubble (e.g., "PAC", "TAC").
**Expected:** A native browser tooltip appears showing the full stat name and action summary (e.g., hovering "TAC" shows "Tackling — contesting the ball from a carrier.").
**Why human:** Native `title` attribute tooltips only appear in real browser environments; JSDOM does not render them.

### 5. EventBanner Timing and Single-Fire

**Test:** Score a goal. Then make several unrelated moves without scoring.
**Expected:** "GOOOOOAL!!!" banner appears centered over the pitch on goal, fades in 100ms, holds 800ms, fades out 100ms, disappears. No banner fires for the subsequent unrelated moves.
**Why human:** Animation timing and single-fire guarantee require live browser testing with React Strict Mode; CSS keyframe animations do not execute in JSDOM.
