## Decisions Made

- `pendingEndTurn` stores `{ action: () => void; count: number }` rather than a plain callback so the dialog can render the live count in the prompt string without a closure over stale state
- HEADER "Decline (no contestant)" button uses `eligibleRemaining = 1` (orange, dialog fires) to prevent accidental declines when the player hasn't selected anyone yet; "Confirm Selection" (contestants selected) uses `eligibleRemaining = 0` (green, no dialog)
- `confirmDialog` JSX is defined once and injected into each phase panel's return block so each panel controls its own modal position — dialog never leaks across panels
