<objective>
Implement UX-14: a transient (~1 second) centered banner for key match events — goal
("GOOOOOAL!!!"), interception ("INTERCEPTION!!"), tackle/turnover ("Tackle! Turnover!"), and
loose ball ("Loose Ball."). It subscribes to the existing `ActionEvent`/`eventLog` stream that
`ActionLog.tsx` already reads — no new event types needed — and tracks "is the most recent event
new since last render" via a ref-based diff (18-UI-SPEC: `lastPieceRef`-style pattern, same as
`GameBoard.tsx`'s D-03 selection tracking).

Purpose: Draw the eye to decisive moments without adding a heavy animation system. Copy and
timing are locked in 18-CONTEXT.md / Specific Ideas; all visual/animation values are pre-resolved
in 18-UI-SPEC.md (opacity-only fade 100ms/800ms/100ms, `rgba(0,0,0,0.75)` pill, z-index 20,
28px/700 white for goal, `#f39c12` for interception/tackle).

Output: a new standalone `EventBanner.tsx` + `EventBanner.module.css`, mounted once in
`GameBoard.tsx`'s pitch container.

NOTE: This plan depends on 18.4-02 because both edit `GameBoard.tsx` (same-file serialization,
different wave). Land 18.4-02 first; this plan builds on that file's post-02 state.
</objective>

  <action>
    Create `EventBanner.tsx`: a client-only component that reads `gameState.eventLog` via a Zustand
    selector. Keep a `useRef` holding the index/length (or last-seen event reference) of the last
    eventLog tail it processed (mirroring GameBoard's `lastPieceRef` D-03 pattern). On each render,
    diff the current eventLog tail against the ref; when a NEW event has been appended, map it to a
    banner message using a helper that inspects `type` and (for steal/tackle) `result === 'SUCCESS'`:
      - `GOAL` → `"GOOOOOAL!!!"` (variant `goal`)
      - `STEAL_ATTEMPT` with `result === 'SUCCESS'` → `"INTERCEPTION!!"` (variant `notable`)
      - `TACKLE_ATTEMPT` with `result === 'SUCCESS'` → `"Tackle! Turnover!"` (variant `notable`)
      - `LOOSE_BALL_LAND` → `"Loose Ball."` (variant `notable`)
      - anything else → no banner.
    Use a `useState` for the currently-shown message (null when hidden) and a `useEffect` with a
    timer to auto-clear the message after the fade cycle (~1000ms per UI-SPEC). Update the
    last-seen ref every time a new event is processed so the same event never re-triggers. The
    variant selects text color via a CSS-module class (goal = white, notable = amber). Return null
    when no message is active. Do NOT introduce a new dependency and do NOT re-derive from
    ActionLog's rendering logic — subscribe to the raw eventLog only.
    Create `EventBanner.module.css` per 18-UI-SPEC §UX-14: a `.banner` rule with

    `font-weight: 700`, and an opacity-only fade (keyframes or transition: fade-in 100ms, hold, then
    fade-out — total ~1000ms; opacity only, no transform/scale). Add `.goal { color: #ffffff; }`
    and `.notable { color: #f39c12; }` modifier classes.
