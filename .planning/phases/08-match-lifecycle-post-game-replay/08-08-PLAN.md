<objective>
Close the two client-side Phase 8 verification gaps (CR-01 client end, CR-04) found in 08-VERIFICATION.md.

- CR-01 (client end): the ActionPanel Snapshot button is gated on `phase === 'SNAPSHOT'`, but `applySnapshot` transitions to phase `'SHOT'`, never `'SNAPSHOT'`. The phase value `'SNAPSHOT'` is unreachable in a live game, so the button is permanently invisible. Re-gate the button on the ACTUAL trigger conditions for a snapshot: ball carrier in the opponent penalty area during MOVEMENT, or immediately post-pass in PASS phase (matching `applySnapshot`'s SNAP-01 logic). The server (08-07) re-validates, so the client guard is UX only.
- CR-04: `useGameStore.setGameState` is `(state) => set({ gameState: state })`. It does not clear `selectedPieceId` or `validMoveHexes`, so stale selection rings and move highlights persist across every server broadcast (end-turn, phase change, goal, kick-off repositioning). Change it to also reset both to their empty values.

Purpose: Make the snapshot button reachable in live play and stop stale selection state from leaking across server pushes. Surgical client fixes — no new features.
Output: ActionPanel Snapshot button gated on reachable conditions; setGameState clears selection state; client tsc passes; client build passes.
</objective>
