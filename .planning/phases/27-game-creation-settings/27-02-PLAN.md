<objective>
Add the server side of game-creation settings: a host-authenticated `ROOM_SETTINGS_CONFIRM` handler that validates and stores speed/teamType/draftPools, three new `Room` fields, and the **race-condition fix** that gates `TEAM_SELECTION_START` on BOTH "host confirmed settings" AND "slot 2 joined". Written test-first so the security and race behaviors are pinned before implementation.

Purpose: The server is the single source of truth for host identity (D-01), for locking settings after confirm (D-03), for the draft-pool allow-list (D-04 enforced server-side, not just via disabled checkboxes), and for delivering confirmed settings to a late-joining player (D-02). Without the both-conditions gate, a joiner who joins before the host confirms would reach team selection with unset settings (Pitfall 1).

Output: `roomStore.ts` gains `teamType`/`draftPools`/`settingsConfirmed`; `roomHandlers.ts` gains the confirm handler and a gated `ROOM_JOIN` emit; `room.integration.test.ts` gains five new cases.
</objective>
