## Component Inventory — Phase 7 Additions

Phase 6 components are not changed in structure. Phase 7 adds the following new components and extends existing ones.

### New Components

#### 1. ConnectionStatus (new)

**Location:** Rendered inside `<header>` in GameBoard.tsx, right-aligned, next to the score. During lobby screens, rendered as an absolute-positioned element in the top-right corner of the page (does not obstruct the lobby card).

**Element:** A 10px × 10px circle (`border-radius: 50%`) with a 13px / 400 label to its right.

**Visual states:**

| Socket event        | Dot fill  | Label           | Background |
| ------------------- | --------- | --------------- | ---------- |
| `connect`           | `#22c55e` | "Connected"     | none       |
| `reconnect_attempt` | `#eab308` | "Reconnecting…" | none       |
| `disconnect`        | `#ef4444` | "Disconnected"  | none       |

**Gap between dot and label:** 4px (`xs`).
**Text color:** `#a0a0a0` (`text-muted`).
**Placement in header:** flex row, gap 8px from score span, `align-items: center`.
**Placement on lobby:** `position: fixed; top: 16px; right: 16px;` — does not shift lobby card.

#### 2. DisconnectBanner (new)

**Trigger:** Rendered when `game:disconnect-warning` is received. Dismissed automatically when the next `game:state` broadcast arrives (no manual dismiss).

**Position:** Fixed banner at top of viewport, full width, z-index above header.

- `position: fixed; top: 0; left: 0; right: 0; z-index: 100`
- Height: 40px
- Background: `#0f3460` (border-subtle — consistent with panel borders)
- Text: `#f5c518` (accent-gold), 13px / 700, centred
- Copy: "Opponent disconnected. Waiting for them to reconnect… (90s)"

**When dismissed:** Component is conditionally rendered (unmounted, not hidden) when the Zustand `disconnectWarning` flag is cleared.

#### 3. ActionPanel (new)

**Location:** Inserted into the sidebar in GameBoard.tsx, between TurnIndicator and ActionLog.

**Container:** Same `.panel` style as TurnIndicator and ActionLog —

- background: `#16213e`, border: `1px solid #0f3460`, border-radius: 4px, padding: 16px

**Internal layout:** `display: flex; flex-direction: column; gap: 8px`

**Rendered only for the active player** (`playerSlot === activePlayerSlot`). If the player is not active, the ActionPanel renders nothing (null).

**Buttons inside ActionPanel — full specification per phase:**

All action buttons use the existing `.ctaButton` style contract:

- background: `#0f3460`, color: `#ffffff`, border-radius: 4px, padding: 10px 20px, font-size: 13px, font-weight: 700
- hover: background `#1a56b0`
- disabled: `opacity: 0.5; cursor: default` (use HTML `disabled` attribute)

| Button         | Label              | Visible When                                                        | Disabled When                             | Emits                                           |
| -------------- | ------------------ | ------------------------------------------------------------------- | ----------------------------------------- | ----------------------------------------------- |
| Roll           | "Roll Dice"        | phase IN [`PASS`, `SHOT`, `HEADER`, `LOOSE_BALL`] AND active player | never (if visible, always enabled)        | `game:roll`                                     |
| End Turn       | "End Turn"         | phase === `MOVEMENT` AND active player                              | —                                         | `game:end-turn`                                 |
| Undo           | "Undo Move"        | phase === `MOVEMENT` AND active player                              | `gameState.lastDiceRoll` is set (UNDO-02) | `game:undo`                                     |
| Start Movement | "Start Movement"   | phase === `KICK_OFF` AND active player (attacking team)             | —                                         | `game:start-movement`                           |
| GK Kick        | "Kick (High Pass)" | phase === `GK_RESTART` AND active player (GK's team)                | —                                         | `game:gk-restart` with `{ choice: 'kick' }`     |
| GK Throw       | "Quick Throw"      | phase === `GK_RESTART` AND active player (GK's team)                | —                                         | `game:gk-restart` with `{ choice: 'throw' }`    |
| GK Movement    | "Start Movement"   | phase === `GK_RESTART` AND active player (GK's team)                | —                                         | `game:gk-restart` with `{ choice: 'movement' }` |

**GK restart group:** Render all three GK buttons (Kick, Throw, Movement) simultaneously during `GK_RESTART`. No radio selection — direct-action buttons. A panel label above them reads "GK Restart — choose:" at 13px / 400 / `#a0a0a0`.

**Undo + End Turn group:** Render both in the same panel column during `MOVEMENT`. Undo appears above End Turn. No visual group separator needed.

**No spinner or loading state required.** The `isProcessing` mutex on the server drops duplicates silently. Do not implement client-side debounce or spinner for Phase 7.

#### 4. PassTypeSelector (new)

**Trigger:** Rendered inside ActionPanel when `phase === 'PASS'` and it is the active player's turn, BEFORE the Roll button. The selector chooses the pass type, which is then sent as part of the pass initiation event.

**Control type:** Toggle button group (4 inline buttons side by side).

**Layout:** `display: flex; gap: 4px; flex-wrap: wrap`

**Buttons:**

| Label        | Value          |
| ------------ | -------------- |
| "Standard"   | `'STANDARD'`   |
| "First-time" | `'FIRST_TIME'` |
| "High"       | `'HIGH'`       |
| "Long"       | `'LONG'`       |

**Button style (unselected):** background `#0f3460`, color `#a0a0a0`, font-size 13px, font-weight 400, border-radius 4px, padding 6px 8px, border `1px solid #0f3460`, cursor pointer
**Button style (selected):** background `#1a56b0`, color `#ffffff`, font-weight 700, border `1px solid #1a56b0`
**Button style (hover, unselected):** background `#16213e`, color `#e0e0e0`

**Initial state:** First available pass type pre-selected based on `GameState.phase` context. Default to `'STANDARD'` when entering `PASS` phase.

**Pass type label above group:** "Pass Type" at 13px / 400 / `#a0a0a0`, margin-bottom 4px.

## Hex Interaction State Extensions (Phase 7)

The existing HexCell already handles: base fill, valid-move highlight, difficult-angle dot.

Phase 7 adds one new highlight state: **goal hex clickable during SHOT phase.**

| New state           | Fill            | Fill opacity | Stroke    | Stroke width | Cursor  | Condition                                                                                    |
| ------------------- | --------------- | ------------ | --------- | ------------ | ------- | -------------------------------------------------------------------------------------------- |
| Shot target         | `#ef4444` (red) | 0.55         | `#cc2222` | 1.5          | pointer | `phase === 'SHOT'` AND hex is in `homeGoal` or `awayGoal` region AND is active player's turn |
| Shot target hovered | `#ef4444` (red) | 0.75         | `#cc2222` | 2            | pointer | hover state of above                                                                         |

**Implementation:** The `isHighlighted` prop passed to `HexCell` can remain boolean. The calling `HexGrid` component determines what `isHighlighted` means in context: during `SHOT` phase, it passes `true` only for goal hexes belonging to the OPPONENT's goal. The fill colour of the highlight overlay is determined by the phase context, passed as a second prop: `highlightColor?: string`. Default remains `#f5c518` (valid move). During `SHOT` phase, pass `#ef4444`.

**No other new hex states** are added in Phase 7. Pass target hex, header challenger hex, and snapshot confirmation are deferred (CONTEXT.md deferred section).

## Board Click Routing Contract

The `onHexClick` handler in HexGrid must route clicks differently by phase. This is the definitive decision table:

| Phase                                            | Click target                        | Action                                                                                        |
| ------------------------------------------------ | ----------------------------------- | --------------------------------------------------------------------------------------------- |
| `MOVEMENT`                                       | Own team piece                      | `store.selectPiece(id)` — highlight valid moves                                               |
| `MOVEMENT`                                       | Highlighted hex                     | `socket.emit(GAME_MOVE, { pieceId, to: hex })` + clear selection                              |
| `MOVEMENT`                                       | Any other hex                       | no-op                                                                                         |
| `SHOT`                                           | Opponent goal hex (highlighted red) | `socket.emit(GAME_SHOT, { targetHex: hex })`                                                  |
| `SHOT`                                           | Any other hex                       | no-op                                                                                         |
| `PASS`                                           | Any hex                             | no-op (pass target is not a hex click — pass is initiated via Roll after pass type selection) |
| `KICK_OFF`, `GK_RESTART`, `HEADER`, `LOOSE_BALL` | Any hex                             | no-op (actions driven by ActionPanel buttons only)                                            |

**Player gating:** Hex clicks are no-ops when `playerSlot !== activePlayerSlot`. This is enforced in the store action, not in HexCell directly.

## Lobby Flow Wiring Contract

The existing LobbyScreen sub-screens are retained. Only the data sources and socket wiring change.

### CreateRoomScreen

**On mount / Create button click:** `socket.emit(ROOM_CREATE)` — no user input needed.
**Waiting for `room:joined`:** Display a loading state on the room code display: `"Generating…"` in `#a0a0a0` (same `.roomCode` style, smaller weight 400). Once `room:joined` fires, replace with real code in `#f5c518` weight 700.
**After `room:joined`:** `store.setRoomCode(code)`, `store.setPlayerSlot(slot)`, navigate to `WAITING` screen automatically.
**Copy Code button:** copies `store.roomCode` (real code, not `MOCK42`).

### JoinRoomScreen

**Join button click:** `socket.emit(ROOM_JOIN, { code: input })`.
**On `room:error`:** Display inline error below input field. Style: `color: #ef4444`, font-size 13px, font-weight 400. Copy variants:

- Error `ROOM_NOT_FOUND`: "Room not found. Check the code and try again."
- Error `ROOM_FULL`: "This room is already in progress."
- Error `ROOM_IN_PROGRESS`: "This room is already in progress."
  **On `room:joined`:** `store.setRoomCode(code)`, `store.setPlayerSlot(slot)`, navigate to `GAME_BOARD` directly (Player 2 goes straight to board; both players joined → game starts — CONN-03).

### WaitingScreen (Player 1 only)

**Room code:** Display `store.roomCode` (real code). CopyButton works as before.
**Auto-dismiss:** When `game:state` broadcast arrives (meaning Player 2 joined), Zustand `setScreen('GAME_BOARD')` is called from the central `game:state` listener in App.tsx.
**No manual "Start Game" button.** Game starts automatically via CONN-03.
