# Phase 14 — UI Design Contract

> Visual and interaction contract for Phase 14: Kick Off Rules & Replay.
> Generated by gsd-ui-researcher.

---

## Phase Classification: No New UI

**This phase is server-side only.** All work targets `gameEngine.ts`, `gameHandlers.ts`,
and `packages/shared/src/types.ts`. No new React components, CSS modules, or visual
elements are introduced.

The three requirements with observable visual effects (REPLAY-04, REPLAY-05, REPLAY-06)
are entirely driven by the data frames the server emits — the client renders whatever
frames arrive. The existing `ReplayPanel` and `BallMarker` rendering logic is sufficient
and must not be modified.

**Executor constraint: Do not touch any file in `packages/client/src/`.**

## Copywriting Contract

No new user-facing copy is introduced in Phase 14. The server emits error events that
the existing `ActionPanel .errorText` slot renders. The only new server error code is:

| Element                                     | Copy                                                             |
| ------------------------------------------- | ---------------------------------------------------------------- |
| KICKOFF_STANDARD_PASS_ONLY error (MATCH-07) | "Kick off: only a Standard Pass is allowed from the centre hex." |
| Primary CTA                                 | none — no new CTAs                                               |
| Empty state                                 | none — no new empty states                                       |
| Destructive confirmation                    | none — no destructive actions                                    |

The error string above is emitted server-side as the `GAME_ERROR` payload. The client's
existing error display renders it verbatim. The executor must ensure the error code
`'KICKOFF_STANDARD_PASS_ONLY'` maps to this human-readable string in the client's
error handler (check `gameHandlers.ts` for the emit call and the client's `GAME_ERROR`
listener for the display path).

## Existing Replay UI — Preservation Contract

The executor must not break any of these existing rendering behaviours:

### ReplayPanel (`packages/client/src/components/ReplayPanel.tsx`)

| Element          | Current behaviour                                          | Must remain |
| ---------------- | ---------------------------------------------------------- | ----------- |
| Position counter | Displays current frame / total frames in `#f5c518`         | Yes         |
| Status text      | "Replaying…" / "Replay complete" in `#a0a0a0`              | Yes         |
| CTA button       | "New Game" — `#0f3460` bg, `#ffffff` text, hover `#1a56b0` | Yes         |
| Score line       | Home/Away name + score, correct team colours               | Yes         |

### Replay frame rendering (client-side)

| Aspect               | Current behaviour                     | Phase 14 effect                                                                                                                              |
| -------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Frame interval       | Server emits one frame per second     | After D-03: server emits one frame per 0.5s. Client renders on receipt — no client change needed.                                            |
| Movement frames      | Server emits one frame per MOVE event | After D-04: server emits K simultaneous frames per movement phase. Client renders each frame as it arrives — no client change needed.        |
| Ball marker position | Updated only on GOAL events           | After D-06: updated on every frame via `ballAfter`. Client's `BallMarker` already reads `gameState.ball.position` — no client change needed. |

The client is a passive consumer of the frame stream. Frame structure improvements are
entirely server-side.
