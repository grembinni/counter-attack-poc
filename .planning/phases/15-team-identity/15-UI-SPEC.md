# Phase 15 — UI Design Contract

> Visual and interaction contract for Phase 15: Team Identity.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.

Phase 15 is a rendering-only phase. It adds no new screens, routes, or user flows. All UI changes are:

1. SVG `<pattern>` defs inside `PieceOverlay.tsx` (outfield jersey patterns + GK jersey patterns)
2. A new `TeamBadge` component (`<img>` tag) replacing `TeamShieldIcon` in `GameBoard.tsx`
3. A targeted color-literal refactor across three client files

No modals, no forms, no empty states, no destructive actions, no user input.

## Spacing Scale

Declared values (multiples of 4 where practical; existing codebase uses 2px granularity in SVG contexts):

| Token | Value | Usage                                 |
| ----- | ----- | ------------------------------------- |
| xs    | 4px   | Icon gaps, stat row gaps, dot spacing |
| sm    | 8px   | Card padding, panel inner spacing     |
| md    | 16px  | Card gap, overlay card gap            |
| lg    | 24px  | Card padding (lobbby/overlay cards)   |
| xl    | 32px  | (reserved — not currently used)       |
| 2xl   | 48px  | (reserved — not currently used)       |
| 3xl   | 64px  | (reserved — not currently used)       |

Exceptions:

- SVG pixel coordinates use 1px, 2px, 3px, 6px granularity — these are rendering coordinates inside a 24px tile space, not layout spacing tokens. They are not subject to the 4px grid rule.
- `TeamBadge` renders at exactly 28×28px in the scoreboard — a fixed rendering size, not a spacing token.

## Typography

### Design Scale (max 4 sizes)

Prescriptive contract — planner and executor use exactly these 4 sizes. Do not introduce additional sizes.

| Role            | Size | Weight    | Line Height | Usage                                                                                        |
| --------------- | ---- | --------- | ----------- | -------------------------------------------------------------------------------------------- |
| Label / meta    | 11px | 400       | 1.4         | Stat labels, role text, phase label, sub-links, panel headers (uppercase)                    |
| Body            | 13px | 400 / 700 | 1.5         | Action log entries, lobby body, card body, error text; bold variant for CTAs and player name |
| Heading         | 20px | 700       | 1.2         | Overlay heading, card heading                                                                |
| Display / clock | 36px | 700       | 1.0         | Match clock (`.clockDisplay`)                                                                |

Weights in use: regular (400) and bold (700). No other weights.

### Codebase Audit Record — do not extend

The following sizes exist in the codebase as legacy values. They are documented here for inventory purposes. Do not replicate or expand on them in new work.

| Legacy Size | Location                                        | Note                                                                                |
| ----------- | ----------------------------------------------- | ----------------------------------------------------------------------------------- |
| 10px        | `.statRow`, `.statLabel` (App.module.css)       | Folded into the 11px label tier — 1px difference is imperceptible at this scale     |
| 28px        | Scoreboard score display (GameBoard.module.css) | Retained for the existing score numeral only; not a scale member for new components |

Phase 15 does NOT introduce any new type sizes or weights. The `TeamBadge` component renders an `<img>` — no typography. SVG jersey labels are not used (pieces render as SVG circles with pattern fills, no text labels in this phase).

## SVG Jersey Pattern Contract

All patterns use `patternUnits="userSpaceOnUse"`. Pattern ids always include `piece.id` suffix to prevent SVG id collisions across multiple pieces of the same team in the same document.

### Outfield Patterns

| Team   | Pattern Id                 | Tile Size | Base Fill | Stripe/Accent                                                                             | Notes                                                             |
| ------ | -------------------------- | --------- | --------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------- |
| Cosmos | `cosmos-jersey-{piece.id}` | 24×24px   | `#1e3a8a` | White horizontal stripe `height=12` at `y=6` (fillOpacity 0.6)                            | Centered wide horizontal stripe — 3× the prior 4px stripe         |
| Xolos  | `xolos-jersey-{piece.id}`  | 16×16px   | `#ea580c` | `#6b7280` checker rects at (0,0) and (8,8), each 8×8px (fillOpacity 0.7)                  | Tile is 16px to give 2 checker squares per axis                   |
| City   | `city-jersey-{piece.id}`   | 4×24px    | `#dc143c` | `#f5c518` vertical stripe: `x=3, width=1` (fillOpacity 0.8); plus a sibling arch `<path>` | Arch is a non-repeating sibling element, not inside pattern       |
| Crew   | `crew-jersey-{piece.id}`   | 8×8px     | `#f5c518` | `#111111` diagonal line `x1=8 y1=0 x2=0 y2=8` (strokeWidth 2, strokeOpacity 0.75)         | Full-circle fill masked — lower 70% covered by solid gold overlay |

### City Jersey Arch Path

Rendered as a sibling `<path>` element after the base circle fill. Not a pattern repeat.

```
d: M {cx - PIECE_RADIUS * 0.7} {cy + PIECE_RADIUS * 0.3} Q {cx} {cy + PIECE_RADIUS * 0.9} {cx + PIECE_RADIUS * 0.7} {cy + PIECE_RADIUS * 0.3}
fill: none
stroke: #f5c518
strokeWidth: 1.5
pointerEvents: none
```

### Crew Shoulder Mask

To restrict diagonal stripes to top ~30% only, render a second sibling element covering the lower 70%:

A `<clipPath>` restricting to the upper 30% of the token is the recommended approach:

- `clipPathUnits="userSpaceOnUse"`
- Clip `<rect>`: `y={cy - PIECE_RADIUS}` to `y={cy - PIECE_RADIUS + PIECE_RADIUS * 0.6}` (top ~7px of 24px height)
- Apply this clipPath on a second `<circle>` filled with `url(#crew-jersey-{piece.id})`, overlaid on the gold base circle

### GK Patterns

| Role    | Pattern Id                                | Tile Size | Colors                                                        | Notes                                                                                                                                    |
| ------- | ----------------------------------------- | --------- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| Home GK | `home-gk-checker-{piece.id}`              | 12×12px   | `#7c3aed` base + `#4c1d95` checker at (0,0) 6×6 and (6,6) 6×6 | Tile is 12px for two 6px checker squares per axis                                                                                        |
| Away GK | (no pattern — solid fill + sibling rects) | n/a       | `#f59e0b` circle fill; `#ea580c` stripe rects                 | Two `<rect>` siblings: left at `cx-PIECE_RADIUS+4`, right at `cx+PIECE_RADIUS-7`; both width=3, height=PIECE_RADIUS\*2, fillOpacity 0.85 |

### Anchor Convention for All Patterns

All `<pattern>` elements must set:

```
x={cx - PIECE_RADIUS}
y={cy - PIECE_RADIUS}
patternUnits="userSpaceOnUse"
```

This anchors the tile origin to the top-left of the piece's bounding box, keeping the pattern visually registered to the token.

## Copywriting Contract

Phase 15 introduces no new user-facing copy. There are no new prompts, labels, empty states, error messages, or CTA labels. The scoreboard badge display is purely visual (image, no text beyond the existing team name display).

The `alt` attribute on `TeamBadge` images follows this pattern: `{teamId} badge` (e.g., "cosmos badge", "xolos badge"). This is accessibility copy, not UI copy.

## Interaction Contract

Phase 15 introduces no new interaction patterns. The `TeamBadge` component is display-only (`<img>` with no click handler). All jersey patterns are visual fills on existing clickable `<circle>` elements — click semantics are unchanged.

| Interaction               | Behavior                       | Change from Phase 14    |
| ------------------------- | ------------------------------ | ----------------------- |
| Click piece token         | Select piece (existing)        | Unchanged               |
| Click hex                 | Move/action (existing)         | Unchanged               |
| Badge image in scoreboard | Display only — not interactive | New element, no handler |

## Accessibility Contract

| Element              | Requirement                                                                                                      |
| -------------------- | ---------------------------------------------------------------------------------------------------------------- |
