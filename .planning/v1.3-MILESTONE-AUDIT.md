## Re-Audit 2026-07-04 (Integration Checker Run)

Integration checker (`gsd-integration-checker`) run across Phase 19→20→21 chain. All requirements confirmed wired. Additional findings:

### New Observations

**PALETTE-01 field name drift (non-blocking):**
`TeamPalette` interface evolved from the originally specified 4-field model (`primary`, `primaryLight`, `secondary1`, `secondary2`) to a 6-field home/away model (`homePrime`, `homeAlt`, `homeFont`, `awayPrime`, `awayAlt`, `awayFont`) per design decision D-08. Phase 19 VERIFICATION.md marked PALETTE-01 satisfied against the live implementation; REQUIREMENTS.md now updated to note the design evolution. All consumers use the correct 6-field names.

**LEAGUE-03 routing pattern (non-blocking):**
`TeamConfig.league` field exists and is populated ('mls' or 'international') but `TeamSelectionScreen` routes tab groups via hardcoded `MLS_TEAMS`/`INTL_TEAMS` arrays rather than reading `.league` at runtime. The grouping is functionally correct (all MLS teams in MLS_TEAMS, all international in INTL_TEAMS) but the field has no runtime consumer. If teams are added dynamically in future, the hardcoded arrays will need updating alongside the data.

**LEAGUE-02 "both tabs" wording (non-blocking):**
The struck-out card is visible when the away player is on the correct tab (auto-switch ensures this). If the away player manually navigates to the tab that doesn't contain the home-picked team, no indicator appears there (correct behavior — the card doesn't exist on that tab). The "all tabs" wording in the requirement is satisfied by the auto-switch ensuring the struck-out card is always visible when relevant.
