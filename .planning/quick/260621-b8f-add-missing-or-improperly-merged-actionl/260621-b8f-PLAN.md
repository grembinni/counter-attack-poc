<objective>
Close four ActionLog coverage gaps surfaced during Phase 18 close-out:

1. The **contested** HEADER duel emits NO HEADER ActionEvent (server gap), so no contest log appears.
2. The pass delivered after a won header emits NO event (server gap).
3. SHOT_ATTEMPT renders the shooter/GK duel and the handling sub-check in ONE entry (client merge bug).
4. The GK Punt (GK_KICK_TARGET delivery) emits NO event (server gap).

Purpose: ActionLog must log header contests, post-header passes, the shot handling sub-check, and punts the same way it logs tackle/steal/shot/standard passes.

Output: Two new ActionEvent variants (HEADED_PASS, GK_PUNT), three server emission sites, one client render split, two new client render branches, and tests proving each entry renders.
</objective>

<investigation_findings>
Confirmed by reading gameEngine.ts, gameHandlers.ts, types.ts, and ActionLog.tsx:

- **#1 HEADER contest — SERVER GAP (not client).** The `GAME_HEADER_CONTESTANT` handler
  (gameHandlers.ts ~line 2531-2549) calls `computeHeaderDuelWinner`, stores
  `headerDuelWinner`, and stays in HEADER — but emits **no HEADER event**. Only the
  _tie_ path (via `applyRoll`, line 2534) and the _uncontested_ paths (gameEngine.ts
  ~lines 2037, 2064, 2256) emit HEADER events. The ActionLog `HEADER` render branch
  (ActionLog.tsx lines 446-517) already exists and is correct — it just never receives
  a contested-win/contested-loss event. Fix is server-side: emit the HEADER event when
  `computeHeaderDuelWinner` returns a non-null winner.

- **#2 Post-header pass — SERVER GAP.** `applyResolveHeaderTarget` (gameEngine.ts
  ~line 2999) routes a won header to PASS with the winner as carrier but emits **no
  event**. The contested-win branch in `applyRoll` (gameEngine.ts ~line 2194) likewise
  emits only the HEADER event, not a pass event. Fix: emit a new `HEADED_PASS` pass-format
  event at the header→PASS delivery point.

- **#3 Shot split — CLIENT ONLY.** The `handlingDie !== null` branch of SHOT_ATTEMPT
  (ActionLog.tsx lines 365-391) renders `{duelStr} | handling: ...` in one entry. No
  server change — split the single rendered entry into two log lines.

- **#4 Punt — SERVER GAP.** `applyGKKickTarget` (gameEngine.ts line 2496) transitions
  GK_KICK_TARGET → GK_KICK_MOVE and moves the ball, but emits **no event**. (Note: the
  _quick throw_ path already emits STANDARD_PASS at line 2566; the punt does not.) Fix:
  emit a new `GK_PUNT` pass-format event in `applyGKKickTarget`.

Scope split: #1, #2, #4 are server emission + (for #2/#4) new client branches; #3 is
client-render-only. Grouped into 3 tasks below by file-ownership and concern.
</investigation_findings>
