- `outcomeLabel` (the `LOOSE_BALL` → `"LOOSE BALL (tie)"` remap) is now computed identically in both the handling-duel branch and the regular-duel branch rather than being defined once and shared via closure — the two branches are in separate `if`/`else` blocks with no shared scope, so duplicating the one-line ternary (per the plan's explicit "your call" option) was simpler than introducing a function-scope hoist that would need to run before the `shooterScore === null` early branch too.
